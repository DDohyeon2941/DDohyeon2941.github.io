Insurance claim review classification

2020.08–2020.10 · Financial Big Data Festival · Team project

Insurance claims need different levels of review, and patterns can differ by disease group. In a competition, our team built classifiers tailored to those groups to distinguish immediate payment, document review, and on-site review.

Task:
Classify claims into three levels of review
Scope:
Competition training, validation, and submission predictions

Problem and context

Insurance claims require different levels of review. The competition task was to classify three review types from the provided claim information. A value can mean different things across diseases or institutions, so we considered feature construction alongside group-specific modeling.

My role

I participated in the Financial Big Data Festival team project with Jong Hwan Park. As a team, we performed claim preprocessing, feature construction, classifier training, and cross-validation.

Approach

Preprocessing and feature construction

Exploratory analysis informed features based on zero/nonzero monetary values, relative amounts, and combinations of institution categories. This page explains feature purposes rather than detailed source-field names or individual claims.

Learning by disease group

The public model code divides data into two disease-category groups and trains a LightGBM model for each. Group-specific predictions are then restored to the original claim order.

Cross-validation and submission

StratifiedKFold preserves class proportions across 5 splits, evaluating accuracy and F1. Predictions from validation models were combined into competition test submissions.

Scope

The implementation covers competition-data preprocessing, classifier training, validation, and submission predictions. It was not an industry project deployed in an insurer’s actual review system.

We implemented preprocessing through cross-validation and submission prediction generation. The public code does not include source data.
