# Project introductions: problem and response

Project introductions previously foregrounded algorithms or processing steps before explaining why the work was needed. All nine active project introductions now start with a concrete problem and explain the response in plain language. The project list, detail introduction, and hover preview use the same summary; the home manufacturing feature is aligned with them.

- Manufacturing linkage: incorrect correspondence can invalidate training pairs; verify the same target and construct a linked dataset.
- Time series: mismatched recording times and unavailable future information can distort learning; align inputs with the intended prediction time.
- GAN: more minority images do not necessarily help classification; explore class characteristics and usefulness for learning, with the personal follow-up's benefit still unverified.
- Federated learning: incorrect client labels weaken the shared model; compare aggregation and update controls, retaining the finding that the tested controls did not improve results.
- Exit recognition: visual signs can be difficult to read directly; investigate camera-image classification and lightweight inference, without claiming a completed guidance service.
- OOD: learned patterns and label reliability differ across environments; adjust each environment's influence and build coursework experiments, without claiming verified generalization gains.
- Seongsu: overall popularity does not explain local commercial differences; define comparable closing/continuing groups and analyze them to support policy proposals.
- Insurance: review needs and patterns differ among claims; build disease-group classifiers for the competition's three review categories.
- Documents: equivalent information appears in inconsistent forms; interpret context and standardize representations for reuse.
