제조 AI는 Prediction 문제가 아니다

2026.05.28 · Manufacturing AI · Cause-Effect Mapping · Data Validation

현업 사례의 세부 내용은 공개 범위를 고려해 일반화했습니다.

목차

  1. 왜 제조 AI에서는 원인과 결과 연결이 어려운가
  2. 실제 프로젝트에서 마주친 문제
  3. 그래서 모델보다 먼저 검증해야 했던 것들
  4. 제조 AI는 모델링 이전에 공정을 설명할 수 있어야 한다
제조 AI에서 중요한 것은 단순히 높은 accuracy가 아니다.

현재 데이터가 실제 공정의 원인과 결과를 신뢰성 있게 설명하고 있는지를 먼저 검증해야 한다.

많은 AI 프로젝트는 입력(X)과 결과(Y)를 연결하는 문제로 설명된다.

좋은 feature를 만들고, 좋은 모델을 선택하면 더 높은 accuracy를 얻을 수 있다는 방식이다.

하지만 제조 AI에서는 데이터가 존재한다고 해서 원인과 결과가 자동으로 연결되지는 않는다.

실제 제조 환경에서는:

  • 어떤 공정 조건이
  • 어떤 샘플에 적용되었고
  • 어떤 품질 결과로 이어졌는가

자체가 불명확한 경우가 많다.

즉 제조 AI의 핵심은 단순 prediction이 아니라,

Cause → Effect Mapping

을 검증하는 문제에 가깝다.

이번 프로젝트에서도 모델 개발 이전에 가장 먼저 해야 했던 일은, 모델 선택이 아니라 데이터의 cause-effect mapping을 검증하는 과정이었다.

왜 제조 AI에서는 원인과 결과 연결이 어려운가

프로젝트의 목표는 공정 조건을 기반으로 대상 품질(품질 측정값)을 예측하고, 목표 품질을 만족하는 조건값을 추천하는 AI 모델을 만드는 것이었다.

핵심은 단순 prediction이 아니었다.

모델은:

  • 이전 상태
  • 공정 조건
  • 최종 결과(품질 측정값)

사이의 관계를 학습해야 했다.

즉:

"어떤 상태에서 어떤 조건값을 적용했더니 어떤 결과가 나왔는가"

를 설명할 수 있어야 했다.

문제는 제조 데이터가 생각보다 단순하지 않다는 점이었다.

같은 제품 모델이라도:

  • 그룹마다 초기 상태가 다르고
  • 이전 공정 특성이 다르며
  • 공정 편차와 변동성이 존재한다.

즉 같은 조건값을 적용하더라도, 그룹에 따라 결과가 달라질 수 있다.

따라서 제조 AI에서는 단순히 데이터를 많이 모으는 것이 아니라,

현재 데이터가 실제 동일 샘플의 공정 흐름을 설명하는가

를 먼저 검증해야 했다.

실제 프로젝트에서 마주친 문제

1. 검사 통과 = 모든 대상이 정상은 아니었다

프로젝트 초기에는 다음과 같은 가정을 하고 있었다.

"검사를 통과한 대상은 모두 품질 기준 충족이다"

하지만 실제 데이터를 확인해보니 그렇지 않았다.

검사 상태와 개별 측정값의 의미가 일치하는지 확인할 필요가 있었다.

즉 검사 통과 상태만으로 모든 대상의 측정값이 유효하다고 가정할 수는 없다.

이 문제는 단순 데이터 정제 문제가 아니었다.

평가 기준 자체가 실제 현장의 품질 판정 방식과 일치하지 않는다는 의미에 가까웠다.

결국:

제조 AI에서는 label 자체가 현실 공정을 올바르게 설명하는지부터 검증해야 했다.

2. 동일 그룹이라고 같은 샘플은 아니었다

다음 문제는 공정 조건과 검사 결과를 실제로 연결할 수 있는가였다.

프로젝트에서는:

  • 이전 공정
  • 대상 공정
  • 검사 결과(품질 측정값)

를 연결해서 분석해야 했다.

특히 목표는:

이전 상태 → 공정 조건 → 품질 측정값

관계를 학습하는 것이었다.

하지만 제조 환경에서는 단순히 그룹 식별자가 같다고 해서, 반드시 동일한 공정 흐름이라고 볼 수는 없었다.

그룹 단위 식별자가 같더라도 개별 대상의 상태와 이력은 다를 수 있다.

따라서 단순 그룹 단위 연결만으로는:

  • 이전 상태
  • 적용 조건값
  • 최종 품질 결과

가 실제 동일 샘플을 의미한다고 보장할 수 없었다.

이 상태에서 데이터를 그대로 사용하면, 모델은 실제 공정의 인과관계가 아니라 서로 다른 샘플이 섞인 상관관계를 학습하게 된다.

3. 조건값 데이터가 무엇을 의미하는지도 먼저 정의해야 했다

문제를 더 복잡하게 만든 것은, 현재 확보 가능한 조건값 데이터의 의미였다.

측정 기록을 해석할 때에는 데이터가 어느 시점의 상태를 나타내는지 확인해야 한다.

일반적으로 데이터 검토에서는 기록 시점, 측정 시점, 적용 시점을 구분할 필요가 있다.

데이터에 기록된 조건값이 전체 이력을 의미하는지, 특정 시점의 상태만 의미하는지 확인해야 한다. 예를 들어

"특정 시점에 적용된 조건"

이라는 의미일 수 있다.

또한 이전 단계의 모든 대상이 이후 단계 데이터에도 존재한다고 가정해서는 안 된다.

즉 두 단계에 공통으로 존재하는 동일 대상인지 확인해야 한다.

결국 현재 데이터 구조에서:

"어떤 조건값을 적용했더니 어떤 결과가 나왔는가"

를 분석하려면,

  • 이전 단계와 이후 단계에 모두 존재하며
  • 동일 대상 기준으로 연결 가능하며
  • 의미와 시점이 검증된 결과 데이터

를 중심으로 분석해야 했다.

즉 단순히 데이터가 존재하는지가 아니라,

현재 데이터가 실제로 무엇을 의미하는가

를 먼저 정의하는 과정이 필요했다.

그래서 모델보다 먼저 검증해야 했던 것들

결국 모델 학습 이전에 먼저 해야 했던 것은, “쓸 수 있는 데이터”의 기준을 정의하는 일이었다.

우리는 다음 조건들을 먼저 검증했다.

  • 동일 대상 기준으로 공정 흐름이 연결되는가
  • 이전 상태와 최종 결과(품질 측정값)가 동일 샘플 기준으로 연결되는가
  • 해당 조건값이 실제 생산 조건값으로 해석 가능한가
  • 검사 결과의 상태와 측정값의 의미가 일치하는가
  • 현재 label이 실제 현장의 품질 판정 기준을 반영하는가

이 조건을 만족한 데이터만 이후 분석과 모델 학습에 사용했다.

제조 AI는 모델링 이전에 공정을 설명할 수 있어야 한다

많은 제조 AI 프로젝트들은 model accuracy에 집중한다.

하지만 실제 제조 환경에서 중요한 것은:

  • 현재 데이터가 실제 공정을 설명하는가
  • 모델이 실제 인과관계를 학습하고 있는가
  • 결과를 공정 관점에서 해석할 수 있는가

이다.

특히 제조 데이터는 여러 시스템에 분산되어 있고, 공정 흐름과 운영 기준이 현실 환경에 따라 계속 변한다.

따라서 제조 AI에서는 모델링 이전에, 현재 데이터가 실제 공정의 cause-effect relationship을 설명할 수 있는지 먼저 검증해야 한다.

어쩌면 제조 AI에서 가장 어려운 것은, 좋은 모델을 만드는 일이 아니라

"현재 데이터가 실제 공정을 설명하는 데이터인지 판단하는 일" 일 수도 있다.
