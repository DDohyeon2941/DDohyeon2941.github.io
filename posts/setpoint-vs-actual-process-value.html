Why Setpoint ≠ Actual Process Value

Training and operational data can differ in manufacturing AI

In manufacturing AI, the question is more than whether a model can be trained.

We first need to verify that inference can use data available at the actual time of operation.

A common situation in manufacturing AI is:

A model trains on actual measured values, but operational inference is expected to use setpoints.

The two do not have the same meaning.

In an actual project, someone proposed predicting process conditions from quality measurements collected after inspection.

This appeared feasible because both condition values and quality measurements existed in the training data.

The approach was problematic in the intended operating workflow.

In actual production, conditions are selected first,
and quality measurements are collected as a result.

The proposed inputs would therefore use information that did not yet exist at inference time.

The data available at use time matters

High accuracy alone is insufficient.

Inference must use information available at the actual time of operation.

Training and operational data structures often differ in manufacturing AI.

  • An actual value exists after the process.
  • A setpoint exists before the process.
  • Inspection results are measured after the process.
  • Recommendations must be provided before the process.

A model can train on completed-process data, while operation requires decisions about conditions for a process not yet performed.

We need to distinguish data available for training from data available at operational inference time.

Why predicting conditions from quality measurements was problematic

The project aimed to recommend process conditions that meet a target quality.

The intended operating flow was:

Prior state → process conditions → quality measurement

The prior state is checked, suitable conditions selected, and the resulting quality measured.

Using quality measurements to predict conditions reverses this flow:

Quality measurement → process conditions

It resembles inferring a cause after observing an outcome.

Such a model can be trained because completed records include both conditions and quality measurements.

During actual production, however, the quality measurement does not yet exist: the conditions must be selected first.

The model might score highly while remaining unusable in the intended operational workflow.

This went beyond data leakage

This was not only a question of leakage.

The nature and distributions of the data also differed.

A setpoint is a target entered by an operator or configured by a system. An actual value is closer to what occurred in the process.

The two may look like comparable numbers but play different roles in manufacturing AI.

  • A setpoint expresses intent before the process.
  • An actual value reflects execution after the process.
  • An inspection value measures a process outcome.
  • A recommendation must be determined before the process.

Their coexistence in training records does not make them interchangeable in the same operating workflow.

Operator intervention, equipment condition, process variation, and maintenance can produce different actual values and outcomes from the same setpoint.

We need to ask both whether a model can be built and whether the same structure works in operation.

Define the operating structure before the model

Before assessing model performance, a manufacturing AI project should define:

  • What is the actual operating flow?
  • Which data exist before the process?
  • Which values are produced after the process?
  • What data are actually available at inference time?
  • Do training and operational data have the same distribution?

Without this structure, high accuracy can coexist with a model that cannot be used in actual production.

Manufacturing AI requires a structure that can work in the operating environment, beyond prediction alone.

A manufacturing AI model must do more than work on a dataset.

It must fit within the actual process flow.
