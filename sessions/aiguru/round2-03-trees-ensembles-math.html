01 Impurity equations — Gini vs Entropy 25 min
Key point: A tree measures how mixed the classes are within one node, then chooses the split that reduces that number the most. Two measures can provide this number: Gini and Entropy.
Definition Gini impurity
Gini = 1 − Σ pₖ²
pₖ
Proportion of class k within the node
50% defective and 50% normal → p₁=0.5, p₂=0.5
Σpₖ²
Concentration in one class
The sum of all pₖ². Greater concentration produces a larger value (0.98²+0.02²=0.96)
1 − (...)
Convert concentration into mixing
More concentration means smaller Gini → A value closer to 0 means a purer node
Definition Entropy (information entropy)
Entropy = − Σ pₖ log₂pₖ
pₖ
Same as Gini — Class proportion
The proportion of class k within the node
−log₂pₖ = log₂(1/pₖ)
Information in that class (unit: bit)
A smaller pₖ (a rarer event) produces a larger value: an unusual event provides more information
−Σpₖlog₂pₖ
Expected value (average information) = Uncertainty
A weighted average of each class's information, weighted by its probability pₖ
ProofWhy logarithms? — Start from the requirement that information must add

An information function I(p) must satisfy at least these three requirements.

  • ①
    A certain event (p=1) must carry 0 information
    An event we already know will occur adds no new information
  • ②
    Rarer events (p↓) must carry more information (monotonically decreasing)
    When an unlikely event happens, we are more surprised and learn more
  • ③
    For two independent events occurring together, their information must add
    I(p·q) = I(p) + I(q) — This is the key requirement

The challenge is requirement ③. The joint probability of independent events uses multiplication (p·q), but their information must add. We need a function whose output turns multiplication of its inputs into addition. The function satisfying this requirement, I(p·q) = I(p) + I(q) under continuity and monotonic-decrease conditions, is the logarithm— because its defining property is log(a·b) = log(a) + log(b).

To also satisfy ① and ②, reverse the sign because log is negative for probabilities between 0 and 1, giving I(p) = −log(p). With base 2 (log₂), the unit becomes the bit. This gives the −log₂pₖ term above.

Calculation exampleCheck additivity — Tossing a coin twice

The probability of two heads (HH) from two coin tosses is 0.5 × 0.5 = 0.25(multiplication for independent events).
The information is −log₂(0.25) = 2 bit, exactly the information from the first toss (1 bit) plus the second toss (1 bit).

Defining information using a function such as pₖ² would break this additive property: only logarithms convert multiplication of probabilities into addition of information. This is also why Gini (1−Σpₖ²) is treated as an inexpensive approximation to impurity rather than information: it does not satisfy this additive property.

Read −log₂pₖ as a number of questions — The Twenty Questions intuition

Identifying heads in a coin toss (pₖ=0.5) requires one question: “Heads?” → −log₂(0.5) = 1 bit.
For an event with probability pₖ=1/8, identifying one among eight possibilities requires three binary questions (halve the possibilities three times → 8=2³) → −log₂(1/8) = 3 bit.

Thus −log₂pₖ can also be read as “the number of yes/no questions needed to identify the event”. This agrees with multiplication becoming addition: question counts also add for independent events (two coin tosses = 1 question + 1 question = 2).

Entropy takes this number of questions per event and weights it by the probability that the event occurs— meaning the average number of questions needed to identify a class drawn from this node.

Calculate it yourself — Gini vs Entropy for different pₖ distributions
Distribution (p₁, p₂)Gini = 1−Σpₖ²Entropy = −Σpₖlog₂pₖInterpretation

0.90 / 0.10 1−(0.81+0.01) = 0.18 −(0.9·log₂0.9 + 0.1·log₂0.1) = 0.47 Fairly pure, but a minority class remains
0.99 / 0.01 1−(0.9801+0.0001) = 0.02 −(0.99·log₂0.99 + 0.01·log₂0.01) = 0.08 Almost pure — Both measures near 0
1.00 / 0.00 0.00 0.00 Completely separated — Both exactly 0
A numerical difference — Entropy responds more strongly to minority classes

At (0.9, 0.1), relative to each measure's maximum, Gini is 0.18/0.50 = 36% , while Entropy is 0.47/1.00 = 47% . For the same distribution, Entropy indicates comparatively lower purity.

The reason lies in the logarithm: as pₖ approaches 0, log₂pₖ diverges steeply, while Gini's pₖ² approaches 0 gradually. Therefore Entropy places more weight on a minority class that is small but still present.

In practice, however, the optimal split chosen by the two measures is usually the same. More important than the metric choice is the principle that splitting reduces uncertainty.

02 Split criteria — Classification (Gain) vs regression (ΔMSE) 30 min
A tree tries every variable and split point, then chooses the point that most reduces uncertainty after splitting. First, examine how an if-statement split is expressed mathematically.
Model representation Tree = An if statement expressed with indicator functions
f(x) = Σ cₘ · 𝟙(x ∈ Rₘ)
𝟙(condition)
Indicator function = The if statement itself
1 if the condition is true, 0 otherwise. Example: 𝟙(temperature > 85) — “1 if temperature exceeds 85, otherwise 0”
Rₘ
The region handled by leaf m
The intersection of split conditions. Example: R₁ = {temperature>85 and pressure≤3}
cₘ
The prediction for that region
Classification: most frequent class / Regression: mean y in that region, ȳ
Code and equations correspond one-to-one — The same idea in two languages

A tree of depth 2, written side by side in code and equations:

Code (if statements)

if temperature > 85:
  if pressure > 3: return 0.80
  else:       return 0.35
else:
  return 0.04

Equation (indicators)

f(x) = 0.80·𝟙(temperature>85, pressure>3)
     + 0.35·𝟙(temperature>85, pressure≤3)
     + 0.04·𝟙(temperature≤85)

For any x, exactly one indicator equals 1 and all others equal 0, because the regions Rₘ are disjoint and cover the whole space. Although written as a sum (Σ), it actually forms a lookup that selects exactly one cₘ. This is the mathematical version of “trees divide space into rectangles” from Round 1.

Which side gets equality? — “At most/greater than” vs “less than/at least”
This is a library convention: sklearn (CART) uses x ≤ t → Left; x > t → Right, while XGBoost uses x < t → Left; x ≥ t → Right. The results are essentially the same because, for continuous variables, the split point t is not arbitrary but the midpoint between two sorted observations(for example, t=85.15 between 84.2 and 86.1). Since no training sample lies exactly at t, the partition, Gain, and learned tree are the same regardless of which side includes equality. Equality determines only where to send a new observation that happens to equal t. This material consistently uses the sklearn convention (≤ / >).
Why this representation matters — The link across today's session

① It makes the learning target clear — Training a tree means finding regions Rₘ (where to split) and values cₘ (what to predict). cₘ is easy: a mean or mode. Choosing Rₘ is harder, and Gain/ΔMSE below provides the criterion.
② Connection to section 04 (ensembles) — Bagging's f_b(x) and boosting's hₘ(x) both have the form Σcₘ𝟙(x∈Rₘ). An ensemble averages these step functions (bagging) or accumulates them (boosting) to produce a smoother function.
③ Why the equation is nonparametric — The data determines both the number of regions M and their shapes Rₘ. Unlike β, there is no fixed number of parameters specified in advance.

Discussion question
“f(x) = Σcₘ𝟙(x∈Rₘ) is a step function that is not differentiable everywhere, whereas linear regression is a smooth line. How does this difference connect to the Round 1 intuition that trees capture nonlinearity?”
Answer guide — Capture nonlinearity through resolution, rather than drawing a curve

Linear regression f = βᵀx is smooth and differentiable everywhere, but the price is a shape fixed to one line or plane. It cannot escape the assumption that y changes at a constant rate with x.
A tree takes the opposite approach. Instead of using a slope, it freely chooses how many steps to place and where. Even a winding relationship can be approximated with enough closely spaced steps. Rather than drawing a curve with an equation, it represents nonlinearity by filling in pixels (rectangular regions).

ProofCheck nondifferentiability from its definition — What does a nonexistent limit mean?

Differentiability means that the following limit exists:

f′(x₀) = lim_{h→0} [f(x₀+h) − f(x₀)] / h
STEP 1 — What does it mean for a limit to exist?

As h shrinks toward 0, calculate the quotient repeatedly. If it approaches and settles on one number , the limit exists, and that number is f′(x₀). Two conditions are implicit:

  • ⓐ
    It must settle — The value must approach a destination, rather than keep increasing
  • ⓑ
    Both sides must agree — h can approach 0 from positive values (the right) or negative values (the left), and the two results must be the same single number.

Think of a limit as a meeting place approached from both sides. The person from the left and the person from the right must arrive at the same place to meet: for the limit to exist.

STEP 2 — No limit means that one of those conditions fails
  • A
    The two sides arrive at different places — The left settles at 3 and the right at 5 → No single answer to “What is the limit?” → No limit
  • B
    No settling = Divergence — As h shrinks, the values grow as 100, 1000, 10000, ... without settling on any number. ∞ names the situation of unbounded growth rather than a number, so it cannot be a finite limiting value → No limit. Divergence is simply the name for this situation
STEP 3 — Check a step-function boundary with actual numbers

Consider a tree with just one split :

Tree (if statements)

if temperature ≤ 85: prediction = 10 ← c₁
if temperature > 85: prediction = 40 ← c₂

10 and 40 are the mean y values in each leaf: the output of f(x). The only split is 85, so 85.1, 90, and 200 all fall in the prediction-40 region

Graph (one step)

40 ─ ┌────────── │ 10 ─ ───────┘ ↑ t=85 → Temperature

What does approach mean? — To measure the slope at t=85, choose a point near 85 , calculate the quotient, and move that point progressively closer to 85. There are two kinds of nearby points: just above 85 (approaching from the right) or just below it (approaching from the left).

Approach from the right: 86 → 85.1 → 85.01 → 85.001 → ... All lie in the temperature>85 region, so their predictions are all 40. The values immediately to the right of f(85) are also 40, giving quotient = (40−40)/distance = always 0. However close they get, the quotient stays 0 → Settles at 0.

Approach from the left: 84 → 84.9 → 84.99 → 84.999 → ... All lie in the temperature≤85 region, so their predictions are all 10. But the destination's value is 40. The quotients are:

Chosen pointPrediction differenceDistance hQuotient = Difference/distance
84.9300.1300
84.99300.013,000
84.999300.00130,000
84.999930 — Does not decrease0.0001300,000 — No sign of settling

Here is the key: the distance (denominator) shrinks as we approach, but the prediction difference (numerator) remains 30. Even at 84.999, we are still in the left region with prediction 10; crossing 85 changes it to 40. The jump is a cliff that does not narrow beforehand, however close we get. The quotient grows without bound = Divergence (case B).

Conclusion: The right settles at 0, while the left diverges. They fail to meet, so there is no single number and no limit → Not differentiable at t=85.

STEP 4 — Contrast with an interior point (x=90): Why does it work at 90?

Note: 90 is not a split point. This tree has only one split, at 85, so 90 is an ordinary point inside the >85 region.
Approaching from the left (89.9, 89.99, ...), all points exceed 85, stay in the same region, and predict 40. The right-hand approach (90.1, 90.01, ...) also predicts 40, and f(90)=40. Both sides give quotient = (40−40)/distance = 0 → Both settle at 0 → The limit exists, and the function is differentiable with slope 0.

In one line — The difference between 85 and 90 is “whether the region changes along the approach”. At x=90, the entire approach stays in one region, so the numerator is 0. At x=85, the left-hand approach remains in another region (prediction 10), keeping the numerator at 30. Thus differentiation fails only at the split points(a tree with three split points has three such points); everywhere else, the function lies on a flat interval with slope 0.

Precise statement: f(x) = Σcₘ𝟙(x∈Rₘ) is not differentiable at its finitely many split points, and has derivative 0 everywhere else. Together, these mean that ∂L/∂(split point) is always 0 or undefined , so a tree cannot be trained by gradient descent. It instead maximizes Gain using greedy exhaustive search. This also explains why GBM in section 04 performs gradient descent in function space rather than on tree parameters. Averaging these angular steps (bagging) or accumulating them (boosting) produces a much smoother approximation.

Start with 200 defective/normal cases and an 18% defect rate in the parent node (36 defective · 164 normal).

03 How equations calculate feature importance 20 min
Definition MDI (Mean Decrease in Impurity)
Importance(xⱼ) = Σ ΔI(splitᵢ)  — Across all nodes split using xⱼ
ΔI(splitᵢ)
Impurity reduction at that split
Gain (classification) or ΔMSE (regression) from section 02
Σ (all trees, all splits)
Sum every split that uses variable xⱼ
Repeated uses of one variable at multiple nodes accumulate
Normalization
Sum of all feature importances = 1
This is the value in sklearn feature_importances_
Connection to section 02 — The measure changes, but the calculation structure stays the same

As we saw in section 02, classification sums reductions in Gini or Entropy; regression sums reductions in MSE to obtain feature importance. Whatever the split criterion, MDI accumulates its reduction for each variable.

Calculation exampleCalculate it yourself — Temperature vs pressure importance in a two-level tree

After the first split from section 02 (temperature, all 200 cases, Gain=0.0369), suppose pressure creates a second split within the high-temperature group (92 cases): 40 high-pressure cases (80% defective) and 52 low-pressure cases (10% defective).

SplitCases used / TotalGainContribution = (n/N) × Gain
① Temperature (root, 200 cases) 200/200 0.0369 1.0 × 0.0369 = 0.0369
② Pressure (within high temperature, 92 cases) 92/200 0.2304 0.46 × 0.2304 = 0.1060

Importance(temperature) = 0.0369; Importance(pressure) = 0.1060 → Total = 0.1429
After normalization, Temperature = 0.0369/0.1429 = 25.8%, Pressure = 0.1060/0.1429 = 74.2%

Temperature examined all 200 cases at the root but had a small Gain. Pressure examined only a subset of 92 cases but separated defective and normal cases much more strongly within it (Gain=0.2304). MDI multiplies the number of cases examined by how effectively they are separated, then accumulates those contributions. Therefore a variable used less often can receive higher importance if it separates the classes strongly.

Pitfall — High-cardinality variables are easily overvalued: a mathematical explanation

A variable with many candidate splits, such as a continuous variable, has more chances to find a split that looks good only by chance in the training data. This chance enters the Gini/Entropy/MSE equations through two routes.

Route ① — pₖ is actually p̂ₖ (a sample proportion), which easily reaches extremes in small nodes

In Gini = 1−Σp̂ₖ², p̂ₖ is not a true probability but the proportion of samples in that node. Smaller nodes are more likely to reach p̂ₖ=0 or 1 by chance. Even when a split variable is unrelated to y, all three samples in a node may share one class (25% probability for balanced classes). Then that node's Gini is exactly 0, inflating Gain beyond the genuine effect. Entropy has the same issue (p̂=1 gives −1·log₂1=0).

Extreme thought experiment — a completely unique variable such as customer ID and split to the end, each leaf contains one sample. All leaves have p̂=1 and Gini=0 → Gain reaches its theoretical maximum (the entire parent impurity). The variable carries no information, yet the equation makes it look perfect. Regression behaves the same way: MSE(node)=(1/n)Σ(yᵢ−ȳ)² is exactly 0 in a one-sample node, so finer splits increase ΔMSE for free.

Route ② — The tree chooses a maximum, but the equation has no penalty for the number of attempts

What the tree actually calculates is Gain* = max(all variables × all candidate split points). Even for a variable completely unrelated to y, sample noise makes each candidate's Gain a random value fluctuating near 0. However, the maximum among K noisy values increases as K grows. Each candidate is a lottery ticket, and the tree submits only the best ticket drawn.

One actual lottery — Comparing two meaningless variables

y = Four A and four B (parent Gini = 0.5). Compare two variables completely unrelated to y .

Meaningless continuous variable — Sorting the eight observations by this variable produces a random class order:

Sorted order: A A B A B B A B
Split positions: ↑₁ ↑₂ ↑₃ ↑₄ ↑₅ ↑₆ ↑₇   ← 7 candidates = 7 lottery tickets

Most of the seven Gain values are tiny, but position ②creates a problem: the left side {A, A} is pure by chance, giving Gini=0; the right side has 2A/4B, giving Gini≈0.444.
Weighted average = (2/8)×0 + (6/8)×0.444 = 0.333 → Gain = 0.5 − 0.333 = 0.167
This is fairly large despite arising entirely from noise. Among seven tickets, the tree selects only this one to submit.

Meaningless binary variable — There is only one split. A 4:4 split into 2A2B/2A2B gives Gain≈0; even a lucky 3A1B/1A3B split gives Gain=0.125. Either way, the one result must be submitted as it is, good or bad — There is no second draw.

Both variables are equally meaningless for y, yet the continuous one looks better to the tree. This reflects different numbers of attempts rather than different ability. As an analogy, the tallest person among 100 is taller on average than the tallest among 2, even if both groups come from the same population.

Statistically, this has the same structure as running multiple tests and reporting only the best result without correction. Since Gain/ΔMSE contains no term for how many candidates were tried, this bias accumulates directly in MDI.

Practical responses — C4.5 introduced Gain Ratio by dividing Gain by split information, while sklearn uses permutation importance(shuffle a variable in validation data and measure the performance drop) as an alternative to MDI without this bias. Either way, the conclusion is the same: assess overfitting alongside the importance ranking.

One step further — Trees are nonparametric; what about ensembles?
What parametric really means — More than just having parameters

Parametric = Before seeing the data, the form of f is fixed, and learning means filling in a finite number of parameter values within that fixed form.
. Linear regression is a typical example: f = β₀+β₁x₁+β₂x₂ is specified independently of the data. Whether there are 100 observations or 1 million, the model still estimates three β values.

Non-parametric = The data determines the function's form itself. As more data arrives, model complexity (the effective number of parameters) may also grow.
A tree is a typical example: the data determines which variables to split, where, and how many times. More data can lead to deeper branching.

AdaBoost and GBM have αₘ and γₘ — Yet they are still nonparametric

The boosting equation F(x) = Σαₘhₘ(x) contains coefficients (αₘ), which may suggest a parametric model. It remains nonparametric for two reasons.

① The base learner hₘ is a tree — The data determines each tree's split variables and points. Combining nonparametric components produces a nonparametric model.
② The form of F is not fixed in advance — The data determines which trees are stacked and in what order. We cannot specify a fixed form such as F=β₀+β₁x beforehand.

Thus αₘ and γₘ are coefficients that resemble parameters but do not meet the parametric definition: “a fixed functional form + a finite parameter set independent of data size”.

ModelTypeReason
Linear / Logistic regressionParametricFixed form of f; parameter count independent of the data
Decision TreeNon-parametricThe data determines the branching structure itself
RandomForest (Bagging)Non-parametricAn average of nonparametric trees
AdaBoost / GBM / XGBoostNon-parametricA weighted sum of nonparametric trees with data-dependent structure
An interesting counterexample — The base learner, rather than boosting itself, decides

If boosting uses linear models as base learners instead of trees(for example, XGBoost's booster='gblinear'), a sum of linear models is still linear, so the result is parametric.
The ensemble method itself does not determine whether the model is parametric; the base learner does.

04 Bagging vs Boosting — Different mathematical structures 30 min

f_b(x)
The bth independent tree

Var(f_bag) = ρσ² + ((1−ρ)/B)σ²

Before the derivation — Be clear about what Var measures

The variance in this derivation assumes a thought experiment:

“Resample the training data → Train the whole forest again from scratch → Feed in the same x and record its prediction.” Repeat this hundreds of times; then the variability of the recorded predictions is Var(f_bag).

Similarly, σ² = Var(f_b) is the variability from performing the same experiment with one tree. Trees are unstable: changing even a few observations may change their splits substantially, so σ² is large. Bagging asks, “If one tree varies by σ², how much does the average of B trees vary?”.

ProofWhere does Var(f_bag) come from? — Derive it from the beginning
Preparation 1 — Why is Var(aX) = a²Var(X)?

Variance is the average squared deviation from the mean. Halving values that fluctuate as {−10, 0, +10} gives {−5, 0, +5}: half the deviation means a quarter of its square. Multiplying X by a therefore multiplies its variance by a². Since an average is a sum × (1/B), Var(f_bag) = (1/B)²·Var(Σf_b) = (1/B²)·Var(Σf_b).

Preparation 2 — Why covariance appears in the variance of a sum: (a+b)² = a²+b²+2ab

Let a be the deviation of X and b the deviation of Y. The deviation of X+Y is a+b, and its variance is the average of the squared deviation:

(a+b)² = a² + b² + 2ab  →  Var(X+Y) = Var(X) + Var(Y) + 2Cov(X,Y)

The average of a² is Var(X), and that of b² is Var(Y), while the average of the cross term ab is exactly the definition of covariance. Intuitively, if Y tends to be positive when X deviates positively, ab is usually positive and the sum fluctuates more. If they are unrelated, positive and negative ab values cancel to average 0; only then does the variance of the sum equal the sum of variances. Thus, the covariance term is an extra charge for moving together. Trees originate from the same data and fluctuate together, so this charge cannot be avoided.

Main derivation — Expand everything by hand for B=3

Let a₁, a₂, and a₃ be the deviations of three trees. The squared deviation of their sum is:

(a₁+a₂+a₃)² = a₁²+a₂²+a₃² + a₁a₂+a₁a₃+a₂a₁+a₂a₃+a₃a₁+a₃a₂

A 3×3 table has 9 cells:

a₁a₂a₃
a₁σ²ρσ²ρσ²
a₂ρσ²σ²ρσ²
a₃ρσ²ρσ²σ²

3 diagonal cells = The mean of each squared deviation (aᵦ²), each equal to σ². The 6 off-diagonal cells = The mean of each cross term (aᵦaᵦ'), each equal to Cov = ρ·σ·σ = ρσ² (covariance = correlation × the product of both standard deviations; assume the same σ² and ρ because all trees are built in the same way).

Var(f₁+f₂+f₃) = 3σ² + 6ρσ²  →  Var(f_bag) = (3σ² + 6ρσ²)/9 = σ²/3 + (2/3)ρσ²

For general B, the B×B table has B diagonal cells and B(B−1) off-diagonal cells (for B=3, 3×2=6, matching the table above):

Var(f_bag) = (1/B²)[B·σ² + B(B−1)·ρσ²] = σ²/B + ((B−1)/B)·ρσ²
Rearrangement — Why does it become ρσ² + (1−ρ)σ²/B?

Here is the algebra that is easy to skip. Since (B−1)/B = 1 − 1/B:

σ²/B + (1 − 1/B)ρσ² = σ²/B + ρσ² − ρσ²/B = ρσ² + (1−ρ)σ²/B

This simply separates the same expression into “the part not divided by B (ρσ²)” and “the part divided by B ((1−ρ)σ²/B)”. This makes it clear what remains as B grows. More trees drive the second term toward 0 because it is divided by B, but the first term, ρσ², contains no B and remains as a floor even with a million trees.

Numerical check — σ²=100, ρ=0.5

Conclusion: increasing the number of trees (B) reduces only (1−ρ)σ²/B; lowering ρ is the only way to lower the floor ρσ². Therefore, reducing correlation (ρ) between trees is more fundamental to variance reduction than adding trees. This explains why RandomForest randomly subsamples variables at every split: deliberately showing different variables to different trees reduces ρ itself.

A common confusion — Variance can refer to two different things

“Making trees different (ρ↓) gives different predictions. Does that not increase variance?” This is a natural question, and half of it is correct. The variance that increases and the variance that decreases refer to different things.

① Differences among trees② Var(f_bag) — What we want to reduce
What varies? Within one forest ,how much the predictions of its 100 trees differ Across repeated resampling and retraining, how much the final prediction (average) changes
When is it measured? Train once , then examine the trees inside Repeat training many times and compare the results (a thought experiment)
What happens when ρ decreases? Increases (we deliberately make the trees different) Decreases (their fluctuations cancel each other)

The σ² in the equation also refers to type ② rather than type ①: it measures not differences among trees but how much one tree fluctuates with different training data. Each tree is assumed to fluctuate by σ²; the real question is whether those fluctuations are synchronized.

ρ→1 — Synchronized fluctuations

When the data changes, all 100 trees make errors in the same direction together . Averaging 100 identical errors leaves the same error → Var(f_bag)→σ², with no benefit from averaging. This is effectively one tree.

ρ→0 — Different fluctuations

When the data changes, some trees err upward and others downward, in different ways . In the average, positive and negative errors cancel → Var(f_bag)→σ²/B, falling to 1/100 for 100 trees.

In a poll of 100 people, if all of them read only the same newspaper(ρ=1), a mistake in that newspaper makes all 100 wrong together. It is effectively asking one person. If 100 people use different information sources(ρ↓), their different errors cancel in the average, stabilizing the result. “100 different opinions” (①↑) and “a trustworthy average” (②↓) can therefore hold simultaneously.

To recap: Differences between trees (①↑) let their errors cancel, reducing variation in the average (②). It is normal for ① and ② to move in opposite directions. Bagging targets ②; a large ① may be helpful because it provides more errors that can cancel.

Residual learning in general — Why do residuals appear in Gradient Boosting?

Boosting builds a function F that minimizes Σᵢ L(yᵢ, F(xᵢ)). Week 1 described learning as finding β to minimize L through gradient descent. Here, the function F itself takes the place of β.

  • ①
    A new perspective on gradient descent — From parameter space to function space
    Ordinary gradient descent: β ← β − η·∂L/∂β (move parameters gradually)
    Function-space gradient descent: F(xᵢ) ← F(xᵢ) − η·∂L/∂F(xᵢ) — Treat the prediction F(xᵢ) at each data point as a movable variable and move it in a direction that reduces loss
  • ②
    The desired direction = Negative gradient
    gᵢ = −∂L(yᵢ, F(xᵢ))/∂F(xᵢ) — A vector (g₁, g₂, ..., gₙ) calculated point by point, indicating the direction and magnitude for moving each prediction to reduce loss fastest
  • ③
    Problem — This direction is defined only at the n training points
    A new x has no gᵢ. Therefore, train a tree hₘ on the n (xᵢ, gᵢ) pairs. The vector (g₁,...,gₙ) is defined only at n points, but the learned tree hₘ becomes a function defined over the entire input space(explained further below)
  • ④
    One update = Fₘ = Fₘ₋₁ + γₘhₘ
    Exactly the same structure as β ← β − η·grad: hₘ plays the role of −grad, and γₘ is the learning rate (step size)

Thus, Gradient Boosting = Gradient descent in function space, with trees serving as tools to approximate the gradient.

Connection to section 02 — How can nondifferentiable trees use a gradient?
As seen in section 02, trees themselves cannot be trained by gradient descent because their splits are not differentiable. The Gradient in GBM refers to differentiating the loss function L(∂L/∂F, the derivative with respect to predictions), rather than the tree. There are two layers: The outer loop differentiates the loss to determine the next training target gᵢ (uses derivatives); the inner loop fits a tree to gᵢ through exhaustive Gain search (no derivatives). Even GBM constructs each tree without differentiation: “stack nondifferentiable models (trees) under guidance from a differentiable quantity (loss)” is the precise picture of GBM.
A sharp question — If we move F(xᵢ), do other predictions move too?

Does gᵢ really apply only to sample i, or does moving one prediction change the entire model and other samples? This is a valid question, and the answer is “they are fully separate in function space”. The reason is that the total loss decomposes into a sum of per-sample terms:

Σᵢ L(yᵢ, F(xᵢ)) = L(y₁, F(x₁)) + L(y₂, F(x₂)) + ··· + L(yₙ, F(xₙ))

In function space, F(x₁), ..., F(xₙ) are n independent knobs. Term i depends only on F(xᵢ), so differentiating with respect to F(xᵢ) makes all other terms 0: there are no cross terms. Moving F(x₃) does not change the loss at F(x₇).

Parameter space (linear regression)Function space (GBM's perspective)
What moves? β — Parameters shared by all samples Each F(xᵢ) — A prediction independent for each sample
Moving one causes all sample predictions to move simultaneously only that sample's prediction to move
Gradient form ∂L/∂β = Σᵢ(...) — A sum across all samples gᵢ — Separate for each sample

The Σ in linear regression's ∂L/∂β appears precisely because β is shared. Function space has no shared parameters, so the gradients separate by sample without Σ.

However, the intuition that moving one affects others becomes correct again at the tree-training step. Moving n knobs separately resembles memorizing the training data. In step ③, train tree hₘ instead: one tree leaf groups multiple samples and forces them to share a value. This couples the samples. In other words, gradient calculation collects each sample's preferred direction independently; tree training compromises by moving similar x values together in the same direction. This compromise helps GBM generalize instead of simply memorize.

Vector → Function — Why is the tree defined for every x?

“If training uses n observations, why is hₘ a function of every x?” Here, generalization means “a value is defined at every x,” rather than a guarantee of accurate predictions everywhere.

  • Problem
    The gradient (g₁, ..., gₙ) is not a function but a vector of length n
    “Move by −10 at x₃ and +5 at x₇.” Instructions exist only at the n training points, with none for a new x*
  • Solution
    The learned tree is hₘ(x) = Σcₘ𝟙(x∈Rₘ) — Its regions Rₘ cover the entire input space without gaps
    The rule “temperature>85 goes here” applies even to an unseen temperature of 87.3. Every x* must fall into a leaf and receive its value, using the equation from section 02
  • Assumption
    Extend instructions at n points by assuming that similar x values should move in similar directions
    Whether this extension is accurate is a separate issue, motivating the later discussion of overfitting and shrinkage

This is not unique to GBM: all supervised learning does precisely this. Linear regression also trains on n (xᵢ, yᵢ) pairs but produces β̂ᵀx, which gives a value for any x. GBM's distinguishing feature is simply that its training target is g (the gradient) rather than y.

ProofDifferentiate squared error to obtain residuals — Calculate it directly

Set the loss to L = ½(yᵢ − F(xᵢ))²and differentiate while treating F(xᵢ) as the variable.

∂L/∂F(xᵢ) = ½ · 2 · (yᵢ − F(xᵢ)) · (−1) = −(yᵢ − F(xᵢ))

Apply the chain rule: differentiating the outer square gives 2·(yᵢ−F), and differentiating the inner (yᵢ−F) with respect to F gives −1. Taking the negative gradient then gives:

gᵢ = −∂L/∂F(xᵢ) = yᵢ − F(xᵢ) = rᵢ (residual)

“Learning residuals” is the specific case of a gradient under squared-error loss. The ½ factor convention cancels the 2 from differentiating the square, keeping the equation simple without changing the minimum.

the loss function L−∂L/∂F = gᵢInterpretation
½(y−F)² (squared error, regression) y − F The residual itself — Follow the magnitude of the error directly
|y−F| (absolute error, regression) sign(y − F) Follow only the direction of the error, ignoring its magnitude — Less sensitive to outliers
Cross-entropy (classification) y − p, p=σ(F) Difference between the actual label and predicted probability — A probability residual

The algorithm is the same in all three cases; only the equation for gᵢ changes. This also explains why absolute-error or Huber loss can be more robust than squared error with many outliers: rather than following their large residuals (y−F) directly, absolute-error loss follows only the direction (±1).

ProofHow is γₘ determined? — Deriving line search

Once hₘ is fixed, choose how far to move in that direction (γₘ). The criterion is the γ that reduces loss most at this step:

γₘ = argmin_γ Σᵢ L(yᵢ, Fₘ₋₁(xᵢ) + γ·hₘ(xᵢ))

For squared error, solve it directly. Let J(γ) = Σ½(rᵢ − γhₘ(xᵢ))², where rᵢ = yᵢ−Fₘ₋₁(xᵢ). Differentiate with respect to γ and set it to 0:

dJ/dγ = −Σ hₘ(xᵢ)(rᵢ − γhₘ(xᵢ)) = 0   →   γₘ = Σrᵢhₘ(xᵢ) / Σhₘ(xᵢ)²

Look closely at the form: it is exactly “the slope formula from simple regression without an intercept, with residual r as the response and hₘ(x) as the explanatory variable”(Week 1's β̂ = Σxy/Σx²). At every step, least squares determines how much to multiply the new tree's output to best fit the residuals.

Relationship to the practical learning rate — Libraries such as XGBoost take the optimal correction and multiply it by ν (learning_rate, usually 0.01–0.3) to deliberately apply less of it: Fₘ = Fₘ₋₁ + ν·γₘhₘ. Taking an optimal step every time follows training residuals, including noise, too closely and can overfit. Smaller steps taken more often can generalize better: this is shrinkage. It answers the question of why smaller γ requires more steps m.

StagePrediction FResidual r = y − FNotes

This reveals boosting's defining feature: each tree predicts only what previous stages failed to predict, rather than y itself. After the first tree, no tree serves as a complete predictor on its own: each only predicts residuals. They must accumulate in order to form F. This contrasts with bagging, where each tree is a complete predictor.

Why does the order differ? — The equations explain

In bagging, tree b need not know tree 1. There is no previous term in the equation, and each f_b is trained independently.
In boosting, tree m must know Fₘ₋₁. The equation itself is recursive.

Bagging averages a sum, while boosting accumulates corrections. This structural difference produces their practical differences: parallel vs sequential training, and variance vs bias reduction.
