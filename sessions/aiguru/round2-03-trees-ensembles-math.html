01 불순도 수식 — Gini vs Entropy 25 min
핵심: 트리는 "한 노드 안에 클래스가 얼마나 섞여 있는가"를 숫자로 재고, 그 숫자가 가장 많이 줄어드는 분기를 선택합니다. 이 숫자를 재는 자가 두 가지 있습니다 — Gini와 Entropy.
정의 Gini 불순도
Gini = 1 − Σ pₖ²
pₖ
노드 안 k번째 클래스 비율
불량 50%·정상 50%면 p₁=0.5, p₂=0.5
Σpₖ²
"한 클래스로 쏠린 정도"
모든 pₖ²를 더한 값. 한쪽으로 쏠릴수록 커짐 (0.98²+0.02²=0.96)
1 − (...)
"섞여 있는 정도"로 뒤집기
쏠림이 클수록 Gini는 작아짐 → 0에 가까울수록 순수한 노드
정의 Entropy (정보 엔트로피)
Entropy = − Σ pₖ log₂pₖ
pₖ
Gini와 동일 — 클래스 비율
노드 안 k번째 클래스가 차지하는 비율
−log₂pₖ = log₂(1/pₖ)
그 클래스 하나의 "정보량" (단위: bit)
pₖ가 작을수록(드문 사건일수록) 값이 커짐 — 흔치 않은 일이 일어났을 때 더 많은 정보를 얻는다는 뜻
−Σpₖlog₂pₖ
기댓값(평균 정보량) = 불확실성
각 클래스의 정보량을 그 클래스가 나올 확률(pₖ)로 가중 평균한 것
증명왜 하필 log인가 — "정보량은 더해져야 한다"는 조건에서 출발

정보량을 정의하려면 함수 I(p)가 최소한 이 세 가지를 만족해야 합니다.

  • ①
    확실한 사건(p=1)은 정보량이 0이어야 한다
    이미 알고 있는 사실이 일어나봤자 새로 얻는 정보는 없음
  • ②
    드문 사건일수록(p↓) 정보량은 커야 한다 (단조 감소)
    일어나기 힘든 일이 실제로 일어나면 더 놀랍고, 더 많이 알게 됨
  • ③
    독립적인 두 사건이 동시에 일어났을 때, 정보량은 서로 더해져야 한다
    I(p·q) = I(p) + I(q) — 여기서 문제가 생김

문제는 ③입니다. 독립 사건의 결합 확률은 곱셈(p·q)인데, 정보량은 덧셈이어야 합니다. "곱하면 들어가는 함수의 결과값은 더해지는" 성질을 가진 함수가 필요한 것이고, 이 조건 I(p·q) = I(p) + I(q)을 만족하는 함수는 (연속이고 단조감소라는 조건 하에) 로그함수뿐입니다 — 로그의 정의 자체가 log(a·b) = log(a) + log(b)이기 때문입니다.

여기에 ①②를 만족시키려면 확률이 0~1 사이일 때(log값이 음수) 부호를 뒤집어야 하므로 I(p) = −log(p)가 됩니다. 밑을 2로 두면(log₂) 단위가 "bit"가 되고, 이것이 앞서 본 −log₂pₖ입니다.

계산 예시덧셈 성질 확인 — 동전 두 번 던지기

동전을 두 번 던져 둘 다 앞면(HH)이 나올 확률은 0.5 × 0.5 = 0.25(독립 사건이므로 곱셈).
정보량으로 보면 −log₂(0.25) = 2 bit인데, 이는 정확히 첫 번째 던지기의 정보량(1 bit) + 두 번째 던지기의 정보량(1 bit)과 같습니다.

만약 정보량을 pₖ² 같은 함수로 정의했다면 이 덧셈 성질이 깨졌을 것입니다 — 로그만이 "확률의 곱셈"을 "정보량의 덧셈"으로 바꿔줍니다. Gini(1−Σpₖ²)가 "정보량"이 아니라 "불순도를 대충 근사하는 지표"로 취급되는 이유도 여기 있습니다 — Gini는 이 덧셈 성질을 만족하지 않는, 계산이 가벼운 근사치입니다.

−log₂pₖ를 "질문 횟수"로도 읽을 수 있다 — 스무고개 직관

동전 던지기(앞면 pₖ=0.5)를 맞히려면 질문이 딱 1번 필요합니다: "앞면이야?" → −log₂(0.5) = 1 bit.
어떤 사건의 확률이 pₖ=1/8이라면, 8개 중 하나를 골라내는 데 이진 질문이 3번 필요합니다 (반으로 나누기를 3번 반복 → 8=2³) → −log₂(1/8) = 3 bit.

즉 −log₂pₖ는 "그 사건이 무엇인지 알아내는 데 필요한 예/아니오 질문 횟수"로도 읽을 수 있습니다. 위에서 본 "곱셈→덧셈" 성질과 같은 결론입니다 — 질문 횟수도 독립 사건이 겹치면 그대로 더해지기 때문입니다 (동전 두 번 = 질문 1번+1번 = 2번).

Entropy는 이 "사건 하나당 필요한 질문 수"를 그 사건이 실제로 나올 확률로 가중 평균한 값입니다 — "이 노드 안에서 클래스를 하나씩 뽑아 맞히려면, 평균적으로 몇 번의 질문이 필요한가"라는 뜻입니다.

직접 계산해보기 — pₖ 분포별 Gini vs Entropy

0.90 / 0.10 1−(0.81+0.01) = 0.18 −(0.9·log₂0.9 + 0.1·log₂0.1) = 0.47 꽤 순수하지만 여전히 소수 클래스 존재

숫자로 보면 드러나는 차이 — Entropy가 "소수 클래스"에 더 민감하게 반응

(0.9, 0.1) 지점을 각자의 최댓값 대비 비율로 보면 — Gini는 0.18/0.50 = 36% 수준인데, Entropy는 0.47/1.00 = 47% 수준입니다. 같은 분포인데도 Entropy가 상대적으로 더 "덜 순수하다"고 반응합니다.

이유는 log 함수 자체의 성질에 있습니다 — pₖ가 0에 가까워질 때 log₂pₖ는 가파르게 발산하지만, Gini의 pₖ²는 완만하게 0으로 수렴합니다. 그래서 Entropy는 "적더라도 존재하는 소수 클래스"의 존재를 Gini보다 더 크게 반영합니다.

하지만 실무에서 두 지표로 고른 "최적 분기"는 대부분 일치합니다. 지표 선택 자체보다, "분기라는 행위가 불확실성을 줄인다"는 원리가 존재한다는 것이 더 중요한 결론입니다.

02 분기 기준 — 분류(Gain) vs 회귀(ΔMSE) 30 min
트리는 모든 변수·모든 분기점을 시도해보면서, 분기 후 불확실성이 가장 많이 줄어드는 지점을 선택합니다. 그 전에 먼저 — "분기"라는 if문이 수식으로는 어떻게 쓰이는지부터 봅니다.
모델 표현 트리 = if문의 수식화 (Indicator 함수)
f(x) = Σ cₘ · 𝟙(x ∈ Rₘ)
𝟙(조건)
Indicator 함수 = if문 그 자체
조건이 참이면 1, 거짓이면 0. 예: 𝟙(온도 > 85) — "온도가 85 넘으면 1, 아니면 0"
Rₘ
m번째 잎 노드가 담당하는 영역
분기 조건들의 교집합. 예: R₁ = {온도>85 그리고 압력≤3}
cₘ
그 영역의 예측값
분류: 최빈 클래스 / 회귀: 그 영역 y의 평균 ȳ
코드와 수식의 1:1 대응 — 같은 것을 두 언어로

깊이 2짜리 트리 하나를 코드와 수식으로 나란히 써보면:

코드 (if문)

if 온도 > 85:
  if 압력 > 3: return 0.80
  else:       return 0.35
else:
  return 0.04

수식 (Indicator)

f(x) = 0.80·𝟙(온도>85, 압력>3)
     + 0.35·𝟙(온도>85, 압력≤3)
     + 0.04·𝟙(온도≤85)

어떤 x를 넣어도 정확히 하나의 𝟙만 1이 되고 나머지는 전부 0이 됩니다 — 영역 Rₘ들이 서로 겹치지 않고(disjoint) 전체 공간을 빠짐없이 덮기 때문입니다. 그래서 "합(Σ)"으로 쓰여 있어도 실제로는 딱 하나의 cₘ이 선택되는 조회(lookup) 구조입니다. 이것이 1라운드에서 봤던 "트리는 공간을 사각형으로 자른다"의 수식 버전입니다.

등호는 어느 쪽에 붙는가 — "이하/초과"냐 "미만/이상"이냐
라이브러리 관례일 뿐입니다: sklearn(CART)은 x ≤ t → 왼쪽, x > t → 오른쪽(이하/초과), XGBoost는 x < t → 왼쪽, x ≥ t → 오른쪽(미만/이상). 결과가 사실상 같은 이유는 — 연속형에서 분기점 t는 임의의 값이 아니라 정렬된 관측값 두 개의 중간점으로 잡히기 때문입니다 (예: 84.2와 86.1 사이면 t=85.15). 학습 데이터 중 t에 정확히 올라탄 샘플이 없으므로, 등호를 어느 쪽에 주든 데이터가 갈리는 결과·Gain·학습된 트리가 전부 동일합니다. 등호의 귀속은 "새 데이터가 우연히 정확히 t에 떨어졌을 때 어느 잎으로 보낼까"에 대한 약속일 뿐입니다. 이 자료에서는 sklearn 방식(≤ / >)으로 통일해 표기합니다.
이 표현이 왜 중요한가 — 오늘 세션 전체의 연결고리

① 학습의 대상이 명확해짐 — 트리 학습이란 결국 영역 Rₘ(어디서 자를지)과 값 cₘ(뭐라고 예측할지)을 찾는 것입니다. cₘ은 쉽습니다(평균 또는 최빈값). 어려운 건 Rₘ이고, 그걸 고르는 기준이 바로 아래에서 볼 Gain/ΔMSE입니다.
② 04번(앙상블)과 연결 — Bagging의 f_b(x)도, Boosting의 hₘ(x)도 전부 이 Σcₘ𝟙(x∈Rₘ) 꼴입니다. 앙상블이란 "이 계단 함수들을 평균 내거나(Bagging) 누적해서(Boosting) 매끄러운 함수를 만드는 것"입니다.
③ 왜 non-parametric인지 수식으로 재확인 — 영역의 개수 M과 각 Rₘ의 모양이 전부 데이터로 결정됩니다. β처럼 "몇 개인지 미리 정해진 파라미터"가 없다는 것이 이 수식에서 그대로 보입니다.

토론 질문
"f(x) = Σcₘ𝟙(x∈Rₘ)은 x에 대해 미분이 불가능한 계단 함수입니다. 그런데 선형 회귀는 매끄러운 직선이죠. 이 차이가 '트리는 비선형을 잡는다'는 1라운드의 직관과 어떻게 연결될까요?"
답 가이드 — 곡선이 아니라 "해상도"로 비선형을 잡는다

선형 회귀 f = βᵀx는 어디서나 미분 가능하고 매끄럽지만, 그 대가로 모양이 직선(평면) 하나로 고정됩니다 — "y는 x에 대해 일정한 비율로만 변한다"는 가정을 벗어날 수 없습니다.
트리는 정반대입니다. 기울기라는 개념 자체가 없는 대신, 계단을 어디에 몇 개 놓을지가 완전히 자유롭습니다. 아무리 구불구불한 관계라도 계단을 촘촘히 쌓으면 근사할 수 있습니다 — 곡선을 수식으로 그리는 게 아니라 픽셀(사각형 영역)로 찍어내는 방식의 비선형입니다.

증명"미분 불가능"을 정의로 직접 확인 — 극한이 "없다"는 게 무슨 뜻인가부터

미분 가능이란 아래 극한이 존재한다는 뜻입니다:

f′(x₀) = lim_{h→0} [f(x₀+h) − f(x₀)] / h
STEP 1 — "극한이 존재한다"의 뜻

h를 0으로 점점 줄여가며 위 몫을 계속 계산했을 때, 그 값이 어떤 하나의 숫자로 점점 가까워져 정착하면 극한이 존재하는 것이고, 그 정착한 숫자가 f′(x₀)입니다. 여기엔 조건이 두 개 숨어 있습니다:

  • ⓐ
    정착해야 한다 — 값이 어딘가에 멈춰야지, 계속 커지기만 하면 안 됨
  • ⓑ
    양쪽이 같아야 한다 — h는 양수로도(오른쪽 접근) 음수로도(왼쪽 접근) 0에 갈 수 있는데, 두 방향의 결과가 같은 하나의 숫자여야 함

비유하면 극한은 양쪽에서 걸어와 만나는 약속 장소입니다 — 왼쪽에서 온 사람과 오른쪽에서 온 사람이 같은 지점에 도착해야 "만났다(극한 존재)"고 합니다.

STEP 2 — "극한이 없다" = 두 조건 중 하나가 깨진 것
  • A
    양쪽이 다른 곳에 도착 — 왼쪽 접근은 3에, 오른쪽 접근은 5에 정착 → "그래서 극한값이 뭔데?"에 답할 수 없음 → 극한 없음
  • B
    정착 자체를 안 함 = 발산 — h를 줄일수록 값이 100, 1000, 10000... 어떤 숫자에도 머물지 않고 한없이 커짐. ∞는 숫자가 아니라 "끝없이 커진다"는 상황의 이름일 뿐이라 극한값이 될 수 없음 → 극한 없음. "발산"은 어려운 개념이 아니라 이 상황에 붙인 이름입니다
STEP 3 — 계단 함수 경계에서 실제 숫자로 확인

분기가 하나뿐인 트리를 놓고 봅니다:

트리 (if문)

if 온도 ≤ 85: 예측 = 10  ← c₁
if 온도 > 85: 예측 = 40  ← c₂

10, 40은 각 잎에 속한 y들의 평균 = f(x)의 출력값. 분기점은 85 하나뿐 — 85.1도 90도 200도 전부 "예측 40" 영역

그래프 (계단 한 칸)

40 ─ ┌────────── │ 10 ─ ───────┘ ↑ t=85 → 온도

"접근"이란 — t=85에서의 기울기를 재려면 "85 근처의 점을 잡아 몫을 계산하고, 그 점을 85로 점점 가까이 보내는" 작업이 필요한데, 근처의 점은 두 종류입니다: 85보다 살짝 큰 쪽에서 다가오거나(오른쪽 접근), 살짝 작은 쪽에서 다가오거나(왼쪽 접근).

오른쪽에서 접근: 86 → 85.1 → 85.01 → 85.001 → ... 이 점들은 전부 "온도>85" 영역이라 예측값이 모두 40. f(85) 근방의 오른쪽 값도 40이므로 몫 = (40−40)/거리 = 항상 0. 아무리 가까이 와도 계속 0 → 0에 정착.

왼쪽에서 접근: 84 → 84.9 → 84.99 → 84.999 → ... 이 점들은 전부 "온도≤85" 영역이라 예측값이 모두 10. 그런데 도착지의 값은 40. 몫을 계산하면:

잡은 점예측값 차이거리 h몫 = 차이/거리
84.9300.1300
84.99300.013,000
84.999300.00130,000
84.999930 — 안 줄어듦0.0001300,000 — 정착 기미 없음

핵심이 여기 있습니다 — 가까이 갈수록 거리(분모)는 줄어드는데, 예측값 차이(분자)는 30에서 꿈쩍도 안 합니다. 84.999까지 붙어도 여전히 왼쪽 영역이라 예측은 10이고, 85를 넘는 순간 40이니까요. 점프는 아무리 가까이 가도 미리 좁혀지지 않는 절벽입니다. 그래서 몫이 폭주 = 발산(방식 B).

결론: 오른쪽은 0에 정착, 왼쪽은 발산 — 만남 실패, "하나의 숫자"가 없으므로 극한 없음 → t=85에서 미분 불가능.

STEP 4 — 내부 지점(x=90)과 대비: 왜 90에서는 되는가

주의 — 90은 분기점이 아닙니다. 이 트리의 분기는 85 하나뿐이므로, 90은 ">85 영역"의 한복판에 있는 평범한 점입니다.
왼쪽에서 접근(89.9, 89.99, ...)해도 전부 85보다 크니까 같은 영역, 예측 모두 40. 오른쪽에서 접근(90.1, 90.01, ...)해도 마찬가지로 예측 40. f(90)도 40. 양쪽 다 몫 = (40−40)/거리 = 0 → 둘 다 0에 정착 → 극한 존재, 기울기 0으로 미분 가능.

한 줄 정리 — 85와 90의 차이는 "접근하는 도중에 영역이 바뀌느냐"입니다. x=90은 오는 길 내내 같은 영역이라 분자가 0이고, x=85는 왼쪽에서 오는 길이 전부 다른 영역(예측 10)이라 분자가 끝까지 30으로 살아 있습니다. 그래서 미분이 깨지는 곳은 정확히 분기점들뿐이고 (분기점 3개짜리 트리면 미분 안 되는 점도 딱 3개), 그 외의 모든 점은 평평한 구간 위라 기울기 0입니다.

정확한 진술: f(x) = Σcₘ𝟙(x∈Rₘ)은 분기점(유한 개)에서 미분 불가능하고, 나머지 모든 곳에서 도함수가 0입니다. 이 둘이 합쳐지면 — ∂L/∂(분기점)이 항상 0이거나 정의되지 않아 트리는 경사하강으로 학습할 수 없고, 그래서 Gain 최대화라는 탐욕적 전수 탐색으로 학습합니다. 04에서 볼 GBM이 "트리의 파라미터"가 아니라 함수 공간에서 경사하강을 하는 이유도 여기 있습니다. 한편 이 "각진 계단"을 여러 장 평균 내거나(Bagging) 누적하면(Boosting) 훨씬 부드러운 근사가 됩니다.

02에서 본 것처럼 — 분류는 Gini(또는 Entropy) 감소량의 합, 회귀는 MSE 감소량의 합이 곧 변수 중요도입니다. 분기 기준이 무엇이었든, 그 기준의 "감소량"을 변수별로 누적한 것이 MDI입니다.

계산 예시직접 계산해보기 — 2단계 트리에서 온도 vs 압력 중요도

02에서 구한 1차 분기(온도, 200건 전체 대상, Gain=0.0369)에 이어, 온도 높음 그룹(92건) 안에서 압력으로 2차 분기를 했다고 가정합니다: 압력 높음 40건(불량 80%), 압력 낮음 52건(불량 10%).

분기사용된 건수 / 전체Gain기여도 = (n/N) × Gain
① 온도 (root, 200건) 200/200 0.0369 1.0 × 0.0369 = 0.0369
② 압력 (온도-높음 하위, 92건) 92/200 0.2304 0.46 × 0.2304 = 0.1060

Importance(온도) = 0.0369, Importance(압력) = 0.1060 → 합 = 0.1429
정규화하면 온도 = 0.0369/0.1429 = 25.8%, 압력 = 0.1060/0.1429 = 74.2%

온도는 root에서 전체 데이터(200건)를 다 봤지만 Gain 자체는 작았고, 압력은 부분집합(92건)만 봤지만 그 안에서 훨씬 강하게 불량/정상을 갈랐습니다(Gain 0.2304). MDI는 "몇 건을 봤는지"와 "얼마나 잘 갈랐는지"를 곱해서 누적하기 때문에, 사용 빈도가 낮아도 분리력이 강한 변수가 더 높은 중요도를 받을 수 있습니다.

함정 — 카디널리티가 높은 변수는 과대평가되기 쉽다 (수식으로 보는 이유)

연속형처럼 분기 후보가 많은 변수는 "이번 학습 데이터에서만 우연히 좋아 보이는" 분기를 찾을 확률이 높습니다. 이 "우연"이 Gini/Entropy/MSE 수식 안에서 정확히 어디로 스며드는지 보면 두 개의 통로가 있습니다.

통로 ① — 수식의 pₖ는 사실 p̂ₖ(표본 비율)이고, 작은 노드에서 쉽게 극단값을 친다

Gini = 1−Σp̂ₖ²의 p̂ₖ는 진짜 확률이 아니라 그 노드에 담긴 표본의 비율입니다. 노드가 작을수록 p̂ₖ가 우연히 0이나 1을 치기 쉽습니다 — 샘플 3개짜리 노드는 y와 무관한 변수로 갈랐어도 셋 다 같은 클래스일 확률이 꽤 되고(반반 클래스면 25%), 그 순간 그 노드의 Gini는 정확히 0이 되어 Gain이 실제 이상으로 부풀려집니다. Entropy도 동일합니다(p̂=1이면 −1·log₂1=0).

극단적 사고 실험 — 고객ID처럼 전부 유니크한 변수로 끝까지 가르면 잎마다 샘플 1개, 모든 잎에서 p̂=1, 모든 잎의 Gini=0 → Gain이 이론상 최댓값(부모 불순도 전체)이 됩니다. 정보량은 0인데 수식상으로는 "완벽한 변수"로 보이는 것입니다. 회귀도 똑같습니다 — MSE(node)=(1/n)Σ(yᵢ−ȳ)²는 샘플 1개짜리 노드에서 정확히 0이라, 잘게 가를수록 ΔMSE가 공짜로 커집니다.

통로 ② — 트리는 "최댓값"을 고르는데, 수식엔 시도 횟수에 대한 벌점이 없다

트리가 실제로 계산하는 것은 Gain* = max(모든 변수 × 모든 분기점 후보)입니다. y와 완전히 무관한 변수라도 각 후보의 Gain은 표본 노이즈 때문에 0 근처에서 흔들리는 랜덤값인데, 노이즈 K개 중 최댓값은 K가 클수록 커집니다. 후보 하나하나가 제비뽑기 한 장이고, 트리는 뽑은 것 중 제일 좋은 것만 제출하기 때문입니다.

제비뽑기 한 판을 실제로 — 무의미한 변수 둘의 대결

y = A 4개, B 4개 (부모 Gini = 0.5). y와 완전히 무관한 변수 둘을 비교합니다.

무의미한 연속형 변수 — 이 변수로 8개를 정렬하면 클래스가 무작위 순서로 늘어섭니다:

정렬 결과:  A  A  B  A  B  B  A  B

7개 자리의 Gain을 전부 계산하면 대부분 미미하지만, ②번 자리가 문제입니다 — 왼쪽 {A, A}가 우연히 순수해서 Gini=0, 오른쪽은 2A/4B로 Gini≈0.444.
가중평균 = (2/8)×0 + (6/8)×0.444 = 0.333 → Gain = 0.5 − 0.333 = 0.167
완전한 노이즈에서 나온 값인데 꽤 큽니다. 트리는 7장 중 이것만 골라서 제출합니다.

무의미한 이진 변수 — 가르는 방법이 1가지뿐입니다. 4:4로 갈라 양쪽이 2A2B/2A2B쯤 되면 Gain≈0, 운 좋게 3A1B/1A3B가 되어도 Gain=0.125. 어느 쪽이든 그 1장의 결과를 좋든 나쁘든 그대로 제출해야 합니다 — 다시 뽑을 기회가 없습니다.

Parametric의 진짜 기준 — "파라미터가 있다"가 아니다

Parametric = 데이터를 보기 전에 함수 f의 형태가 고정되어 있고, 학습이란 그 고정된 형태 안의 유한 개 파라미터 값을 채우는 것.
선형 회귀가 대표적입니다 — f = β₀+β₁x₁+β₂x₂라는 형태가 데이터와 무관하게 먼저 정해지고, 데이터가 100건이든 100만 건이든 추정할 파라미터는 β 3개로 동일합니다.

Non-parametric = 함수의 형태 자체가 데이터에 의해 결정됨. 데이터가 늘어나면 모델의 복잡도(유효 파라미터 수)도 함께 늘어날 수 있음.
트리가 대표적입니다 — "어느 변수를, 어느 지점에서, 몇 번 나눌지"가 전부 데이터가 결정하고, 데이터가 많아지면 분기가 더 깊어질 수 있습니다.

AdaBoost·GBM에는 αₘ, γₘ이 있는데 — 그래도 Non-parametric

Boosting의 수식 F(x) = Σαₘhₘ(x)를 보면 계수(αₘ)가 있어서 "파라미터가 있으니 parametric 아닌가?" 싶지만, 두 가지 이유로 non-parametric입니다.

① 베이스 학습기 hₘ이 트리 — 각 hₘ의 분기 변수·분기점이 데이터로 결정됩니다. Non-parametric한 부품을 합성한 모델은 전체도 non-parametric입니다.
② F의 함수 형태가 사전에 고정되지 않음 — 어떤 트리들이 어떤 순서로 쌓일지는 데이터가 결정합니다. "F는 β₀+β₁x 꼴이다"처럼 형태를 미리 쓸 수 없습니다.

즉 αₘ, γₘ은 "파라미터처럼 보이는 계수"일 뿐, parametric의 정의인 "고정된 함수 형태 + 데이터 크기와 무관한 유한 파라미터 집합"을 만족하지 않습니다.

핵심: 둘 다 트리를 여러 개 쓰지만, 여러 개를 쓰는 목적과 방식이 수식 구조상 완전히 다릅니다.

유도에 들어가기 전 — "Var"가 무엇에 대한 분산인지부터 확실히

이 유도에서 말하는 분산은 사고 실험을 전제로 합니다:

"학습 데이터를 새로 뽑아서 → 포레스트 전체를 처음부터 다시 학습시키고 → 같은 x 하나를 넣어 예측값을 기록한다" — 이 실험을 수백 번 반복했을 때, 기록된 예측값들이 얼마나 출렁이는가가 Var(f_bag)입니다.

마찬가지로 σ² = Var(f_b)는 "트리 한 그루로 같은 실험을 했을 때의 출렁임"입니다. 트리는 데이터 몇 건만 바뀌어도 분기가 확 바뀌는 불안정한 모델이라 이 σ²가 큽니다 — Bagging의 질문은 "한 그루는 σ²만큼 출렁이는데, B그루를 평균 내면 얼마나 출렁이는가?"입니다.

증명Var(f_bag) 공식이 어떻게 나오는가 — 바닥부터 직접 유도
준비 1 — Var(aX) = a²Var(X)는 왜?

분산 = "평균에서 벗어난 정도(편차)를 제곱해서 평균 낸 것"입니다. 어떤 값이 {−10, 0, +10}으로 흔들릴 때 전부 ½로 줄이면 {−5, 0, +5} — 편차가 ½이 되면 편차의 제곱은 ¼. 그래서 X에 a를 곱하면 분산에는 a²이 붙습니다. 평균은 "합 × (1/B)"이므로 Var(f_bag) = (1/B)²·Var(Σf_b) = (1/B²)·Var(Σf_b).

준비 2 — 합의 분산에서 공분산이 튀어나오는 이유: (a+b)² = a²+b²+2ab

X의 편차를 a, Y의 편차를 b라 하면, (X+Y)의 편차는 a+b이고 분산은 그 제곱의 평균입니다:

(a+b)² = a² + b² + 2ab  →  Var(X+Y) = Var(X) + Var(Y) + 2Cov(X,Y)

a²의 평균이 Var(X), b²의 평균이 Var(Y), 그리고 교차항 ab의 평균이 공분산의 정의 그 자체입니다. 직관 — X가 +로 벗어날 때 Y도 +로 벗어나는 경향이면(같이 흔들림) ab가 주로 양수 → 합의 흔들림이 더 커짐. 서로 무관하면 ab가 +와 −가 반반이라 평균 0 → 그때만 "합의 분산 = 분산의 합". 즉 공분산 항은 "같이 흔들리는 만큼의 추가 요금"입니다. 트리들은 같은 원본 데이터에서 나와 같이 흔들리므로 이 요금을 피할 수 없습니다.

본 유도 — B=3으로 전부 손으로 전개

트리 3그루의 편차를 a₁, a₂, a₃이라 하면, 합의 편차 제곱은:

(a₁+a₂+a₃)² = a₁²+a₂²+a₃² + a₁a₂+a₁a₃+a₂a₁+a₂a₃+a₃a₁+a₃a₂

3×3 표로 보면 총 9칸입니다:

a₁a₂a₃
a₁σ²ρσ²ρσ²
a₂ρσ²σ²ρσ²
a₃ρσ²ρσ²σ²

대각선 3칸 = 자기 제곱(aᵦ²)의 평균 = 각각 σ². 비대각 6칸 = 교차항(aᵦaᵦ')의 평균 = 각각 Cov = ρ·σ·σ = ρσ² (공분산 = 상관계수 × 두 표준편차의 곱, 모든 트리가 같은 방식으로 만들어졌으니 전부 같은 σ²와 ρ로 둠).

Var(f₁+f₂+f₃) = 3σ² + 6ρσ²  →  Var(f_bag) = (3σ² + 6ρσ²)/9 = σ²/3 + (2/3)ρσ²

일반 B로 바꾸면 — B×B 표에서 대각선이 B칸, 비대각이 B(B−1)칸 (B=3일 때 3×2=6칸, 위 표와 일치):

Var(f_bag) = (1/B²)[B·σ² + B(B−1)·ρσ²] = σ²/B + ((B−1)/B)·ρσ²
재배열 — 왜 갑자기 ρσ² + (1−ρ)σ²/B 모양이 되는가

건너뛰기 쉬운 대수가 여기 있습니다. (B−1)/B = 1 − 1/B 이므로:

σ²/B + (1 − 1/B)ρσ² = σ²/B + ρσ² − ρσ²/B = ρσ² + (1−ρ)σ²/B

같은 식을 "B에 안 나눠지는 부분(ρσ²)"과 "B에 나눠지는 부분((1−ρ)σ²/B)"으로 갈라 쓴 것뿐입니다. 이렇게 갈라놓으면 B를 키웠을 때 뭐가 남는지가 한눈에 보입니다 — 뒷항은 B로 나눠지니 트리를 늘릴수록 0으로 사라지지만, 앞항 ρσ²에는 B가 아예 없어서 트리를 백만 그루 심어도 그대로 남는 "바닥"입니다.

결론: 트리 개수(B)로 줄일 수 있는 건 (1−ρ)σ²/B 부분뿐이고, ρσ²라는 바닥은 오직 ρ를 낮춰야만 내려갑니다. 그래서 트리 개수를 늘리는 것보다 트리 간 상관(ρ)을 낮추는 것이 분산 감소에 더 근본적이고, RandomForest가 매 분기마다 변수를 랜덤 서브샘플링하는 이유가 여기서 나옵니다 — 일부러 트리마다 다른 변수를 보게 해서 ρ 자체를 끌어내리는 장치입니다.

무엇의 흩어짐? 한 포레스트 안에서, 트리 100그루의 예측값들이 서로 얼마나 다른가 학습 데이터를 다시 뽑아 재학습할 때마다 최종 예측(평균)이 얼마나 출렁이는가

수식의 σ²도 ①이 아니라 ② 계열입니다 — "트리들 사이의 차이"가 아니라 트리 한 그루가 학습 데이터에 따라 출렁이는 정도입니다. 모든 트리가 각자 σ²만큼 흔들린다는 건 정해져 있고, 진짜 문제는 그 흔들림이 동기화되어 있느냐입니다.

ρ→1 — 동기화된 흔들림

데이터가 바뀌면 100그루가 전부 같은 방향으로 같이 틀립니다. 평균을 내도 "같은 실수 100개의 평균 = 그 실수 그대로" — Var(f_bag)→σ², 평균의 이득이 0. 사실상 트리 1그루와 같습니다.

ρ→0 — 제각각의 흔들림

데이터가 바뀌면 어떤 트리는 위로, 어떤 트리는 아래로 제각각 틀립니다. 평균에서 +실수와 −실수가 서로 상쇄 — Var(f_bag)→σ²/B, 100그루면 1/100로 급감.

여론조사에 비유하면 — 100명에게 물어보는데 100명이 전부 같은 신문만 보는 사람들이면(ρ=1) 그 신문이 틀린 날엔 100명이 다 같이 틀리므로, 사실상 1명에게 물어본 것과 같습니다. 서로 다른 정보원을 가진 100명이면(ρ↓) 각자 틀리는 부분이 달라 평균에서 상쇄되고, 결과가 안정적입니다. "100명이 서로 다른 의견을 낸다"(①↑)는 것과 "그 평균이 믿을 만하다"(②↓)는 것이 동시에 성립하는 이유입니다.

정리하면: 트리들이 서로 달라서(①↑) 오히려 실수가 상쇄되고, 그 결과 평균의 흔들림(②)이 줄어듭니다. ①과 ②는 반대로 움직이는 게 정상이고, Bagging이 노리는 것은 ②입니다. 오히려 ①이 크다는 것은 "상쇄시킬 재료가 풍부하다"는 좋은 신호입니다.

잔차 학습의 일반형 — 왜 "잔차"가 나오는가 (Gradient Boosting)

Boosting의 목표는 Σᵢ L(yᵢ, F(xᵢ))를 최소화하는 함수 F를 만드는 것입니다. Week1에서 "학습 = L을 최소화하는 β 찾기 = 경사하강"이었다면, 여기서는 β 자리에 함수 F 자체가 들어갑니다.

  • ①
    경사하강의 관점 전환 — "파라미터 공간"에서 "함수 공간"으로
    일반 경사하강: β ← β − η·∂L/∂β (파라미터를 조금씩 이동)
    함수 공간 경사하강: F(xᵢ) ← F(xᵢ) − η·∂L/∂F(xᵢ) — 각 데이터 포인트에서의 예측값 F(xᵢ) 자체를 하나의 "움직일 수 있는 변수"로 취급하고, 손실이 줄어드는 방향으로 이동시킴
  • ②
    움직여야 할 방향 = 음의 그래디언트
    gᵢ = −∂L(yᵢ, F(xᵢ))/∂F(xᵢ) — "i번째 예측값을 어느 방향으로 얼마나 밀면 손실이 가장 빨리 줄어드는가"를 데이터 포인트마다 계산한 벡터 (g₁, g₂, ..., gₙ)
  • ③
    문제 — 이 방향은 "학습 데이터 n개 지점"에서만 정의된다
    새로운 x가 들어오면 gᵢ가 없음. 그래서 이 n개의 (xᵢ, gᵢ) 쌍을 학습 데이터 삼아 트리 hₘ을 학습시킴 — 벡터(g₁,...,gₙ)는 n개 지점에서만 정의되지만, 학습된 트리 hₘ은 입력 공간 전체에서 값이 정의되는 함수가 됨 (아래 박스에서 상세히)
  • ④
    한 걸음 이동 = Fₘ = Fₘ₋₁ + γₘhₘ
    경사하강의 "β ← β − η·grad"와 정확히 같은 구조. hₘ이 −grad 역할, γₘ이 학습률(step size) 역할

즉 Gradient Boosting = 함수 공간에서의 경사하강이고, 트리는 "그래디언트를 근사하는 도구"로 쓰이는 것입니다.

02와 연결 — "미분 안 되는 트리로 어떻게 Gradient를?"
02에서 봤듯 트리 자체는 미분이 안 되어 경사하강 학습이 불가능합니다. GBM에 "Gradient"가 붙는 이유는 미분 대상이 트리가 아니라 손실함수 L이기 때문입니다 (∂L/∂F — 예측값에 대한 미분). 구조가 두 겹입니다: 바깥 루프는 손실을 미분해 "다음에 학습할 타깃(gᵢ)"을 정하고(미분 사용), 안쪽 루프는 그 gᵢ에 트리 하나를 맞추는데 여기는 여전히 Gain 전수 조사입니다(미분 없음). 즉 GBM조차 트리를 만드는 순간만큼은 미분 없이 갑니다 — "미분이 안 되는 모델(트리)을, 미분이 되는 것(손실)의 안내를 받아 쌓는다"가 GBM의 정확한 그림입니다.
날카로운 질문 — "F(xᵢ)를 밀면 다른 샘플의 예측도 같이 움직이는 것 아닌가?"

gᵢ가 정말 i번째 샘플에만 해당하는 값인지, 아니면 하나를 밀면 모델 전체가 바뀌어서 다른 샘플에도 영향이 가는지 — 정확한 의문이고, 답은 "함수 공간에서는 완전히 분리된다"입니다. 이유는 전체 손실이 샘플별 덧셈으로 분해되기 때문입니다:

Σᵢ L(yᵢ, F(xᵢ)) = L(y₁, F(x₁)) + L(y₂, F(x₂)) + ··· + L(yₙ, F(xₙ))

함수 공간 관점에서 F(x₁), ..., F(xₙ)은 서로 독립적인 n개의 손잡이(knob)입니다. i번째 항은 오직 F(xᵢ) 하나에만 의존하므로, F(xᵢ)로 미분하면 나머지 항은 전부 0 — 교차 항이 없습니다. F(x₃)를 밀어도 F(x₇)의 손실은 전혀 변하지 않습니다.

파라미터 공간 (선형 회귀)함수 공간 (GBM의 관점)
움직이는 것 β — 모든 샘플이 공유 F(xᵢ) 각각 — 샘플마다 독립
하나를 밀면 모든 샘플의 예측이 동시에 움직임 그 샘플의 예측만 움직임
그래디언트 형태 ∂L/∂β = Σᵢ(...) — 전 샘플의 합 gᵢ — 샘플별로 따로

선형 회귀의 ∂L/∂β에 Σ가 붙는 이유가 정확히 "β가 공유 파라미터라서"입니다. 함수 공간에는 공유 파라미터가 없으니 Σ 없이 샘플별로 완전히 분리됩니다.

그런데 — "하나를 밀면 전체가 움직인다"는 직관이 다시 맞아지는 곳이 트리 학습 단계입니다. n개 손잡이를 각자 따로 미는 것은 학습 데이터를 외우는 것과 같아서, ③단계에서 트리 hₘ을 학습시키는데 트리는 잎 하나가 여러 샘플을 묶어 같은 값을 강제합니다. 여기서 비로소 샘플들이 서로 연결(coupling)됩니다. 정리하면 — 그래디언트 계산 단계는 "각자 어디로 가고 싶은지" 수집(샘플별 독립), 트리 학습 단계는 "비슷한 x끼리 같은 방향으로 함께 가라"는 타협(샘플 간 연결)입니다. 이 타협이 GBM이 암기가 아니라 일반화를 하는 이유이기도 합니다.

벡터 → 함수 — 왜 트리를 거치면 "모든 x에서 정의"되는가

"n개 데이터로 학습했는데 왜 hₘ이 모든 x에 대한 함수인가?" — 여기서 "일반화"는 "모든 x에서 잘 맞는다"는 보장이 아니라 "모든 x에서 값이 정의된다"는 뜻입니다.

  • 문제
    그래디언트 (g₁, ..., gₙ)은 함수가 아니라 길이 n짜리 벡터
    "x₃에서는 −10만큼, x₇에서는 +5만큼 밀어라" — 지시가 학습 데이터 n개 지점에만 존재. 새로운 x*에 대한 지시는 없음
  • 해결
    학습된 트리는 hₘ(x) = Σcₘ𝟙(x∈Rₘ) — 영역 Rₘ들이 입력 공간 전체를 빈틈없이 덮음
    "온도>85면 이쪽" 규칙은 학습 데이터에 없던 온도 87.3짜리에도 그냥 적용됨. 어떤 x*든 반드시 어느 잎에 떨어지고 그 잎의 값을 받음 (02에서 본 수식 그대로)
  • 가정
    n개 점의 지시를 "비슷한 x는 비슷한 방향으로 밀렸을 것"이라는 가정으로 확장한 것
    이 확장이 실제로 잘 맞을지는 별개 문제 — 그래서 과적합·shrinkage 논의가 뒤따름

사실 이건 GBM만의 특별한 일이 아닙니다 — 모든 지도학습이 하는 일이 정확히 이것입니다. 선형 회귀도 n개의 (xᵢ, yᵢ)로 학습하지만 결과물 β̂ᵀx는 어떤 x에든 값을 줍니다. GBM의 특이점은 학습 타깃이 y가 아니라 g(그래디언트)라는 것뿐입니다.

증명제곱오차에서 잔차가 나오는 미분 과정 — 직접 계산

손실함수를 L = ½(yᵢ − F(xᵢ))²로 두고, F(xᵢ)를 변수 취급해서 미분합니다.

∂L/∂F(xᵢ) = ½ · 2 · (yᵢ − F(xᵢ)) · (−1) = −(yᵢ − F(xᵢ))

합성함수 미분(chain rule)입니다 — 바깥(제곱)을 미분하면 2·(yᵢ−F), 안(yᵢ−F)을 F로 미분하면 −1. 여기에 음(−)의 그래디언트를 취하면:

gᵢ = −∂L/∂F(xᵢ) = yᵢ − F(xᵢ) = rᵢ (잔차)

"잔차를 학습한다"는 말은 사실 "제곱오차를 썼을 때의 그래디언트"라는 특수한 경우입니다. ½을 붙이는 이유도 여기서 보입니다 — 미분할 때 제곱의 2와 상쇄되어 식이 깔끔해지는 관례적 장치일 뿐, 최소화 지점은 바뀌지 않습니다.

손실함수 L−∂L/∂F = gᵢ해석
½(y−F)² (제곱오차, 회귀) y − F 잔차 그 자체 — "얼마나 빗나갔는지"를 그대로 좇음
|y−F| (절대오차, 회귀) sign(y − F) 빗나간 "방향"만 좇고 크기는 무시 — 이상치에 둔감해짐
cross-entropy (분류) y − p, p=σ(F) 실제 라벨과 예측 확률의 차이 — "확률의 잔차" 형태

세 경우 모두 알고리즘은 동일하고 gᵢ의 식만 바뀝니다. 이상치가 많은 데이터에서 제곱오차 대신 절대오차(또는 Huber)를 쓰면 왜 강건해지는지도 이 표에서 보입니다 — 이상치의 큰 잔차(y−F)를 그대로 좇는 대신 방향(±1)만 반영하기 때문입니다.

증명γₘ은 어떻게 정해지는가 — line search 유도

hₘ이 정해졌으면, "이 방향으로 얼마나 갈지"(γₘ)를 정해야 합니다. 기준은 하나 — 그 단계에서 손실을 가장 많이 줄이는 γ:

γₘ = argmin_γ Σᵢ L(yᵢ, Fₘ₋₁(xᵢ) + γ·hₘ(xᵢ))

제곱오차의 경우 직접 풀 수 있습니다. J(γ) = Σ½(rᵢ − γhₘ(xᵢ))² 로 두고 (rᵢ = yᵢ−Fₘ₋₁(xᵢ)), γ로 미분해서 0으로 놓으면:

dJ/dγ = −Σ hₘ(xᵢ)(rᵢ − γhₘ(xᵢ)) = 0   →   γₘ = Σrᵢhₘ(xᵢ) / Σhₘ(xᵢ)²

형태를 자세히 보면 — 이것은 "잔차 r을 종속변수, hₘ(x)를 설명변수로 놓고 절편 없이 돌린 단순 회귀의 기울기 공식"과 정확히 같습니다 (Week1의 β̂ = Σxy/Σx²). 즉 매 단계마다 "새 트리의 출력을 몇 배로 반영해야 잔차에 가장 잘 맞는가"를 최소제곱으로 푸는 것입니다.

실무의 learning rate와의 관계 — 실제 라이브러리(XGBoost 등)에서는 이렇게 구한 최적 보정폭에 ν(learning_rate, 보통 0.01~0.3)를 곱해 일부러 덜 반영합니다: Fₘ = Fₘ₋₁ + ν·γₘhₘ. 매 단계 최적으로 가면 학습 데이터의 잔차(노이즈 포함)를 너무 정확히 좇아 과적합되기 때문에, "일부러 덜 가는 대신 여러 걸음"이 일반화에 유리합니다 — shrinkage라고 부릅니다. 앞서 토론 질문 "γ를 작게 주면 왜 m을 늘려야 하나"의 답이 여기 있습니다.
계산 예시숫자로 한 사이클 돌려보기 — 데이터 3건, 2단계

y = (10, 20, 30)인 3건으로 Gradient Boosting(제곱오차, ν=1)을 손으로 돌려봅니다.

단계예측 F잔차 r = y − F비고
F₀ (초기값) (20, 20, 20) (−10, 0, +10) F₀는 전체 평균 ȳ=20 — 제곱오차에서 상수 하나로 손실을 최소화하는 값이 평균이기 때문
h₁ 학습 잔차 (−10, 0, +10)을 타깃으로 트리 학습 → 예: h₁ = (−10, +5, +5) 깊이 1 트리(stump)라 두 그룹으로밖에 못 나눠 잔차를 완벽히 못 맞춤
F₁ = F₀ + h₁ (10, 25, 25) (0, −5, +5) 잔차의 크기가 (10,0,10)→(0,5,5)로 감소 — 손실 100→25
h₂ 학습 남은 잔차 (0, −5, +5)를 타깃으로 다음 트리 학습 → ... 이 과정을 m번 반복 — 매번 "남은 오차"만 좇음

여기서 Boosting의 성격이 그대로 보입니다 — 각 트리는 y를 맞추는 게 아니라 "직전까지 못 맞춘 부분"만 맞춥니다. 그래서 첫 트리를 빼고는 어떤 트리도 단독으로는 의미가 없고(잔차를 예측하는 함수일 뿐), 반드시 순서대로 누적되어야 F가 완성됩니다. Bagging의 트리들이 각자 완결된 예측기인 것과 대비되는 지점입니다.
