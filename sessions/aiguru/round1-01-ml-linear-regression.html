수집(01) — 가장 근본적인 단계 수정됨

어떤 데이터를 가져올지 자체가 의사결정의 시작입니다. 변수 선택이 잘못되면 이후 모든 단계가 의미 없어집니다.

수집에서 자주 생기는 문제 세 가지:
· 0이 진짜 0인지, 수집 실패인지 구분 불가 — 수집 시점에 메타데이터가 없으면 나중에 절대 알 수 없음
· 소스가 다르면 정렬 기준 불일치 — 센서 A는 1초, 센서 B는 5초 단위로 찍히면 어떤 시점 기준으로 붙이냐에 따라 데이터가 달라짐
· 어떤 데이터를 가져올지 자체가 도메인 지식 — ML 지식보다 공정 지식이 필요한 결정

전처리(02) — 수집 문제를 수습하는 단계

전처리에서 문제가 많이 발생하는 건 맞지만, 그 원인은 대부분 수집 단계에서 이미 만들어집니다. 전처리는 수집의 결과를 수습하는 단계에 가깝습니다.

평가(05) — 기준을 잘못 잡으면 잘못된 모델을 자신있게 배포

불균형 데이터에서 Accuracy만 보면 전부 다수 클래스로 예측해도 95%가 나옵니다. 평가 기준이 잘못되면 좋은 모델인지 나쁜 모델인지 판단 자체가 틀립니다.

핵심 용어 정의 — 먼저 맞춰두기
용어정확한 의미자주 쓰는 애매한 표현
학습 (training) 모델이 데이터의 X→y 패턴을 수치(계수)로 요약하는 과정. 정답(y)이 있는 데이터로 진행 "AI가 공부한다" — 맞지만 불명확
미학습 데이터 (unseen data) 모델이 학습에 전혀 사용하지 않은 데이터. 모델 입장에서 처음 보는 입력값 "새 데이터" — 새로 수집한 데이터로 오해될 수 있음
훈련 데이터 (train set) 모델 학습에 사용한 데이터. 이 데이터로 계수를 계산 "학습 데이터" — 동의어로 써도 무방
테스트 데이터 (test set) 학습에 사용하지 않고 성능 평가에만 쓰는 데이터. 학습 전에 따로 분리해둠 "검증 데이터" — 엄밀히는 validation과 다름
예측값 (ŷ, y-hat) 모델이 X를 입력받아 출력하는 숫자. 정답(y)과 비교해서 성능을 측정 "결과값" — 어떤 결과인지 불명확
잔차 (residual) 실제값(y) − 예측값(ŷ). 모델이 얼마나, 어떻게 틀렸는지를 나타내는 수치 "오차" — error와 혼용되지만 잔차가 더 구체적
토론 질문 1
"보통 어느 단계에서 문제가 가장 많이 생긴다고 생각하세요? 그리고 왜 그럴까요?"
01 선형 회귀 15 min
X가 증가하면 y가 얼마나 변하는지, 그 관계를 직선 하나로 요약하는 모델
선형이다 = X가 1 증가할 때 y의 변화량이 항상 일정하다 수정됨
선형의 정확한 의미

X가 1에서 2가 될 때 y가 10 증가하고, X가 50에서 51이 될 때도 똑같이 10 증가하면 선형입니다. X가 어느 구간에 있든 변화량이 일정해야 합니다.

비선형은 구간마다 변화량이 다른 것입니다. 온도가 10→20도일 때 반응속도가 2 증가하고, 60→70도일 때 15 증가한다면 비선형입니다.

계수는 전체 데이터를 한꺼번에 사용해서 산출합니다. 구간별로 분리해서 계수를 만들지 않습니다. 그래서 계수가 유효한 X의 범위는 모델이 알려주지 않고, 사용자가 데이터 범위와 잔차 플롯을 보고 직접 판단해야 합니다.

잘 맞는 경우

X와 y 관계가 실제로 선형에 가까울 때. 변수가 적고 해석이 중요할 때

잘 안 맞는 경우

비선형 관계 (곡선, 역U자)
이상치가 많을 때 — 이상치 하나가 회귀선 전체를 자기 쪽으로 당겨버림
변수 간 상호작용이 강할 때

선형 회귀를 쓰는 이유

계수가 의미를 가짐 — "X가 1 증가하면 y가 β만큼 변한다"고 설명 가능. 해석이 필요한 상황에서 강점

토론 질문 2
"이런 모델은 어떤 상황에서 잘 안 맞을까요? 실무에서 접한 데이터 중 떠오르는 게 있나요?"
02 Coefficient (계수) 해석 10 min
기울기 (coefficient)
β
X가 1 단위 증가할 때 y의 평균 변화량
양수 = 같이 증가 / 음수 = 반대 방향
절편 (intercept)
α
X = 0일 때 y의 시작값
실무적 의미가 없는 경우도 많음
계수 해석 시 주의사항
  • ✕
    계수 크기 ≠ 변수 중요도
    나이(0~100) vs 연봉(0~100,000,000) — 단위 차이로 계수 크기가 달라짐. 단위가 다른 변수끼리 계수를 직접 비교하면 안 됨
  • ✕
    R²가 낮으면 계수도 신뢰 불가
    계수 값이 나왔어도 R²가 낮으면 그 숫자 자체를 믿기 어려움
  • !
    다중회귀에서는 "다른 변수를 고정한 상태"로 읽어야
    "X가 1 증가하면 y가 β 변한다" → 정확히는 "나머지 변수가 동일할 때" 조건이 붙음
다중회귀 — 부호 반전 예시 (나이 + 경력 → 연봉) 수정됨
상황나이 계수경력 계수이유
나이만 투입 +250만 — 나이↑ → 연봉↑ (경력 효과까지 흡수해서 양수)
경력만 투입 — +320만 경력↑ → 연봉↑ (정상적인 양의 관계)
둘 다 투입 −80만 ← 반전 +410만 나이·경력 r=0.88 → 나이 몫이 경력에 넘어감
부호 반전은 다중공선성의 결과 중 하나

다중공선성의 정의: 한 변수를 다른 변수로 설명할 수 있는 상태 (나이를 알면 경력을 거의 예측 가능)
부호 반전은 다중공선성이 있을 때 나타날 수 있는 현상 중 하나입니다. 항상 일어나는 건 아닙니다.

다중공선성이 있을 때 나타나는 현상들:
· 계수가 불안정해짐 — 데이터를 조금만 바꿔도 계수가 크게 흔들림
· 부호가 반전될 수 있음
· R²는 높아도 개별 계수를 신뢰할 수 없음

잘못된 해석 vs 올바른 독법

✕ "나이가 많으면 연봉이 낮다"
✓ "경력이 동일한 사람들 사이에서, 나이만 1살 많으면 연봉이 −80만" — 단, 이 계수 자체를 신뢰하기 어려운 상태

진단 방법: 변수 하나 제거 후 다시 돌렸을 때 다른 변수 계수가 크게 바뀌면 다중공선성 신호. 변수 간 상관관계 |r| > 0.8 이상 쌍 확인

03 과적합 / 일반화 15 min
훈련 성능 (train)
↑ 높음
학습 데이터를 외운 상태
테스트 성능 (test)
↓ 낮음
새 데이터엔 맞지 않음
과적합 = 학습 데이터의 노이즈까지 외워버린 상태. 모델이 복잡해질수록 훈련 성능은 오르지만 테스트 성능은 어느 순간부터 떨어짐
과적합 vs 공정 변화 — 구분이 중요 추가됨

둘 다 "train에서 학습한 패턴이 새 데이터에서 안 맞는다"는 현상은 동일합니다. 그런데 원인이 다르고 대응도 완전히 달라집니다.

과적합: 패턴 자체는 유효한데 모델이 노이즈까지 외움 → 데이터를 더 모으거나 모델을 단순하게
공정 변화: 패턴 자체가 바뀜 → 새로운 조건으로 데이터를 다시 수집하고 모델을 다시 학습

구분 방법: "공정에 실제 변화가 있었는가?" — 설비 교체, 원자재 변경, 계절 변화 등 이벤트가 있었으면 공정 변화. 아무것도 바뀐 게 없는데 성능이 떨어지면 과적합을 먼저 의심

데이터를 늘리면 과적합이 해결되는가
  • ✓
    부분적으로 맞음
    데이터가 많아지면 노이즈들이 서로 상쇄되고 진짜 패턴만 남음
  • ✕
    편향된 방식으로 수집되면 의미 없음
    정상 공정 데이터만 10만 건 있어도 불량 조건 데이터가 없으면 불량 예측 불가
  • ✕
    모델 자체가 너무 복잡하면 한계 있음
    이 경우는 데이터보다 모델 복잡도를 줄이는 게 맞음

"왜 이런 현상이 생긴다고 생각하세요? 학습 데이터를 늘리면 해결될까요?"
04 선형 회귀가 작동하는 조건 15 min
잔차 = 실제값 − 예측값. 잔차를 보는 목적은 "얼마나 틀렸냐"가 아니라 "어떻게 틀렸냐"를 보는 것
1 선형성 — X와 y 사이에 직선 관계가 있어야 자주 위반
직관
나이와 생산성이 역U자 곡선인데 모델은 직선으로만 맞추려 함.
→ 중간 구간은 과대예측, 양 끝은 과소예측.
→ 잔차에 U자 패턴이 생김
진단
산점도(X vs y) 눈으로 확인.
잔차 플롯에서 U자·곡선 패턴 여부
대응
변수 변환 (log, sqrt) 시도.
또는 트리 계열 모델로 전환 — 가장 현실적
2 잔차 독립성 — 앞의 오차가 뒤의 오차에 영향을 주면 안 됨

랜덤 vs 패턴 — 의미가 다름

랜덤하게 흩어짐 = 모델이 잡을 수 있는 패턴은 다 잡았고, 남은 건 예측 불가능한 노이즈. 더 이상 개선할 구조적 패턴이 없음

패턴이 있음 (U자, 나팔형 등) = 모델이 아직 잡지 못한 구조가 남아있음. 개선 가능하다는 신호.

U자 패턴이 보이면 나쁜 게 아니라 "아직 할 일이 남아있다"는 신호입니다. 뭘 놓쳤는지 방향이 생긴 거고, 그걸 찾아서 개선하면 됩니다.

정상 — 랜덤하게 흩어짐
더 개선할 구조적 패턴 없음. 모델이 할 수 있는 건 다 함
U자 → 선형성 위반 — 개선 가능
아직 잡지 못한 구조 있음. 변수 변환 또는 트리 모델 전환 검토
나팔 모양 → 등분산성 위반
특정 구간 오차 큼. RMSE 하나로 평가하면 이 문제가 가려짐
추세선 → 잔차 독립성 위반
시계열 데이터에서 오차가 연쇄되는 패턴. 시계열 모델로 전환 필요
토론 질문 4
"잔차 플롯을 봤더니 U자 패턴이 나왔습니다. 이 모델 결과를 그대로 보고해도 될까요?"
05 다중공선성 10 min
정의: 입력 변수(X)들 사이에 강한 상관관계가 있어, 한 변수를 다른 변수로 거의 예측할 수 있는 상태 — 나이를 알면 경력을 거의 예측할 수 있을 때 수정됨
왜 문제가 되는가 — 두 가지 관점
① 계수 해석이 망가진다

"나이가 올라서 y가 변한 건지, 경력이 같이 올라서 그런 건지" 모델이 구분하지 못합니다.

결과적으로 계수를 어디에 배분할지 불안정해지고, 데이터를 조금만 바꿔도 계수 값이 크게 흔들립니다. 같은 데이터로 돌려도 변수 하나 추가하면 다른 변수 계수가 완전히 바뀔 수 있습니다.

② R²가 멀쩡해 보여서 모른다

다중공선성은 예측 정확도 자체를 크게 망치지 않습니다. R²가 0.9가 나와도 계수는 틀려져 있을 수 있습니다.

잔차 플롯도 깨끗하게 보일 수 있습니다. 수치로는 발견되지 않아서 넘어가기 쉬운 문제입니다.

언제 특히 문제가 되는가

예측만 하면 되는 경우 → 다중공선성이 있어도 예측 정확도는 괜찮을 수 있음. 문제 없이 쓸 수도 있음

계수를 해석해야 하는 경우 → 치명적. "어떤 변수가 y에 영향을 주는가", "X를 1 올리면 y가 얼마나 변하는가"를 말해야 한다면 계수 자체를 신뢰할 수 없게 됨

실무 예시: "공정 온도를 1도 올리면 불량률이 얼마나 바뀌는가?" — 온도와 압력이 함께 움직이는 공정이라면 각각의 계수를 따로 해석할 수 없음

계수 변화 예시 — 나이 + 경력 → 연봉
상황나이 계수경력 계수설명
나이만 투입 +250만 — 경력 효과까지 흡수해서 양수로 나옴
경력만 투입 — +320만 정상적인 양의 관계
둘 다 투입 −80만 ← 부호 반전 +410만 나이·경력 r=0.88 → 나이 몫이 경력에 전가됨
부호 반전은 다중공선성의 결과 중 하나일 뿐, 항상 일어나는 건 아닙니다. 계수가 반전되지 않아도 값이 불안정하게 흔들리고 있을 수 있습니다.
진단 방법 — VIF (분산팽창지수)
VIF란?

VIF (Variance Inflation Factor) = 다중공선성의 정도를 수치로 나타내는 지표.
계산 원리: "이 변수를 나머지 변수들로 회귀분석했을 때 R²가 얼마나 높은가" — R²가 높을수록 이 변수는 다른 변수들로 설명 가능하다는 뜻이므로 VIF가 커짐

VIF = 1 / (1 − R²), R²가 0.9이면 VIF = 10, R²가 0.95이면 VIF = 20

지표질문단위강점주의점
RMSE 평균적으로 얼마나 틀리나? y와 동일 (만원, kg 등) 큰 오차에 민감 — 이상치 탐지에 유리 y 규모에 따라 해석이 달라짐. 500만원 오차가 크냐 작냐는 y 범위를 봐야 판단 가능
R² 모델이 y 분산을 얼마나 설명하나? 없음 (0~1, 음수 가능) 스케일 무관하게 비교 가능 0.9가 항상 좋은 건 아님. 도메인·목적에 따라 기준이 다름
MAPE 평균적으로 몇 % 틀리나? % (비율) 직관적. "평균 8% 오차" — 고객에게 설명하기 쉬움 실제값이 0에 가까우면 % 자체가 폭발. 0 근처 데이터에서 쓰면 안 됨
sMAPE 대칭적으로 몇 % 틀리나? % (비율) MAPE의 0 문제를 일부 완화. 과대/과소 예측에 대칭적 MAPE보다 덜 직관적. 실제값+예측값이 모두 0이면 여전히 문제
MAPE 계산 방식 — 직관적으로 이해하기
MAPE = Mean Absolute Percentage Error

각 데이터 포인트마다 "실제값 대비 오차가 몇 %인지" 계산하고 평균을 냄

예시: 실제 연봉 5,000만원 → 예측 4,600만원 → 오차 400만 → 8%
실제 연봉 3,000만원 → 예측 2,850만원 → 오차 150만 → 5%
→ MAPE = (8% + 5%) / 2 = 6.5%

해석: "이 모델은 평균적으로 실제값의 6.5%만큼 틀린다"

RMSE와 차이: RMSE는 오차 절대값(만원)이라 y 규모 모르면 좋은지 나쁜지 판단 어려움. MAPE는 % 오차라 규모 무관하게 바로 해석 가능

MAPE를 쓰면 안 되는 상황

실제값(y)이 0이거나 0에 가까운 경우: 0으로 나누기 문제 또는 % 오차가 수천 %로 폭등

예시: 실제 불량 수 = 0, 예측 = 0.5 → 오차 0.5 / 0 → 계산 불가
실제 재고 = 1개, 예측 = 3개 → 오차 2 / 1 = 200% → 숫자 자체는 맞아도 지표가 왜곡

이런 경우: RMSE나 MAE(절대 오차 평균)를 먼저 쓰고, 필요하면 sMAPE 검토

상황별 지표 선택 기준
  • ✓
    고객·경영진에게 설명해야 할 때 → MAPE
    "평균 8% 오차"가 "RMSE 420만원"보다 훨씬 직관적. 단, y가 0에 가깝지 않은 경우만
  • ✓
    큰 오차가 특히 치명적인 경우 → RMSE
    RMSE는 큰 오차를 제곱해서 더 크게 반영. 1건의 대형 오류가 결정적으로 위험한 경우에 적합
  • ✓
    모델 간 비교, 설명력 확인 → R²
    스케일 무관하게 비교 가능. 단독으로 쓰지 말고 RMSE 또는 MAPE와 함께 볼 것
  • !
    지표 하나만 보는 건 항상 위험
    R² 높고 RMSE도 낮은데 MAPE가 이상하면 → 특정 구간(y가 작은 구간)에서 예측이 나쁠 수 있음
R² 0.92가 나왔을 때 확인해야 할 것들 수정됨
  • ✕
    데이터 누수(leakage)는 없는가?
    미래 정보가 학습에 포함됐다면 R²가 높을 수 있음. R²가 0.99, 1.0에 가까울수록 오히려 먼저 의심해야 함
  • ✕
    train R²와 test R² 차이가 크지 않은가?
    train 0.92, test 0.45라면 과적합. test R²가 중요
  • ✕
    잔차 플롯에 패턴이 없는가?
    U자나 나팔 모양이 있으면 특정 구간에서 체계적으로 틀리고 있는 것
  • ✕
    학습 데이터와 실제 적용 환경의 분포가 비슷한가?
    공정이 바뀌었거나 다른 라인에 적용한다면 분포가 달라질 수 있음
  • !
    R² 하나보다 MAPE 같은 지표를 함께 보는 게 좋음
    MAPE는 "평균적으로 몇 % 틀리는지"를 보여줌. 고객 입장에서 R²보다 직관적. 단, 실제값이 0에 가까우면 MAPE도 왜곡됨

07 R² 완전 정리 참고
R² = "평균으로 예측하는 것보다 얼마나 나은가" — 0이면 평균과 동일, 1이면 완벽, 음수면 평균보다도 못한 예측 수정됨
R²는 0~1 사이가 아닙니다 — 음수가 나올 수 있음

R²가 음수 = 모델이 "그냥 평균으로 예측하는 것"보다도 못하다는 신호. 이 모델은 사용하면 안 됩니다.
계산 오류가 아닙니다. train/test 분포 차이, 잘못된 변수 선택, 스케일링 누락 등이 원인입니다.

R² 1에 가까울수록 좋다? — 오히려 의심해야 수정됨

R²가 0.99, 1.0에 가깝게 나오면 먼저 세 가지를 확인하세요.

· 데이터 누수: 예측 대상이 학습 데이터에 직접 포함된 경우. 미래를 알고 맞추는 거라 당연히 높음
· 타깃 변수가 변수로 들어간 경우: y를 예측하는데 y와 거의 동일한 변수가 X로 들어간 경우
· train/test가 섞인 경우: 같은 데이터로 학습하고 평가하면 당연히 높음
