00 Review — Week 2 trees & ensembles 10 min
Week 2 summary

Trees divide data space along axis-parallel lines and store averages of information within each node as their predictions.
What is averaged depends on the model and task.
DT / RF regression → mean y within a node. Classification → class proportions (probabilities).
XGBoost → mean residual (error) within a node, with regularization.

This enables nonlinear predictions, but also limits extreme-value prediction and allows one outlier to pull the leaf average.

Ensembles (RF, XGBoost) address single-tree instability, with a trade-off in interpretability.
Model selection is not just about R²: what matters is prediction in business-critical ranges.

Averaging node information — limitations

Tree models average information from observations reaching a leaf to produce predictions.
What is averaged depends on the model.
DT / RF → mean y within the node
XGBoost → mean residual (error) within the node, with regularization

Shared limitations: no prediction beyond the training y range; one outlier can pull the mean; one average poorly represents a wide within-node range.

→ The same question arises in clustering: how valid is representing observations as “one cluster”?

Training R² alone is uninformative

A tree’s training R² automatically rises with deeper splits.
Its gap from test R² matters for actual performance.

→ Likewise, a high silhouette score does not establish meaningful clusters.

Model selection = contextual judgment

“XGBoost is better” is not a valid claim without context.
It depends on explanation needs, dataset size, noise, and the importance of extreme values.

→ Clustering algorithm selection also has no universal formula; judge by data properties and purpose.

What Week 2 taught us: “The model found something” is different from “that finding is meaningful.” This principle is especially important in this week’s clustering discussion.

01 What is clustering? — grouping without target labels 8 min
Clustering means grouping similar observations without target labels (y). This is the fundamental difference from supervised learning.
AspectSupervised learning (Weeks 1–2)Clustering (this week)
Target (y) Available — yield, defect status, etc. Unavailable; the “correct” clusters are not known in advance.
Evaluation Actual versus predicted values (RMSE, R²) Cluster cohesion / separation (silhouette) — indirect measures only
What counts as “good”? Small prediction errors Numbers alone are insufficient — domain validation is essential.
Output Numerical or class predictions A cluster label (hard) or membership probabilities (soft) for each observation
A fundamental premise — recognize it before you begin

K-means always divides the supplied data into K groups; it does not decline to split them.
In contrast, DBSCAN leaves noise observations outside all clusters, while hierarchical clustering has no fixed cluster count until the hierarchy is cut.

Algorithms differ, but one principle is shared: “Divided into groups” and “divided into meaningful groups” are very different claims.

Numerical measures such as silhouette scores describe mathematical separation.
Domain knowledge is needed to validate whether the groups mean anything in practice.

Clustering is not limited to continuous variables

What clustering requires is not necessarily coordinates, but a definition of how similar two observations are.
Once similarity is defined, unstructured data such as text, images, and graphs can also be clustered.

Continuous variables → Use Euclidean or Manhattan distances with K-means, DBSCAN, or hierarchical clustering.

Mixed categorical variables
One-hot encoding followed by Euclidean distance can be inappropriate: categorical distances are always 0 or √2, distorting the distance structure.
Gower distance → calculates continuous, categorical, and ordinal distances according to their types, then combines them. A standard option for mixed data.
K-modes → for categorical data; uses modes instead of centroids and defines distance as the number of mismatches.
K-prototypes → handles continuous and categorical data together by combining K-means and K-modes.

Unstructured data (text, images, graphs)
Text → embeddings followed by cosine similarity
Images → CNN embeddings followed by distance calculation
Graphs → similarity based on node connectivity

In these cases, use algorithms that operate on a pairwise similarity matrix.
Rather than a coordinate space as in K-means, they need pairwise relationships: “How similar are A and B?”
Hierarchical clustering and DBSCAN support this approach. K-means needs coordinates to calculate centroids.

Hard versus soft — how membership works
Hard clustering — one cluster only

Each assigned observation belongs to only one cluster.
This assumes clear boundaries.

A customer is either in the “high-spending” or “low-spending” cluster.

K-means, DBSCAN, Hierarchical

Soft clustering — probabilistic membership

Each observation can belong to several clusters with different probabilities.
This represents ambiguous boundary cases more realistically.

A customer may be “70% high-spending, 30% medium-spending.”

GMM (Gaussian Mixture Model)

Three uses of clustering
① Exploration and understanding

Discover natural groups in the data.
Customer segments or process patterns.

Goal: Understand what the data look like; the result need not be used directly for prediction.

② Preprocessing for anomaly detection

Define normal patterns as clusters and detect observations belonging to none as anomalies.

Goal: Identify “unusual relative to normal behavior.” DBSCAN’s noise labels can be used directly for this purpose.

③ Cluster-based hierarchical prediction

First cluster the data, then fit separate predictive models per cluster.
Clustering becomes an intermediate step rather than predicting y directly.

Goal: Useful when models tailored to each cluster outperform one model for all observations.

③ Cluster-based prediction — why and how
One global model versus separate cluster models — when should you split?

A single linear regression or XGBoost model tries to explain all patterns in one model.
But when the data contain fundamentally different mechanisms, one model may struggle to fit both well.

Example: mixed observations from line A (high-temperature operation) and line B (low-temperature operation) in the same factory.
If their defect mechanisms differ, one model may fit both only moderately well.

→ First separate line A / line B by clustering, then use separate models to fit their respective patterns.

Pipeline
Step 1 Clustering Divide all observations into clusters (K-means, etc.).
→
Step 2 Assign cluster labels Tag every observation with a cluster label.
→
Step 3 Cluster-specific models Cluster 1 → model A; cluster 2 → model B; cluster 3 → model C
→
Final Tailored predictions Predict y according to each cluster’s characteristics.
When it works well

· Process data mix different operating modes.
· Customer segments have very different purchasing patterns that one recommender cannot capture.
· A global model has repeated systematic residual errors in a particular range.
· Domain knowledge confirms that two groups follow different mechanisms.

Cautions

· Poor initial clustering undermines all subsequent prediction models; cluster quality affects the whole pipeline.
· New observations must first be assigned to a cluster, and that assignment can itself be wrong.
· More clusters leave fewer observations per cluster, potentially destabilizing individual models.
· Another option is to add cluster membership as a feature, rather than fit separate models.

02 Hard clustering — three algorithms 20 min
Algorithms define “similar” differently. Those differences determine which data they handle well.
① K-means — group around the nearest center
K-means CENTROID-BASED
Principle
Initialize K centroids, assign each observation to the nearest one, and update centroids to the cluster means. Repeat until assignments stabilize.
Strengths
Fast and easy to implement; scales to large datasets; centers provide intuitive summaries of cluster characteristics.
Weaknesses
Requires K in advance; best suited to spherical clusters; one outlier can pull a centroid; scaling is essential.
Key caution
Initial centroids affect the result, so repeated runs on the same data may differ. Use n_init for multiple starts and select the best result.
Limitations specific to K-means — not to every algorithm

These are not limitations of all clustering methods. They are structural limitations of K-means..
DBSCAN and hierarchical clustering do not share many of these issues.

· Spherical clusters only — cannot properly capture ring or crescent shapes.
· Different cluster sizes or densities → large clusters may be split or small ones absorbed.
· One outlier can pull a centroid; K-means has no explicit noise class.
· Unscaled data → variables with larger units dominate distances.
· K must be set in advance — problematic when the number of groups is unknown.

Choosing K — limitations of the elbow method

Increase K from 1 and observe how within-cluster sum of squares (WCSS) decreases.
Choose the “elbow” where the improvement slows sharply.

In practice, the elbow is often unclear.
The curve may simply decrease smoothly, making K=3 versus K=5 difficult to distinguish numerically.
“The elbow seems to be here” inevitably involves subjective judgment.

Even if the elbow suggests K=5, that may be unhelpful if you cannot name two of the five clusters.
Conversely, if operations have three meaningful states — warm-up, normal, and high load — K=3 may be more useful than the elbow’s K=5.

A practical criterion is: “Can each cluster be described in one sentence?”

Choosing K by silhouette — another trap

You can compare silhouette scores across K values instead of using an elbow.

Problem: silhouette is structurally favorable to K-means-like clusters.
As a distance-based metric, it tends to favor the spherical clusters K-means produces.
This evaluates K-means clusters with a K-means-friendly measure.

Elbow and silhouette often suggest different K values.
Neither guarantees that a particular K is correct.

② DBSCAN — cluster dense regions
DBSCAN DENSITY-BASED
Principle
A region is dense when at least MinPts neighbors occur within radius ε. Connect dense regions into clusters and label observations outside them as noise.
Strengths
No advance K; supports nonspherical clusters; does not force outliers into clusters, making it useful for anomaly detection.
Weaknesses
Choosing ε and MinPts is difficult; mixed cluster densities are challenging; distances become less informative in high dimensions.
Key strength
Explicitly labels outliers as noise. Unclustered observations can themselves become the analysis target, useful in process anomaly detection.
③ Hierarchical clustering — build a hierarchy by merging
Hierarchical Clustering LINKAGE-BASED
Principle
Start with one cluster per observation, then repeatedly merge the closest pair. Represent the result as a dendrogram.
Strengths
No advance K; choose K later from the dendrogram; reveals relationships between clusters.
Weaknesses
Slow and memory-intensive for large datasets; merges cannot be undone; results depend on linkage (single / complete / average).
Reading a dendrogram
Vertical axis = distance at merging. A higher cut produces fewer, larger clusters. Long vertical branches signal substantially different groups, suggesting a natural cut and K.
Linkage — how is distance between clusters defined?

Hierarchical clustering repeatedly merges the closest clusters. Once clusters contain multiple points, “distance from cluster A to B” is ambiguous.
Linkage resolves that ambiguity. The chosen definition can substantially change the result.

Single linkage (minimum distance)
Use the distance between the closest pair of points in the two clusters.
→ Tends to form chains: one close pair can merge otherwise different groups.
An outlier can bridge unrelated clusters, causing the “chaining” problem.

Complete linkage (maximum distance)
Use the distance between the farthest pair of points in the two clusters.
→ All points must remain relatively close for merging; favors small, compact clusters.
Sensitive to outliers: one extreme point can prevent a merge.

Average linkage (mean distance)
Average distances over all cross-cluster point pairs; lies between single and complete linkage.
→ Often a practical choice, reducing both single-linkage chaining and complete-linkage sensitivity to outliers.

Ward Linkage
Choose the pair whose merge causes the smallest increase in total within-cluster variance.
→ Tends toward similarly sized clusters; commonly used alongside average linkage.
Ward is the sklearn default.

Different linkage methods can produce completely different clusters on the same data. Always report the linkage alongside the results.

03 Soft Clustering — GMM 10 min
GMM = Gaussian Mixture Model. Assume the data come from a mixture of Gaussian distributions and calculate membership probabilities for each.
What does “each cluster follows a Gaussian distribution” mean?

Observations within a cluster spread around its center in a bell shape.
Observations are most common near the center and become rarer farther away. Their spread has a defined elliptical shape.

GMM learns three parameters for each cluster.

Mean (μ) — where the cluster is centered; serves the role of a K-means centroid.
Variance (σ²) — how widely the cluster spreads: its “size.”
Covariance (Σ) — the direction in which it stretches: the ellipse’s orientation and shape.

These parameters let you calculate how likely an observation is under a distribution.
They determine membership probabilities such as 70% and 30%.

Difference from K-means: K-means uses only the mean (μ), without modeling cluster size or orientation.
It therefore implicitly treats clusters as equally sized spheres.
GMM allows each cluster to have a different size and orientation, accommodating elliptical clusters.

If the assumption is wrong: If the actual data form a U shape or sharply angled boundaries rather than a bell shape,
GMM forces Gaussian ellipses onto them, distorting the result.

What GMM does

K-means forces assignment to the nearest centroid.
GMM calculates the likelihood of belonging to each distribution.

It reports results such as “70% probability of cluster A, 30% of cluster B.”

K-means can be viewed as a special case of GMM with equally sized spherical clusters.

K-means versus GMM — the key difference

K-means: distance only → circular partitions without learning cluster size or orientation.

GMM: learns means, variances, and orientations (covariance) → supports elliptical clusters.

Boundary observations: K-means forces one assignment; GMM expresses uncertainty through probabilities.

ObservationK-means (Hard)GMM (Soft)Interpretation
Observation A Cluster 1 Cluster 1: 92%; cluster 2: 8% Little difference — clear membership
Observation B Cluster 2 (forced) Cluster 1: 51%; cluster 2: 49% Hard assignment is definitive; soft assignment expresses proximity to a boundary.
GMM limitations

If clusters are not Gaussian, results can be distorted.
K must still be chosen in advance; BIC and AIC can help, but judgment remains necessary.
Probabilities can be difficult to communicate: how would you explain “51% versus 49%” to management?

04 Similarity & dissimilarity — the fundamentals 20 min
Distinguish similarity, metric distance, and loss functions
Concepts — understand their relationships

Similarity ↔ dissimilarity
Opposite directions, but essentially the same information.
Similarity: larger = more alike / Dissimilarity: larger = more different.
To use cosine similarity in clustering, transform it to dissimilarity using 1 − cosine.

Dissimilarity ⊃ metric distance
Dissimilarity numerically expresses how different observations are, without requiring metric axioms.
A metric is a special dissimilarity satisfying four additional conditions.
  ① Nonnegativity: d(A,B) ≥ 0
  ② Identity: d(A,A) = 0
  ③ Symmetry: d(A,B) = d(B,A)
  ④ Triangle inequality: d(A,C) ≤ d(A,B) + d(B,C)
Euclidean and Manhattan distances satisfy all four: they are metrics.
1 − cosine may violate the triangle inequality: it is a dissimilarity, but not a metric.

Relationship summary
Similarity ↔ dissimilarity (same information, opposite directions)
Dissimilarity ⊃ metric distance — metrics add conditions to dissimilarities.

Algorithms have different requirements
K-means needs Euclidean coordinates to calculate centroids. Using a nonmetric dissimilarity removes the usual convergence guarantee.
DBSCAN and hierarchical clustering can operate on pairwise dissimilarity matrices, without requiring metric conditions. This allows cosine- or Pearson-based dissimilarities.

A loss function is a different concept
It defines what a model minimizes during training.
It may borrow a distance-based design, as MSE uses a squared-Euclidean form, but that does not make every loss function a distance.

Why study similarity? — its connection to AI models
The definition of “similar” determines model behavior

A loss function is not itself a similarity. But designing one requires a numerical definition of difference, where distance and similarity concepts can enter.

This explains why K-means favors spherical clusters.
Its objective (WCSS) is a sum of squared Euclidean distances. Defining “similar” as “Euclidean-near” makes minimizing WCSS favor spherical clusters.
An objective based on cosine distance would produce different cluster shapes.

Choosing similarity is more than setting a parameter. It defines what “similar” means, affecting the model’s overall behavior.

ModelObjective / loss functionDistance / similarity involvedMeaning
Linear regression MSE (loss function) Uses a squared-Euclidean form Measures actual–predicted differences like coordinate distances
K-means WCSS (objective) Sum of squared Euclidean distances — a metric-based form This definition favors spherical clusters
Text embeddings Cosine-distance-based loss Cosine similarity — not a metric Learns similarly directed vectors for semantically similar sentences
Recommender systems Pearson- or cosine-based Pearson / cosine — not metrics Preference similarity informs recommendations; it is not necessarily the loss function.
Before reading a formula, first ask: “What does this formula actually measure?”
And more importantly: “What does each element — each number — in the data mean?”
The same formula measures very different things when elements have different meanings. Look for this distinction in each similarity card.
Similarity versus dissimilarity — opposite directions

Dissimilarity (distance): Larger means more different; 0 means identical.
Similarity: Larger means more similar; the maximum means identical.

Clustering algorithms use distances or dissimilarities internally. To use cosine similarity, transform it to 1 − cosine before passing it to the algorithm.

📏
Euclidean distance — dissimilarity
Essence: “the straight-line distance between two points”
How far apart two points are in coordinate space: the Pythagorean theorem extended to multiple dimensions.
Formula
d(A,B) = √( Σ (aᵢ − bᵢ)² )
aᵢ − bᵢ = difference between the ith values of two observations
Square (²) = removes the sign and gives large differences more weight
√ = returns squared units to the original units
Range: 0 to ∞ (smaller = more similar)
Why the meaning of each element matters
This formula examines differences in numerical magnitude for each element.

Temperature (°C) → a 10-degree versus 50-degree difference affects distance; that is meaningful.

Word counts → documents A (100 words) and B (10 words) may discuss the same topic, but absolute count differences make them look different. Document length dominates distance, which is not the intended comparison.

→ Euclidean distance is useful when numerical magnitude itself matters
When it fits well
Sensor measurements (temperature, pressure, flow): magnitude differences are meaningful. Scaled numerical data.
When it fits poorly
Text or purchase patterns, where direction matters more than magnitude. Unscaled mixed data.
Scaling effects — scatterplots of 1,000 samples
Explore why clustering needs scaling and how MinMax scaling differs from standardization. It is normal for all three scatterplots to have the same shape — MinMax and standardization apply a monotonic linear transformation to each feature, preserving order and relative spacing. What changes is not the shape, but the scale of the axes. Turn on the outlier toggle to see why the scale matters.
When to use MinMax

When a specified range matters — for models whose inputs need to be within 0–1, such as some neural-network input setups.

Image inputs are scaled to 0–1 because of activation behavior.
With a large input such as 255, sigmoid outputs approach 1 and gradients approach 0 — vanishing gradients.
ReLU outputs 255 for input 255, allowing values to grow through successive layers — exploding gradients.
Scaling to 0–1 keeps activations in a useful gradient range and stabilizes training.

ImageNet-based models additionally standardize each channel by its mean and standard deviation after scaling to 0–1.
They combine two steps: MinMax sets the range, then standardization centers the distribution.

MinMax is safest when outliers have been ruled out. One outlier can set the endpoints, compressing normal observations into a narrow range.

When to use standardization

When no exact range is required — commonly in clustering, linear regression, and PCA.

With outliers, it can be more stable than MinMax.

Manufacturing data often contain outliers and do not require a 0–1 range, making standardization a usual starting choice.

MinMax and standardization give features different relative contributions

MinMax divides by the range (max − min); standardization divides by the standard deviation.
Even on the same data, they give each feature a different influence.

Example: temperature (range 40, std 8) and pressure (range 6, std 0.3).
After MinMax, std → temperature 0.20, pressure 0.05: temperature contributes 4 times as much.
After standardization, std → temperature 1.0, pressure 1.0: equal contributions.

The scaling method changes which features dominate distances and, therefore, cluster assignments.
If domain knowledge says a feature should influence clustering more strongly, its resulting weight can inform the scaling choice.

Neither method is universally correct. Cluster with both and compare the resulting groups.

🏙️
Manhattan distance — dissimilarity
Essence: “distance traveled along a street grid”
Total movement along horizontal and vertical directions, without diagonal shortcuts. It gives large differences (outliers) less emphasis than a squared-distance formulation.
Formula
d(A,B) = Σ |aᵢ − bᵢ|
|aᵢ − bᵢ| = absolute differences, summed without squaring
Same element structure as Euclidean distance, but a different aggregation
Without squaring, large differences receive less emphasis
Range: 0 to ∞ (smaller = more similar)
How does it differ from Euclidean distance?
Example: A = [1, 1], B = [1, 10]
Euclidean: √(0² + 9²) = 9
Manhattan: |0| + |9| = 9 — equal in this two-dimensional example

Example: A = [1, 1], B = [4, 5]
Euclidean: √(9 + 16) = 5
Manhattan: 3 + 4 = 7 — different

Squaring gives dimensions with large differences greater influence in Euclidean distance.
An extreme value in one dimension can dominate Euclidean distance. Manhattan reflects it linearly, making it comparatively more stable.
When it fits well
Numerical data with outliers; high-dimensional data where Euclidean distances become less distinguishable; situations where dimensions should contribute more evenly.
When it fits poorly
Distance measures based on magnitude are unsuitable when direction or pattern matters more.
🧭
Cosine similarity — similarity
Essence: “how small is the angle between two vectors?”
It is called cosine because it calculates the cosine of the angle (θ) between two vectors.
Smaller angles (more aligned directions) give cos(θ) closer to 1. At 90° it is 0; at 180° it is −1.
It ignores magnitude and compares direction.
Formula
cos(A,B) = ( Σ aᵢbᵢ ) / ( ||A|| × ||B|| )
Σ aᵢbᵢ = dot product: multiply corresponding elements and sum; aligned vectors have a larger value

||A|| = norm of A: its length, √(a₁² + a₂² + ... + aₙ²)
Equal to the Euclidean distance from the origin to A.

Dividing by ||A|| × ||B|| normalizes each vector’s length to 1.
This removes magnitude and leaves direction.

Range: −1 to 1 (aligned: 1; orthogonal: 0; opposite: −1)
Why the meaning of each element matters
If elements represent word counts:
Document A contains “machine learning” 10 times; document B contains it once.
Counts differ tenfold, but if all word proportions match, cosine similarity = 1.
Their vector directions match, even though their norms differ.
“They discuss the same topic” → the intended result.

If elements represent Purchase counts:
VIP customer A: electronics 50 times, clothing 30 times
Regular customer B: electronics 5 times, clothing 3 times
Their vector angles match → cosine similarity = 1.
Useful when purchasing direction matters more than volume (norm).
When it fits well
Text analysis (comparing TF-IDF vectors); recommendations (purchasing direction); cases where direction matters more than scale.
When it fits poorly
When magnitude itself matters: 10°C and 100°C have the same direction but different meanings. Unsuitable when absolute amounts matter.
📈
Pearson correlation — similarity
Essence: “do the vectors point in the same direction after subtracting their means?”
Its formula has the same structure as cosine similarity, with one difference:
subtract each vector’s mean before calculating cosine.
Mean centering removes individual baselines (offsets); the remaining directional comparison is the same as cosine.
Formula — compare with cosine
Cosine: Σ aᵢbᵢ / (||A|| × ||B||)
Pearson: Σ (aᵢ−ā)(bᵢ−b̄) / (||A−ā|| × ||B−b̄||)
The structures are identical.
Pearson replaces aᵢ with (aᵢ−ā)— the mean-centered value.
Subtracting means aligns each vector’s baseline to 0.
The next step is the same as cosine: compare directions.
Range: −1 to 1 (closer to 1 = aligned directions)
Exactly how does it differ from cosine?
Cosine: Compares direction relative to the origin (0)
Pearson: Compares direction relative to each vector’s mean

“Same direction of change” is imprecise.
More precisely, “the same direction of deviations from the mean.”.

Example: user A rates every movie 4–5, while user B rates every movie 1–2.
Both rate the same movies above or below their own averages.

Cosine: absolute ratings → “different.”
Pearson: mean-centered deviations → “similar preferences.”

Use cosine when zero is meaningful; Pearson when individual baselines differ.
A zero word count means the word is absent — meaningful information, so use cosine.
Different personal rating baselines or sensor offsets → Pearson.
When it fits well
Different baselines (means), as with ratings or sensor offsets; patterns of deviations matter more than absolute values.
When it fits poorly
When zero has a meaningful interpretation that mean centering removes, or when many elements are zero and sparse structure makes centering undesirable.
🏷️
Jaccard similarity — similarity
Essence: “what share of everything present is shared?”
If elements represent Binary (0 or 1: absent / present) set data. It compares overlap, rather than magnitude.
Formula
J(A,B) = |A ∩ B| / |A ∪ B|
|A ∩ B| = number of elements that are 1 in both sets (intersection)
|A ∪ B| = number of elements that are 1 in either set (union)
Shared zeros do not count as matches
Range: 0 to 1 (closer to 1 = more similar)
The key difference from Pearson
Pearson is suited to numerical values whose magnitudes are meaningful.
Jaccard is suited to binary presence / absence elements.

Jaccard is strong on sparse data with many zeros.
Not buying the same 999 out of 1,000 products does not mean two people share preferences. Pearson can reflect these shared zeros, whereas Jaccard restricts the denominator to products purchased by at least one person.

On sparse binary data, Pearson’s mean becomes the purchase proportion (0–1), with small deviations that can make results unstable.
When it fits well
Binary purchase, click, or tag indicators; sparse data, such as buying only a few of thousands of products.
When it fits poorly
Not for continuous magnitudes such as temperature, pressure, or purchase amounts.
Jaccard versus Pearson — calculate with 100 samples
Use Jaccard for binary purchase indicators and Pearson for continuous sensor values. In the comparison tab, apply both measures to the same binary data and inspect how the results differ.

05 Which similarity or distance should you use? 10 min
One question guides the choice: “What does ‘similar’ mean in this context?”
Once that is clear, the formula follows. Rules such as “text means cosine; numbers mean Euclidean” are risky.
The criterion is not the data type, but what the elements mean.
Thinking through situations — examples
Time series from process sensors A, B, and C: “Group sensors that move similarly.”
“Move similarly” means rising and falling together.
Sensors may have different baselines or offsets (A around 100, B around 10).
Coordinated deviations matter more than absolute differences.
→ Pearson
Remove magnitude and baseline differences; compare the direction of deviations.
Purchase counts by category per customer: “Group customers with similar purchasing patterns.”
VIP and regular customers have very different purchasing volumes, but may favor the same categories.
The question is where they spend, rather than absolute purchase volume.
Cosine is sufficient when individual baseline purchasing tendencies do not need further centering.
→ Cosine similarity
Remove purchasing volume differences; compare purchasing directions.
Process parameters (temperature, pressure, flow): “Group numerically similar conditions,” with outliers present.
Numerical magnitude represents operating conditions, so absolute differences matter.
Outliers may receive excessive weight with squared-Euclidean calculations.
Scaling is essential either way because temperature, pressure, and flow use different units.
→ Manhattan distance
Compares magnitude differences with less emphasis on extremes. Euclidean is also reasonable for clean data without outliers.
Review texts (TF-IDF vectors): “Group reviews with similar topics.”
Review lengths vary, creating large differences in absolute word counts.
Reviews on the same topic can still have similar word proportions (directions).
Remove length (magnitude), then compare topic (direction).
→ Cosine similarity
A standard text choice that automatically adjusts for document length differences.
A common mistake — accepting the default

Euclidean distance is the default in many sklearn algorithms and other libraries.
Without deliberate thought, you may use it everywhere.

For text, Euclidean distance can let document length dominate similarity.
For ratings, cosine does not remove different personal rating baselines.

Always ask first: “What does each element in these data mean?”

06 Interpreting clusters — “Are these meaningful groups?” 12 min
Silhouette measures mathematical separation. Whether clusters are meaningful in practice is a separate question.
Silhouette score — interpretation and limitations
What is a silhouette score?

For each observation:
a = average distance to other observations in its cluster (smaller = more cohesive)
b = average distance to the nearest other cluster (larger = better separated)
Silhouette = (b − a) / max(a, b)

Range: −1 to 1. Near 1 means good separation; 0 suggests a boundary; negative values suggest possible misassignment.

Structural limitations — why not trust silhouette alone?

① It favors K-means-like clusters.
Silhouette is distance-based and tends to score spherical, convex K-means clusters highly.
Creating clusters with K-means, then declaring success using a K-means-friendly metric, is circular.
Complex DBSCAN cluster shapes may have low silhouette scores despite useful separation.

② Elbow and silhouette often suggest different K values.
Elbow: a bend at K=3. Silhouette: maximum at K=4. Neither provides a universal reason to prefer one.
Neither guarantees the correct K; they identify candidates.

③ A high score can still conflict with operational reality.
Mathematical separation and operational meaning differ.
A silhouette of 0.75 with three clusters all representing “normal operation” may look good numerically but be unhelpful.

④ A low score can still describe meaningful clusters.
Ambiguous boundaries are common in real data and naturally lower silhouette scores.
A score of 0.3 does not necessarily mean the clusters are wrong.

Use silhouette for relative comparisons between candidate K values, not as an absolute standard.

How to check whether clusters are meaningful
  • ✓
    Summarize each cluster’s characteristics numerically and give it a name
    Cluster 1: high mean temperature and low pressure → “high-temperature, low-pressure cluster.” A descriptive name helps establish practical meaning.
  • ✓
    Cross-check defect rates and outcomes by cluster
    Are defects concentrated in cluster 3? Without a relationship to y, clustering may not help prediction.
  • ✓
    Can a domain expert explain the cluster?
    Numerically strong clusters that make no operational sense are difficult to trust.
  • !
    Are clusters stable over time?
    If next month’s data produce very different clusters with the same algorithm, distinguish process change from model instability.
  • ✕
    Do not attach meaning to cluster numbers
    Cluster 1 is not “better” than cluster 2. Labels are arbitrary; inspect the actual characteristics.

The message throughout this session

Clustering does not provide a “correct answer”; it partitions data.
People, rather than the algorithm, must judge whether the partition is meaningful.

The same applies to similarity selection. Defining “similar” starts with what each element means, rather than choosing a formula first.

When reporting results:
❌ “Cluster 1 is the dangerous cluster.”
✅ “We found higher defect rates under high-temperature, high-pressure, low-flow conditions, which could inform monitoring criteria.”

08 Manufacturing & clustering — practical cautions 15 min
Manufacturing data are time-dependent, high-dimensional, and error-prone. These properties require more than simply running a clustering algorithm.
Problems caused by temporal structure
Ordinary clustering treats observations individually

Temperature, pressure, and flow at time t form one point, which is assigned to a cluster.
In manufacturing, a single moment may not provide enough context.
A continuous temperature rise over 30 minutes may matter more than the current reading of 85°C.

Without temporal context, clustering groups a rising 85°C reading with a stable 85°C reading.

There are two ways to address this.

One is windowing. Instead of a single moment, use an interval such as the past 10 minutes as the unit. Vectors of window means, standard deviations, and maxima work with existing algorithms. Window length strongly affects results, and an anomaly crossing a window boundary can be split into partial patterns.

The other is a time-series-specific distance. DTW (Dynamic Time Warping) treats similarly shaped but time-shifted patterns as alike. An anomaly occurring at 10:00 on one day and 10:20 on another can be grouped as the same pattern. Euclidean comparisons require aligned times; DTW adjusts the time axis. Its high computational cost can be slow on large datasets.

Problems caused by erroneous observations
Clustering cannot recognize measurement errors as errors

Suppose a sensor briefly malfunctions, records 200°C, then returns to normal.
Clustering cannot distinguish that from a real process anomaly; it is simply another observation.

With enough repeated errors, clustering can form a cluster around that pattern.
An investigation of “what state cluster 2 represents” may ultimately reveal a sensor-error pattern.

K-means has no explicit noise class, so erroneous observations pull its centroids.
DBSCAN can label sparse errors as noise, but repeated similar errors can still become a cluster.

One step is essential before clustering:
preprocess sensor errors (missing values, out-of-range readings, stuck values) separately from actual process anomalies.
Without that distinction, clusters may reflect data quality rather than process patterns.

Problems caused by high sensor counts
Including all 200 sensors can make distances less informative

Euclidean distances become less distinct in high dimensions. With more variables, distances between points tend to become similar; the nearest and farthest points differ less, weakening clustering.

Nor are all 200 sensors independent. Coolant and pipe temperatures may move together, duplicating their influence on clustering.

A practical approach has two stages.

First, cluster the sensors. Group similarly moving sensors and select a representative or one per group. Pearson is appropriate because units differ (100°C versus 5 bar), while co-movement matters more than magnitude. Euclidean comparisons can let large absolute values dominate, obscuring synchronized sensors.

Then, with the reduced features, cluster process patterns.

When should manufacturing use clustering?
Define the situation first, then choose an appropriate method, rather than starting with an algorithm.
  • ✓
    Mixed operating modes — separate the modes first
    Warm-up, normal, and high-load modes can act as noise in one prediction model. Separate modes by clustering, then use mode-specific models or control criteria. If the number of modes is unknown, first inspect a hierarchical dendrogram.
  • ✓
    Unusual process patterns — anomaly detection
    Build clusters from normal observations, then flag new observations that match none. DBSCAN’s noise classification can help, but measurement errors must first be removed or they may be detected as anomalies.
  • ✓
    Reduce sensor count — feature reduction
    Group sensors that move similarly and select representatives. Pearson plus hierarchical clustering is appropriate, simplifying subsequent analyses.
  • !
    Running clustering immediately to find defect causes
    Without error preprocessing, mode separation, and feature reduction, clusters may reflect data quality or operating modes rather than process mechanisms. A clustering result is not a causal explanation for defects.
The order matters

A typical approach to manufacturing clustering follows this sequence.

1. Preprocess sensor errors and missing values — erroneous data distort later steps.
2. Check operating modes — separate them if mixed.
3. Reduce features by grouping sensors — do not blindly use all 200.
4. Choose an algorithm and similarity for the purpose — only now select the algorithm.
5. Validate results — can you name the clusters, and do they make sense to domain experts?

Clustering is step 4. Skipping steps 1–3 makes its results difficult to trust.
