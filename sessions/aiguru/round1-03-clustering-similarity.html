Week 2 세션 요약

트리는 데이터 공간을 축에 평행한 직각선으로 나눠 각 구간에 노드 안 정보의 평균을 예측값으로 저장합니다.
무엇의 평균인지는 모델과 태스크마다 다릅니다.
DT·RF 회귀 → 노드 안 y값들의 평균. 분류 → 노드 안 클래스 비율(확률).
XGBoost → 노드 안 잔차(오차)들의 평균 (정규화 포함).

이 구조가 비선형을 가능하게 하지만, 동시에 Extreme Value를 못 맞추고 이상치 하나가 노드 평균을 끌어당기는 한계를 만듭니다.

앙상블(RF, XGBoost)은 단일 트리의 불안정함을 해결하지만, 해석 가능성을 포기하는 트레이드오프가 생깁니다.
모델 선택의 기준은 R² 하나가 아닙니다 — 비즈니스적으로 중요한 구간에서 어떻게 예측하는가가 핵심입니다.

노드 안 정보의 평균 — 한계

트리 계열은 리프 노드에 도달한 데이터들의 정보를 평균 내어 예측값으로 씁니다.
무엇의 평균인지는 모델마다 다릅니다.
DT·RF → 노드 안 y값들의 평균
XGBoost → 노드 안 잔차(오차)들의 평균 (정규화 포함)

공통 한계: 학습 y 범위를 벗어나는 예측 불가. 이상치 하나가 평균을 끌어당김. 노드 안 값 범위가 크면 평균 하나로 대표 불가.

→ 이번 주 클러스터링도 같은 구조. 군집 내 데이터를 "하나의 군집"으로 대표하는 게 얼마나 타당한지가 핵심 질문

train R²는 아무 의미 없다

트리는 분기를 깊게 할수록 train R²가 자동으로 올라감.
test R²와의 차이가 실제 성능의 기준.

→ 클러스터링에도 똑같이 적용됨. Silhouette score가 높아도 실제 의미 있는 군집인지는 별개 문제

모델 선택 = 맥락 판단

"XGBoost가 더 좋다"는 맥락 없이 틀린 말.
설명 필요성, 데이터 크기, 노이즈 수준, 극단값 중요성에 따라 달라짐.

→ 이번 주 클러스터링 알고리즘 선택도 동일. 공식은 없고, 데이터 성질과 목적으로 판단

Week 2에서 배운 것: "모델이 뭔가를 찾아줬다"와 "그게 의미 있다"는 다르다. 이번 주 클러스터링에서 이 원칙이 가장 중요하게 등장합니다.

클러스터링의 핵심 전제 — 먼저 인식하고 시작

K-means는 어떤 데이터를 줘도 반드시 K개로 나눠줍니다. 나눠지지 않는 법이 없습니다.
하지만 DBSCAN은 noise로 분류된 데이터는 어느 군집에도 안 들어가고, Hierarchical은 자르기 전까지 군집 수가 정해지지 않습니다.

알고리즘마다 다르지만 공통적인 것은 — "나눠졌다"와 "의미 있게 나눠졌다"는 완전히 다른 이야기입니다.

Silhouette score 등 수치 지표는 "수학적으로 잘 나뉘었는가"만 말해줍니다.
그 군집이 실제로 의미 있는지는 도메인 지식으로 검증해야 합니다.

클러스터링은 연속형 변수만 쓰는 게 아닙니다

클러스터링에 필요한 건 좌표가 아니라 "두 데이터가 얼마나 비슷한가"를 정의할 수 있는 것입니다.
유사도만 정의할 수 있으면 텍스트, 이미지, 그래프 같은 비정형 데이터도 클러스터링이 가능합니다.

연속형 → 유클리드·맨해튼 거리로 직접 K-means, DBSCAN, Hierarchical 적용

범주형이 섞였을 때
원핫인코딩 후 유클리드 → 잘못된 선택. 범주 간 거리가 항상 0 또는 √2만 나와서 거리 구조 왜곡
Gower Distance → 연속형·범주형·순서형을 타입에 맞게 각각 다르게 거리 계산 후 합산. 혼합 데이터의 표준 선택
K-modes → 범주형 전용. 센트로이드 대신 최빈값(mode)을 중심으로, 거리를 "불일치 개수"로 정의
K-prototypes → 연속형 + 범주형 동시 처리. K-means + K-modes 결합

비정형 데이터 (텍스트, 이미지, 그래프)
텍스트 → 임베딩 벡터로 변환 후 코사인 유사도
이미지 → CNN 임베딩 후 거리 계산
그래프 → 노드 간 연결 구조로 유사도 정의

이 경우 유사도 행렬(pairwise similarity matrix)만 있으면 작동하는 알고리즘을 씁니다.
K-means처럼 좌표 공간이 필요한 게 아니라, "A와 B가 얼마나 비슷한가"라는 쌍별 관계만 있으면 됩니다.
Hierarchical, DBSCAN이 여기에 해당합니다. K-means는 센트로이드를 계산해야 하므로 좌표가 필요합니다.

Hard vs Soft — 소속 방식의 차이
Hard Clustering — 하나에만 속한다

각 데이터는 반드시 하나의 군집에만 배정됩니다.
경계가 명확하다는 전제가 깔려 있습니다.

이 고객은 "고가 구매 군집"이거나 "저가 구매 군집"이거나, 둘 중 하나.

K-means, DBSCAN, Hierarchical

Soft Clustering — 확률로 속한다

각 데이터가 여러 군집에 확률로 소속됩니다.
경계가 모호한 데이터를 더 현실적으로 표현합니다.

이 고객은 "고가 군집 70%, 중가 군집 30%".

GMM (Gaussian Mixture Model)

클러스터링의 활용 방식 — 세 가지
① 탐색·이해

데이터 안에 어떤 자연스러운 그룹이 있는지 파악.
고객 세그먼트, 공정 패턴 분류.

목적: "데이터가 어떻게 생겼는가" 이해. 결과가 직접 예측에 쓰이지 않아도 됨

② 이상 탐지 전처리

정상 패턴을 군집으로 정의하고, 어디에도 속하지 않는 데이터를 이상으로 탐지.

목적: "이 데이터는 평소와 다르다"는 판단. DBSCAN의 noise 분류가 여기에 직접 활용됨

③ 군집 기반 계층 예측

군집으로 먼저 나누고 → 군집별로 별도 예측 모델 적용.
y를 바로 예측하는 게 아니라, 중간 단계로 군집이 들어감.

목적: 전체 데이터에 하나의 모델보다 군집별 특성에 맞는 모델이 더 유효할 때

③ 군집 기반 계층 예측 — 왜, 어떻게
전체 모델 하나 vs 군집별 모델 분리 — 언제 나누는 게 나은가

전체 데이터에 하나의 선형 회귀나 XGBoost를 쓰면, 모델은 모든 패턴을 하나의 수식으로 설명하려 합니다.
그런데 데이터 안에 근본적으로 다른 메커니즘이 섞여 있을 때, 하나의 모델이 양쪽을 동시에 잘 맞추기 어렵습니다.

예: 동일 공장의 설비 A 라인(고온 공정)과 설비 B 라인(저온 공정)이 섞인 데이터.
두 라인의 불량 메커니즘이 다르다면, 하나의 모델로 둘 다 잡으려 하면 둘 다 어중간하게 맞출 수 있습니다.

→ 먼저 클러스터링으로 라인 A / 라인 B를 분리하고, 각각 별도 모델을 적용하면 각 패턴에 더 잘 맞는 예측이 가능합니다.

파이프라인 구조
1단계 클러스터링 전체 데이터를 군집으로 나눔 (K-means 등)
→
2단계 군집 레이블 부여 각 데이터에 군집 번호 태깅
→
3단계 군집별 예측 모델 군집 1 → 모델 A, 군집 2 → 모델 B, 군집 3 → 모델 C
→
최종 세부 예측 각 군집 특성에 맞게 y 예측
효과적인 경우

· 서로 다른 운전 조건(모드)이 섞인 공정 데이터
· 고객 세그먼트별로 구매 패턴이 완전히 달라서 하나의 추천 모델이 모두를 못 잡을 때
· 전체 모델의 잔차를 봤을 때 특정 구간에서 체계적 오차가 반복될 때
· 도메인 지식으로 "이 두 그룹은 다른 메커니즘"이 확인될 때

주의점

· 1단계 군집이 잘못되면 2단계 예측 모델 전체가 잘못됨 — 클러스터링 품질이 파이프라인 전체를 좌우
· 새 데이터가 들어왔을 때 먼저 어느 군집인지 분류해야 함 → 군집 분류 자체도 오류 가능성 있음
· 군집 수가 많아질수록 각 군집 데이터가 적어져 개별 모델 학습이 불안정해질 수 있음
· 단순히 군집을 변수(feature)로 추가하는 방법도 있음 — 분리 모델 대신 군집 번호를 x로 넣기

알고리즘마다 "비슷하다"를 정의하는 방식이 다릅니다. 그 차이가 어떤 데이터에서 잘 작동하는지를 결정합니다
① K-means — 가장 가까운 중심으로 모이기
K-means CENTROID-BASED
원리
K개 중심(센트로이드)을 임의로 잡고, 각 데이터를 가장 가까운 센트로이드에 배정. 센트로이드를 군집 평균으로 업데이트. 변화 없을 때까지 반복
강점
빠르고 구현 쉬움. 대용량에서도 동작. 결과 해석이 직관적 (군집 중심값으로 특성 요약 가능)
약점
K를 미리 정해야 함. 구형(원형) 군집만 잘 잡음. 이상치 하나가 센트로이드를 끌어당김. 스케일링 필수
핵심 주의
초기 센트로이드 위치가 결과에 영향 줌 — 같은 데이터를 돌릴 때마다 결과가 조금씩 달라질 수 있음 (n_init 파라미터로 여러 번 돌리고 최선 선택)
K-means 고유의 한계 — 다른 알고리즘은 해당 없음

아래는 클러스터링 전체의 한계가 아닙니다. K-means라는 알고리즘의 구조적 한계입니다.
DBSCAN이나 Hierarchical은 이 문제들 중 상당수를 갖지 않습니다.

· 구형(원형) 군집만 잡음 — 도넛형·초승달형은 원천적으로 못 잡음
· 군집 크기·밀도가 다를 때 → 큰 군집을 억지로 쪼개거나 작은 군집을 흡수
· 이상치 하나가 센트로이드를 끌어당김 — K-means에는 noise 개념이 없음
· 스케일링 안 된 데이터 → 큰 단위 변수가 거리를 지배
· K를 반드시 미리 정해야 함 — 데이터가 몇 개로 나뉘는지 모를 때 문제

K 선택 — Elbow Method의 한계

K를 1부터 늘려가며 군집 내 분산(WCSS) 감소폭을 관찰.
감소폭이 꺾이는 "팔꿈치" 지점을 K로 선택하는 방법.

실무에서 Elbow는 대부분 잘 안 꺾입니다.
완만하게 내려가기만 해서 K=3인지 K=5인지 수치로 판단이 안 되는 경우가 태반.
"팔꿈치가 여기인 것 같다"는 주관적 판단이 들어갈 수밖에 없습니다.

Elbow가 K=5를 가리켜도, 5개 군집 중 2개에 이름을 못 붙이면 의미가 없습니다.
반대로 Elbow가 K=5인데 현장에서 "공정 상태는 워밍업·정상·고부하 3가지"라고 말할 수 있으면 K=3이 더 유효합니다.

"각 군집을 한 줄로 설명할 수 있는가"가 K 선택의 실질적 기준입니다.

Silhouette로 K 고르기 — 또 다른 함정

Elbow 대신 K별 Silhouette score를 비교해서 K를 고르기도 합니다.

문제: Silhouette 자체가 K-means에 구조적으로 유리합니다.
Silhouette는 거리 기반 지표 → K-means가 만든 구형 군집에서 당연히 높게 나옴.
K-means로 군집을 만들고 K-means 친화적인 지표로 평가하는 꼴.

Elbow와 Silhouette가 서로 다른 K를 가리킬 때도 많습니다.
둘 다 "이 K가 맞다"는 보장은 없습니다.

② DBSCAN — 밀도가 높은 곳을 군집으로
DBSCAN DENSITY-BASED
원리
반경 ε 안에 최소 MinPts개 이웃이 있으면 "밀집 지역"으로 판단. 밀집 지역끼리 연결해 군집 형성. 밀집 지역 밖 데이터는 이상치(noise)로 분류
강점
K를 미리 안 정해도 됨. 비구형 군집 가능. 이상치를 군집으로 억지로 넣지 않음 → 이상 탐지에 유리
약점
ε, MinPts 파라미터 설정이 어려움. 밀도가 다른 군집이 섞이면 잘 못 잡음. 고차원에서 거리 개념이 희미해짐
핵심 강점
이상치를 명시적으로 noise로 분류해줌 → "군집에 안 들어간 데이터"가 분석 대상이 되기도 함. 공정 이상 탐지에 직접적으로 유용
③ Hierarchical — 합치면서 계층을 만든다
Hierarchical Clustering LINKAGE-BASED
원리
처음엔 각 데이터가 모두 개별 군집. 가장 가까운 군집 둘을 반복적으로 합쳐나감. 결과를 Dendrogram(수형도)으로 표현
강점
K를 미리 정하지 않아도 됨. Dendrogram 보고 사후에 K 결정 가능. 군집 간 계층 관계 파악 가능
약점
데이터 많으면 느리고 메모리 큼. 한 번 합쳐지면 되돌리기 불가. Linkage 방식(single/complete/average)에 따라 결과가 달라짐
Dendrogram 읽기
세로축 = 합쳐질 때의 거리. 높은 곳 절단 → 소수의 큰 군집. 세로 막대가 긴 구간 = 두 군집이 꽤 다르다는 신호. 그 위를 자르는 게 자연스러운 K
Linkage — "두 군집 사이의 거리를 어떻게 정의하는가"

Hierarchical은 가장 가까운 군집 둘을 반복해서 합칩니다. 그런데 군집이 여러 데이터 포인트로 이뤄지면 "군집 A와 군집 B의 거리"를 어떻게 잴지가 애매해집니다.
Linkage는 그 애매함을 해결하는 방식입니다. 무엇을 기준으로 두 군집 사이의 거리를 측정하느냐에 따라 결과가 크게 달라집니다.

Single Linkage (최단 거리)
두 군집에서 가장 가까운 점 한 쌍의 거리를 군집 간 거리로 사용.
→ 사슬처럼 연결되는 경향 있음. 하나만 가까우면 전혀 다른 군집이 합쳐져버림.
이상치 하나가 다리 역할을 해서 엉뚱한 군집이 묶이는 "chaining" 문제 발생.

Complete Linkage (최장 거리)
두 군집에서 가장 먼 점 한 쌍의 거리를 군집 간 거리로 사용.
→ 군집 내 모든 점이 비슷하게 가까워야 합쳐짐. 작고 촘촘한 군집을 선호.
이상치에 민감 — 극단값 하나가 두 군집이 합쳐지는 걸 막을 수 있음.

Average Linkage (평균 거리)
두 군집의 모든 점 쌍의 거리를 평균 내서 사용. 단일·최장 방식의 중간.
→ 실무에서 가장 무난하게 쓰임. Single의 chaining, Complete의 이상치 민감함을 둘 다 줄임.

Ward Linkage
두 군집을 합쳤을 때 전체 분산 증가량이 가장 작은 쌍을 선택.
→ 군집 크기가 균등하게 나오는 경향. 실무에서 Average와 함께 가장 많이 쓰임.
sklearn 기본값이 Ward입니다.

같은 데이터를 Hierarchical로 돌려도 Linkage 방식에 따라 군집이 완전히 달라질 수 있습니다. "어떤 Linkage를 썼는가"를 결과와 함께 항상 명시해야 합니다.

03 Soft Clustering — GMM 10 min
GMM = Gaussian Mixture Model. 데이터가 여러 개의 정규분포(가우시안)가 섞여서 나왔다고 가정하고, 각 분포에 소속될 확률을 계산
"각 군집이 가우시안 분포를 따른다"는 게 무슨 뜻인가

군집 안 데이터가 중심에서 종 모양으로 퍼져 있다는 뜻입니다.
중심에 가까울수록 데이터가 많고, 멀어질수록 점점 드물어집니다. 그 퍼짐이 타원형으로 정해진 모양을 갖습니다.

GMM은 각 군집의 세 가지 파라미터를 학습합니다.

평균(μ) — 군집의 중심이 어디인가. K-means의 센트로이드와 같은 역할.
분산(σ²) — 군집이 얼마나 넓게 퍼져 있는가. 군집의 "크기".
공분산(Σ) — 군집이 어느 방향으로 길쭉한가. 타원의 방향과 모양.

이 세 가지를 알면 "이 데이터가 이 분포에서 나왔을 확률"을 계산할 수 있습니다.
그 확률이 바로 소속 확률(70%, 30%)이 됩니다.

K-means와 차이: K-means는 평균(μ)만 씁니다. 군집의 크기나 방향을 모릅니다.
그래서 K-means는 모든 군집이 같은 크기의 원형이라고 암묵적으로 가정합니다.
GMM은 군집마다 크기와 방향이 다를 수 있어서 타원형 군집도 잡을 수 있습니다.

가정이 틀리면: 실제 데이터가 종 모양이 아니라 U자형이거나 경계가 뾰족하게 꺾이는 형태라면,
GMM이 억지로 타원형 가우시안을 끼워 맞추려 합니다. 결과가 왜곡됩니다.

GMM이 하는 일

K-means는 "가장 가까운 센트로이드로 강제 배정".
GMM은 "어느 분포에서 나왔을 가능성이 얼마나 되는가"를 계산.

결과: "이 데이터는 군집 A 확률 70%, 군집 B 확률 30%"처럼 표현.

K-means가 GMM의 특수한 경우입니다 — 모든 군집이 같은 크기의 구형이라고 가정한 GMM.

K-means vs GMM 핵심 차이

K-means: 거리만 봄 → 군집 크기·방향 무관하게 원형으로만 구분

GMM: 분포의 평균 + 분산 + 방향(공분산)까지 학습 → 타원형 군집도 가능

경계 근처 데이터: K-means는 강제 배정, GMM은 확률로 "경계에 있다"고 표현

데이터K-means (Hard)GMM (Soft)해석 차이
데이터 A 군집 1 군집1: 92%, 군집2: 8% 차이 없음 — 명확하게 속하는 경우
데이터 B 군집 2 (강제) 군집1: 51%, 군집2: 49% Hard는 단정, Soft는 "경계에 있다"고 표현
GMM의 한계

각 군집이 정규분포를 따른다는 가정이 틀리면 결과 왜곡.
K는 여전히 사전에 정해야 함 (BIC, AIC로 선택 가능하지만 판단 여전히 필요).
확률값 해석이 어려움 — "51% vs 49%"를 경영진에게 어떻게 설명할 것인가.

04 유사도 & 비유사도 — 본질부터 20 min
먼저 개념 구분 — 유사도, 거리(metric), 손실함수
개념 구분 — 포함 관계로 이해하기

유사도(similarity) ↔ 비유사도(dissimilarity)
방향만 다릅니다. 본질적으로 같은 정보입니다.
유사도: 클수록 비슷함 / 비유사도: 클수록 다름
코사인 유사도를 클러스터링에 쓰고 싶으면 1-코사인으로 변환해서 비유사도로 바꿔 넣습니다.

비유사도 ⊃ 거리(metric)
비유사도는 "다름의 정도"를 수치로 표현한 것입니다. 수학적 조건이 없습니다.
거리(metric)는 비유사도 중 조건 4개를 추가로 만족하는 특수한 경우입니다.
  ① 비음수: d(A,B) ≥ 0
  ② 동일성: d(A,A) = 0
  ③ 대칭성: d(A,B) = d(B,A)
  ④ 삼각 부등식: d(A,C) ≤ d(A,B) + d(B,C)
유클리드·맨해튼은 네 조건을 모두 만족 → 진짜 metric.
1-코사인은 삼각 부등식이 깨질 수 있음 → 비유사도이지만 metric은 아님.

포함 관계 요약
유사도 ↔ 비유사도 (같은 정보, 반대 방향)
비유사도 ⊃ 거리(metric) — 거리는 조건이 더 붙은 비유사도

알고리즘마다 요구 조건이 다릅니다
K-means: 센트로이드 계산을 위해 metric 공간(유클리드) 필요. metric 아닌 비유사도 넣으면 수렴 보장 안 됨.
DBSCAN·Hierarchical: pairwise 비유사도 행렬만 있으면 작동. metric 조건 불필요. 코사인·Pearson 기반 비유사도를 쓸 수 있는 이유.

손실함수(loss function)는 위 셋과 다른 개념입니다
모델이 무엇을 최소화할지를 정의하는 학습 목적.
설계할 때 거리 개념을 빌려 쓰는 경우가 있을 뿐 — MSE가 유클리드 형태인 것처럼. 손실함수가 거리라는 뜻이 아닙니다.

그럼 왜 유사도를 배우는가 — AI 모델과의 연결 지점
"비슷하다"의 정의가 모델의 동작을 결정합니다

손실함수 자체는 유사도가 아닙니다. 하지만 손실함수를 설계할 때 "얼마나 다른가"를 수치화하는 방법이 필요하고, 거기서 거리·유사도 개념이 쓰입니다.

K-means가 구형 군집만 잡는 이유가 여기에 있습니다.
K-means의 목적함수(WCSS)가 유클리드 거리의 제곱합입니다 — "비슷하다 = 유클리드로 가깝다"로 정의했기 때문에, WCSS를 최소화하면 자연스럽게 구형 군집이 나옵니다.
만약 코사인 거리로 목적함수를 만들었다면 다른 모양의 군집이 나왔을 것입니다.

유사도 선택은 파라미터 설정이 아닙니다. "무엇을 비슷하다고 볼 것인가"를 결정하는 것이고, 그 결정이 모델의 동작 전체에 영향을 줍니다.

모델목적함수 / 손실함수거기서 쓰는 거리·유사도결과적 의미
선형 회귀 MSE (손실함수) 유클리드 거리 제곱합 형태를 빌림 예측값-실제값 차이를 좌표 거리처럼 측정
K-means WCSS (목적함수) 유클리드 거리 제곱합 — metric 이 정의 때문에 구형 군집만 잡힘
텍스트 임베딩 코사인 거리 기반 손실 코사인 유사도 — metric 아님 의미가 비슷한 문장을 같은 방향 벡터로 학습
추천 시스템 Pearson·코사인 기반 Pearson / 코사인 — metric 아님 취향 유사도가 추천의 근거. 손실함수와 직접 같지 않음
수식을 보기 전에 먼저 물어야 할 것: "이 수식은 결국 무엇을 측정하는가?"
그리고 더 중요한 것: "데이터의 element(각 숫자)가 무엇을 의미하는가?"
같은 수식이라도 element가 다르면, 측정하는 것이 완전히 달라집니다. 각 유사도 카드에서 이 차이를 확인하세요.
유사도 vs 비유사도 — 방향이 반대일 뿐

비유사도(거리, Distance): 클수록 다름. 0이면 완전히 같음.
유사도(Similarity): 클수록 비슷함. 최댓값이면 완전히 같음.

클러스터링 알고리즘은 내부적으로 거리(비유사도)를 씁니다. 코사인 유사도를 쓰고 싶으면 1 − 코사인으로 변환해서 넣습니다.

유클리드 거리 (Euclidean Distance) — 비유사도
본질: "두 점 사이의 직선 거리"
좌표 공간에서 두 점이 얼마나 멀리 떨어져 있는가. 피타고라스 정리를 다차원으로 확장한 것.
수식
d(A,B) = √( Σ (aᵢ − bᵢ)² )
aᵢ − bᵢ = 두 데이터의 i번째 값 차이
제곱(²) = 방향 무관하게 양수화 + 큰 차이를 더 강하게 반영
√ = 제곱을 원래 단위로 되돌림
결과: 0 ~ ∞ (작을수록 비슷)
element 의미가 왜 중요한가
이 수식은 각 element의 수치 크기 차이를 봅니다.

element가 온도(°C)면 → 10도 차이와 50도 차이가 거리에 반영됨. 자연스러움.

element가 단어 빈도수면 → 문서 A(100단어)와 문서 B(10단어)가 같은 주제여도, 절대 빈도 차이로 "다른 문서"로 판단. 문서 길이가 거리를 지배해버림. 이건 원하는 게 아님.

→ 수치 크기 자체에 의미가 있을 때만 유클리드가 유효
잘 맞는 경우
센서 측정값 (온도, 압력, 유량) — 크기 차이가 직접 의미. 스케일링 완료된 수치 데이터
잘 안 맞는 경우
텍스트, 구매 패턴 — 절대적 크기보다 방향·패턴이 의미 있는 경우. 스케일링 안 된 혼합 데이터
스케일링 효과 — 1,000개 샘플 산포도
클러스터링 전 스케일링이 왜 필요한지, MinMax와 표준화가 어떻게 다른지 직접 확인하세요. 세 산포도의 분포 모양이 같은 건 정상입니다 — MinMax와 표준화는 모두 단조 변환(각 값에 같은 수식을 적용)이라 데이터 간 상대적 순서와 간격 비율이 유지됩니다. 달라지는 건 분포 모양이 아니라 축의 척도(scale)입니다. 이상치 토글을 켜면 척도 차이가 얼마나 중요한지 바로 보입니다.
MinMax를 쓰는 경우

범위가 반드시 지켜져야 할 때 — 신경망 입력층처럼 0~1 안에 값이 있어야 하는 모델.

이미지에서 0~1로 맞추는 이유는 활성함수 때문입니다.
Sigmoid는 입력이 255처럼 크면 출력이 거의 1로 고정되고 기울기가 0에 가까워집니다 — gradient vanishing.
ReLU는 입력이 255면 출력도 255, 레이어를 거칠수록 값이 폭발합니다 — gradient exploding.
0~1로 맞추면 활성함수가 기울기가 살아있는 구간에서 작동하고 학습이 안정됩니다.

단, ImageNet 기반 모델들은 0~1로 MinMax 후 채널별 평균·std로 표준화를 추가로 적용합니다.
MinMax로 범위를 맞추고, 표준화로 분포 중심을 맞추는 두 단계를 함께 씁니다.

이상치가 없다는 게 확인됐을 때만 안전합니다. 이상치 하나가 0과 1을 결정해버리면 정상 데이터가 좁은 구간에 몰립니다.

표준화를 쓰는 경우

범위가 딱히 중요하지 않을 때 — 클러스터링, 선형 회귀, PCA 대부분의 경우.

이상치가 있을 때 — MinMax보다 안정적입니다.

제조 데이터는 이상치가 많고 범위가 0~1일 필요가 없는 경우가 대부분이라 표준화가 기본 선택입니다.

MinMax와 표준화는 변수별 기여도가 조금씩 다릅니다

MinMax는 범위(max−min)로 나누고, 표준화는 std로 나눕니다.
같은 데이터라도 두 방법이 각 변수에 부여하는 기여도가 달라집니다.

예: 온도(범위 40, std 8)와 압력(범위 6, std 0.3)이 있을 때
MinMax 후 std → 온도 0.20, 압력 0.05 — 온도가 4배 더 기여
표준화 후 std → 온도 1.0, 압력 1.0 — 동등하게 기여

어떤 스케일링을 쓰느냐에 따라 어느 변수가 거리를, 그리고 군집을 더 결정하는지가 달라집니다.
도메인 지식으로 "이 변수가 군집 결정에 더 영향을 줬으면 좋겠다"는 판단이 있다면, 그 변수의 기여도가 높게 나오는 스케일링을 선택하는 근거가 됩니다.

반드시 하나가 정답이 아닙니다. 두 방법으로 각각 클러스터링해보고 결과가 어떻게 달라지는지 확인하는 것도 좋은 접근입니다.

맨해튼 거리 (Manhattan Distance) — 비유사도
본질: "바둑판 도로에서 이동하는 거리"
대각선 지름길 없이, 수직·수평으로만 이동할 때의 총 거리. 유클리드보다 큰 차이(이상치)를 덜 과장한다.
수식
d(A,B) = Σ |aᵢ − bᵢ|
|aᵢ − bᵢ| = 차이의 절댓값 — 제곱 없이 절댓값만 합산
유클리드와 element 구조는 같지만 합산 방식이 다름
제곱을 안 하기 때문에 큰 차이(이상치)를 덜 과장함
결과: 0 ~ ∞ (작을수록 비슷)
유클리드와 무엇이 다른가
예: A = [1, 1], B = [1, 10]
유클리드: √(0² + 9²) = 9
맨해튼: |0| + |9| = 9 — 2차원에서는 같음

예: A = [1, 1], B = [4, 5]
유클리드: √(9 + 16) = 5
맨해튼: 3 + 4 = 7 — 차이 발생

유클리드는 제곱 때문에 큰 차이가 있는 차원을 강하게 반영.
이상치 하나가 특정 차원에서 극단값이면 유클리드 거리가 폭발. 맨해튼은 그걸 선형적으로만 반영해서 더 안정적.
잘 맞는 경우
이상치가 있는 수치 데이터. 고차원 데이터 (유클리드는 고차원에서 거리 구분이 흐릿해짐). 각 차원을 동등하게 보고 싶을 때
잘 안 맞는 경우
크기보다 방향·패턴이 의미 있는 경우에는 거리 계열 자체가 부적합

코사인 유사도 (Cosine Similarity) — 유사도
본질: "두 벡터 사이의 각도가 얼마나 작은가"
이름이 코사인인 이유 — 두 벡터 사이 각도(θ)의 코사인값을 계산하기 때문입니다.
각이 작을수록(방향이 가까울수록) cos(θ)가 1에 가까워집니다. 각이 90°면 0, 180°면 −1.
크기(규모)는 완전히 무시하고 방향만 봅니다.
수식
cos(A,B) = ( Σ aᵢbᵢ ) / ( ||A|| × ||B|| )
Σ aᵢbᵢ = 내적(dot product). 같은 위치 element를 곱해서 합산. 같은 방향일수록 값이 커짐

||A|| = A 벡터의 norm = 벡터의 크기(길이) = √(a₁² + a₂² + ... + aₙ²)
원점에서 점 A까지의 유클리드 거리와 같습니다.

||A|| × ||B||로 나누는 것 = 두 벡터의 크기를 각각 1로 정규화.
크기를 제거하고 방향만 남기는 조작입니다.

결과: −1 ~ 1 (각이 작을수록 1, 직교하면 0, 반대 방향이면 −1)
element 의미가 왜 중요한가
element가 단어 빈도수이면:
문서 A "머신러닝" 10번, 문서 B "머신러닝" 1번
절대 빈도는 10배 차이지만 다른 단어 비율이 같으면 코사인 유사도 = 1
두 벡터의 방향(각도)이 같기 때문. 크기(norm)는 달라도 무방.
"같은 주제를 얘기하고 있다" → 원하는 결과

element가 구매 횟수이면:
VIP 고객 A: 전자제품 50번, 의류 30번
일반 고객 B: 전자제품 5번, 의류 3번
두 벡터의 각도가 같음 → 코사인 유사도 = 1
구매량(norm)보다 구매 방향(각도)을 보고 싶을 때 유효
잘 맞는 경우
텍스트 분석 (TF-IDF 벡터 비교). 추천 시스템 (구매 패턴의 방향 비교). 규모보다 방향·각도가 중요한 경우
잘 안 맞는 경우
수치 크기 자체가 의미 있을 때 — 온도 10°C와 100°C는 각도는 같아도 의미가 다름. 절대량이 중요한 경우

Pearson 상관 유사도 (Pearson Correlation) — 유사도
본질: "평균을 빼고 난 뒤, 같은 방향을 가리키는가"
코사인 유사도와 수식 구조가 완전히 같습니다. 차이는 하나 —
각 데이터에서 평균을 먼저 빼고 코사인을 계산합니다.
평균을 빼면 각자의 기준선(오프셋)이 제거되고, 그 뒤의 방향 비교는 코사인과 동일합니다.
수식 — 코사인과 나란히 비교
코사인: Σ aᵢbᵢ / (||A|| × ||B||)
Pearson: Σ (aᵢ−ā)(bᵢ−b̄) / (||A−ā|| × ||B−b̄||)
구조가 완전히 동일합니다.
Pearson은 aᵢ 대신 (aᵢ−ā)를 씁니다 — 평균을 뺀 값.
평균을 빼면 각자의 기준선이 0으로 맞춰집니다.
그 뒤에 하는 일은 코사인과 같습니다 — 방향 비교.
결과: −1 ~ 1 (1에 가까울수록 같은 방향)
코사인과 정확히 무엇이 다른가
코사인: 원점(0) 기준으로 방향 비교
Pearson: 각자 평균 기준으로 방향 비교

"변화 방향이 같다"는 표현은 엄밀하지 않습니다.
정확하게는 "평균 대비 편차의 방향이 같다"입니다.

예: 사용자 A는 모든 영화에 4~5점, 사용자 B는 모든 영화에 1~2점.
그러나 둘 다 같은 영화에서 자기 평균 대비 높고 낮게 평가.

코사인: 절대 점수 기준 → "다르다"
Pearson: 평균 제거 후 편차 기준 → "같은 취향"

데이터의 "0"이 의미 있으면 코사인, 기준선이 각자 다르면 Pearson.
단어 빈도에서 0은 "그 단어가 없다"는 실제 정보 → 코사인.
사람마다 다른 평점 기준, 센서마다 다른 오프셋 → Pearson.
잘 맞는 경우
기준선(평균)이 각자 다를 때 — 평점 시스템, 센서 오프셋. 절대값보다 평균 대비 편차 패턴이 의미 있는 경우
잘 안 맞는 경우
데이터의 0이 의미 있는 경우 (평균 빼면 0의 의미가 사라짐). element가 희소(0이 많음)한 경우 — 평균이 왜곡됨
🏷️
자카드 유사도 (Jaccard Similarity) — 유사도
본질: "공통으로 가진 것이 전체에서 얼마나 되는가"
element가 0 또는 1 (있다/없다)인 집합 데이터에 씁니다. 크기 개념이 없고 "겹치는가 안 겹치는가"만 봅니다.
수식
J(A,B) = |A ∩ B| / |A ∪ B|
|A ∩ B| = 둘 다 1인 element 수 (공통으로 가진 것)
|A ∪ B| = 둘 중 하나라도 1인 element 수 (합집합)
0을 공통점으로 계산하지 않습니다
결과: 0 ~ 1 (1에 가까울수록 비슷)
피어슨과 결정적으로 다른 점
피어슨은 element가 연속형 수치여야 의미 있습니다.
자카드는 element가 0/1이어야 의미 있습니다.

0이 많은 희소 데이터에서 자카드가 강합니다.
상품 1000개 중 둘 다 999개를 안 샀다고 해서 취향이 같은 게 아닙니다. 피어슨은 이 "둘 다 0"을 공통점으로 반영하지만, 자카드는 분모를 "둘 중 하나라도 산 것"으로 한정해서 이 문제를 피합니다.

이진 데이터에 피어슨을 쓰면 평균이 구매 비율(0~1 사이)이 되고 편차가 매우 작아져 결과가 불안정합니다.
잘 맞는 경우
구매 여부, 클릭 여부, 태그 여부 등 0/1 이진 데이터. 0이 많은 희소 데이터 (상품 수천 개 중 일부만 구매)
잘 안 맞는 경우
연속형 수치 데이터 — 온도, 압력, 구매 금액처럼 크기가 의미 있는 데이터에는 쓸 수 없음
자카드 vs 피어슨 — 100개 샘플로 직접 계산
이진 데이터(구매 여부)에는 자카드, 연속형 데이터(센서값)에는 피어슨. 비교 탭에서 같은 이진 데이터에 두 유사도를 모두 적용하면 결과가 어떻게 달라지는지 확인하세요.
전체 정리 — 본질 비교
수식본질 (한 줄)크기 반영기준선 보정metric 여부값 범위
유클리드 거리 좌표 공간에서 직선 거리 반영 없음 metric 0 ~ ∞
맨해튼 거리 차원별 수치 차이의 합 반영 (덜 과장) 없음 metric 0 ~ ∞
코사인 유사도 원점 기준, 같은 방향인가 무시 (norm으로 나눔) 없음 metric 아님 −1 ~ 1
Pearson 유사도 평균 대비 편차의 방향이 같은가 (= 평균 빼고 코사인) 무시 있음 (평균 제거) metric 아님 −1 ~ 1
자카드 유사도 공통으로 가진 것이 전체에서 얼마나 되는가 해당 없음 (0/1만) 없음 metric 0 ~ 1

그 답이 정해지면 수식은 따라옵니다. "텍스트면 코사인, 수치면 유클리드" 같은 공식은 위험합니다.
데이터 타입이 아니라 element가 무엇을 의미하는지가 선택 기준이기 때문입니다.
상황별 사고 흐름 — 예시로 보기
공정 센서 A, B, C의 시계열 데이터. "비슷하게 움직이는 센서끼리 묶고 싶다"
"비슷하게 움직인다" = 같이 올라가고 같이 내려가는가.
센서마다 측정 기준이나 오프셋이 다를 수 있음 (A는 항상 100 주변, B는 항상 10 주변).
절대값 차이가 아니라 변화 방향의 동조가 의미 있음.
→ Pearson
절대값과 기준선 차이를 모두 제거하고 변화 방향만 비교
고객별 상품 카테고리 구매 횟수. "비슷한 구매 패턴의 고객끼리 묶고 싶다"
VIP와 일반 고객의 구매량은 크게 다르지만, 어떤 카테고리를 주로 사는지 패턴이 같을 수 있음.
절대적 구매량보다 "어느 방향으로 소비하는가"가 관심사.

→ 코사인 유사도
구매량(크기) 차이를 제거하고 구매 방향(패턴)만 비교

리뷰 텍스트 데이터 (TF-IDF 벡터). "주제가 비슷한 리뷰끼리 묶고 싶다"
리뷰 길이가 다양함 — 짧은 리뷰와 긴 리뷰는 단어 빈도 절대값이 크게 다름.
하지만 같은 주제를 얘기하면 단어 비율(방향)은 비슷.
길이(크기)를 제거하고 주제(방향)만 비교하는 게 목적.

06 군집 결과 해석 — "의미 있는 군집인가?" 12 min
수치 지표(Silhouette)는 "수학적으로 잘 나뉘었는가"만 말해줍니다. "실제로 의미 있는가"는 별개입니다
Silhouette Score — 기준과 한계
Silhouette Score란

각 데이터 포인트에 대해:
a = 같은 군집 내 다른 데이터들과의 평균 거리 (작을수록 응집)
b = 가장 가까운 다른 군집 데이터들과의 평균 거리 (클수록 분리)
Silhouette = (b − a) / max(a, b)

① K-means에 구조적으로 유리한 지표입니다.
Silhouette는 거리 기반으로 계산됩니다. K-means가 만든 구형·볼록한 군집에서 당연히 높게 나옵니다.
K-means로 군집을 만들고, K-means 친화적인 지표로 "잘 됐다"고 평가하는 순환 구조입니다.
DBSCAN처럼 복잡한 형태의 군집은 실제로 잘 나뉘어도 Silhouette가 낮게 나올 수 있습니다.

② Elbow와 Silhouette가 다른 K를 가리킬 때가 많습니다.
Elbow: K=3이 꺾임. Silhouette: K=4에서 최대. 어느 걸 믿어야 하는지 기준이 없습니다.
두 지표 모두 "이 K가 맞다"는 보장이 아닙니다. 단지 후보일 뿐입니다.

③ 점수가 높아도 군집이 현실과 안 맞을 수 있습니다.
수학적으로 잘 나뉜 것과, 현장에서 의미 있는 것은 다릅니다.
Silhouette 0.75인데 군집 3개 모두 "정상 공정"인 경우 — 수치는 좋지만 쓸모가 없습니다.

④ 점수가 낮아도 의미 있는 군집일 수 있습니다.
경계가 원래 모호한 데이터(현실에서 흔함)는 Silhouette가 낮게 나오는 게 당연합니다.
0.3이 나왔다고 "군집이 잘못됐다"가 아닐 수 있습니다.

결론: Silhouette는 여러 K 후보 중 상대 비교 참고용입니다. 절대적 기준으로 쓰면 안 됩니다.

08 제조 현장 × 클러스터링 — 실제로 쓸 때 무엇을 주의해야 하는가 15 min
제조 데이터는 시계열이고, 센서가 많고, 오류가 많습니다. 이 조건들이 클러스터링을 그냥 돌리면 안 되는 이유입니다
시계열이라서 생기는 문제
클러스터링은 기본적으로 데이터 포인트 하나하나를 독립적으로 봅니다

시점 t의 온도·압력·유량을 하나의 점으로 보고, 그 점이 어느 군집에 속하는지 결정합니다.
그런데 제조 공정에서 지금 이 시점 하나만 보면 의미가 없는 경우가 많습니다.
온도가 85°C라는 사실보다, 지난 30분 동안 계속 올라가고 있었다는 게 더 중요할 수 있습니다.

그냥 돌리면 클러스터링은 그 맥락을 모릅니다. 올라가는 중인 85°C와 안정적인 85°C를 같은 군집으로 묶어버립니다.

이걸 해결하는 방법은 두 가지입니다.

하나는 윈도우로 자르는 것입니다. "지금 이 시점" 대신 "지난 10분 구간"을 하나의 단위로 만들어서 클러스터링에 넣습니다. 구간의 평균·표준편차·최댓값 같은 통계를 벡터로 만들면 기존 알고리즘을 그대로 쓸 수 있습니다. 단, 윈도우 크기를 얼마로 잡느냐가 결과에 크게 영향을 줍니다. 이상 이벤트가 윈도우 경계에 걸리면 반쪽짜리 패턴이 됩니다.

다른 하나는 시계열 전용 거리를 쓰는 것입니다. DTW(Dynamic Time Warping)는 패턴이 비슷하지만 시간이 약간 어긋난 경우도 유사하다고 봅니다. 같은 공정 이상이 어떤 날은 오전 10시에, 어떤 날은 오전 10시 20분에 나타나도 "같은 패턴"으로 묶을 수 있습니다. 유클리드는 시점이 정확히 맞아야 하지만 DTW는 시간 축을 유연하게 처리합니다. 다만 계산 비용이 높아서 대용량 데이터에서는 느립니다.

오류 데이터가 많아서 생기는 문제
클러스터링은 오류 데이터를 오류라고 모릅니다

센서가 잠깐 오작동해서 온도가 갑자기 200°C로 찍혔다가 돌아왔다고 합시다.
클러스터링은 그게 센서 오류인지 진짜 공정 이상인지 알 수 없습니다. 그냥 데이터로 봅니다.

오류 데이터가 충분히 많으면 클러스터링이 그 패턴을 하나의 군집으로 만들어버립니다.
나중에 "군집 2는 어떤 공정 상태인가"를 분석하다가 결국 센서 오류 패턴이었음을 발견하는 경우가 실제로 많습니다.

K-means는 이상치를 noise로 분류하는 개념 자체가 없기 때문에 오류 데이터가 센트로이드를 끌어당깁니다.
DBSCAN은 밀집되지 않은 오류 데이터를 noise로 분류하는 경향이 있어서 그나마 낫지만, 오류가 반복적으로 비슷하게 나타나면 그것도 하나의 군집으로 묶힐 수 있습니다.

클러스터링을 돌리기 전에 반드시 먼저 해야 할 것이 있습니다.
센서 오류(결측, 범위 이탈, 고착값)와 실제 공정 이상을 구분하는 전처리입니다.
이 구분 없이 바로 클러스터링을 돌리면, 결과가 공정 패턴이 아니라 데이터 품질 패턴을 반영할 수 있습니다.

센서가 많아서 생기는 문제
센서 200개를 그냥 다 넣으면 거리가 의미를 잃습니다

고차원에서 유클리드 거리는 구분이 흐릿해집니다. 변수가 많아질수록 모든 점 사이의 거리가 비슷해지는 경향이 있습니다. "가장 가까운 점"과 "가장 먼 점"의 거리 차이가 작아져서 군집이 잘 안 나뉩니다.

그리고 센서 200개가 다 독립적이지 않습니다. 냉각수 온도와 배관 온도는 같이 올라가고 같이 내려갑니다. 이런 센서들이 군집 결과에 중복으로 영향을 줍니다.

실용적인 접근은 두 단계로 나누는 것입니다.

먼저 센서끼리 클러스터링을 해봅니다. 비슷하게 움직이는 센서를 묶어서 대표 센서를 선정하거나 그룹별로 하나씩만 씁니다. 이때 유사도는 Pearson이 적합합니다. 센서마다 단위가 다르고(온도 100°C, 압력 5 bar), 절대값보다 "함께 움직이는가"가 의미 있기 때문입니다. 유클리드를 쓰면 절대값이 큰 센서가 거리를 지배해서 실제로 동조하는 센서들이 안 묶힙니다.

그 다음 축소된 변수로 공정 패턴 클러스터링을 합니다.

그래서 제조에서 클러스터링을 언제 쓰는가
상황을 먼저 정의하고, 그 상황에 맞는 방법을 고르는 순서입니다. 알고리즘을 먼저 고르는 게 아닙니다
  • ✓
    운전 모드가 섞여 있을 때 — 먼저 모드를 분리하고 싶다
    워밍업·정상·고부하가 섞인 데이터에 예측 모델을 바로 돌리면 모드 차이가 노이즈로 작용합니다. 클러스터링으로 모드를 먼저 분리하고, 모드별로 별도 모델을 쓰거나 다른 관리 기준을 적용합니다. 모드 수를 모른다면 Hierarchical로 Dendrogram을 먼저 확인합니다.
  • ✓
    평소와 다른 공정 패턴을 잡고 싶다 — 이상 탐지
    정상 데이터로 먼저 군집을 만들고, 새 데이터가 어느 군집에도 속하지 않으면 이상으로 탐지합니다. DBSCAN은 noise로 자동 분류해줘서 여기에 직접 활용됩니다. 단, 오류 데이터를 먼저 걸러내지 않으면 오류 패턴이 "이상"으로 잡힙니다.
  • ✓
    센서 수를 줄이고 싶다 — 변수 축소
    비슷하게 움직이는 센서끼리 묶어서 대표 센서를 선정합니다. Pearson + Hierarchical 조합이 적합합니다. 이 작업을 먼저 하면 이후 모든 분석이 훨씬 깔끔해집니다.
  • !
    불량 원인을 찾겠다고 바로 클러스터링을 돌리는 경우
    오류 데이터 전처리, 운전 모드 분리, 변수 축소 없이 바로 돌리면 군집이 공정 패턴이 아니라 데이터 품질 문제나 운전 모드 차이를 반영할 가능성이 높습니다. 군집 결과가 나왔다고 해서 불량 원인이 나온 게 아닙니다.
순서가 중요합니다

제조 데이터에서 클러스터링을 제대로 쓰려면 보통 이 순서로 접근합니다.

1. 센서 오류·결측 전처리 — 오류 데이터가 섞이면 이후 모든 게 왜곡됩니다
2. 운전 모드 확인 — 모드가 섞여 있으면 먼저 분리합니다
3. 센서 그룹핑으로 변수 축소 — 200개를 다 넣지 않습니다
4. 목적에 맞는 알고리즘과 유사도 선택 — 이때야 비로소 알고리즘을 고릅니다
5. 결과가 나왔을 때 — 군집에 이름을 붙일 수 있는지, 도메인에서 말이 되는지 검증합니다

클러스터링은 이 과정의 4번입니다. 1·2·3 없이 4로 바로 가면 결과를 믿기 어렵습니다.
