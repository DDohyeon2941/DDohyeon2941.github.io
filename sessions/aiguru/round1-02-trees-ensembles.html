00 Review of last week 10 min
Week 1 summary

Go beyond a single metric and identify the underlying reason for that result.
Use that understanding to define what AI can solve and explain that scope to practitioners.

R² = 0.92 is not a conclusion. Examine residual patterns, leakage, and the train/test gap before saying, “This model can solve this problem.”

Identify the cause

A U-shaped residual pattern means not simply “the model is bad,” but “a straight line is being used for a nonlinear relationship.” This week, examine how trees address it differently.

Define the problem scope

Overfitting does not simply mean “make a better model.” First distinguish biased data from a changed process; the cause determines what can be solved.

Explain the reasoning

Multicollinearity can destabilize coefficients and reverse their signs, and you need to explain why. The same applies to feature importance this week: explain the context, not just the number.

01 Decision Tree 15 min
Key idea: At each split, a threshold on one variable divides observations into two groups. Repeated rectangular splits partition a 2D space along axis-parallel lines, assigning different predictions to each region. The stepwise result is nonlinear.
Impurity — the criterion for choosing a split
Impurity = “how mixed is this group?” Choose the condition that reduces it most.

A group with 50 defective and 50 normal cases → maximum impurity; neither outcome is certain.
A group with 98 defective and 2 normal cases → impurity near 0; you can say “almost certainly defective.”

A tree tries variables and split points, choosing the condition with the greatest impurity reduction.
Classification → Gini: 0 for a pure group, 0.5 for a half-and-half binary mixture / Regression → MSE: the spread of y values within a node.

Why nonlinear? — partitioning 2D space (temperature × pressure)
Linear regression divides this space along a diagonal line. Trees partition it along axis-parallel lines. Each region gets a different prediction, and predictions change in steps across boundaries. This is why the relationship is nonlinear.
Why more variables can worsen overfitting
Even noisy variables can reduce impurity by chance

More variables increase the chance of finding split conditions that happen to work only on this training set. As these accumulate, training performance rises without generalizing to test data.

MDI normalizes total importance to 1, so adding variables need not greatly change relative rankings. The problem is Overfitting rather than the ranking.

In RandomForest, max_features=1.0 uses all variables, removing random feature selection and making it equivalent to ordinary bagging in this respect. Noisy variables then affect every tree. The sklearn regressor default of 1.0 deserves attention in practice.

Split example ① — classification (defective / normal)
Classification leaf: calculate each class’s proportion among the training observations in that node, then predict the majority class or output those proportions as probabilities.
Split example ② — regression (yield prediction)
Regression leaf: the mean training y value is stored as the prediction. Any unseen observation reaching the “low temperature + high speed” node is predicted as 95.7%, even if its conditions differ slightly.

02 What tree models share — leaf averages 12 min
Key idea: Tree-based models use leaf averages for predictions, but what is averaged differs: Decision Tree and RandomForest average y values; XGBoost averages residuals with regularization. This structure explains difficulty with extreme values and larger errors when values within a node have a wide range.
Store averages during training; return them during prediction

Training: average values of the training observations assigned to each leaf, and store the result.
Prediction: determine which leaf an unseen observation reaches, then return its stored average.

Decision Tree / RandomForest: store the mean y value
XGBoost: store a regularized mean residual for that round (including λ), then sum contributions for the final prediction.

Limitation ① — difficulty predicting extreme values
Cannot extrapolate beyond the training y range

If training y values in a node are [90, 95, 100, 105, 200], its prediction is their mean, 118. Predicting 118 for an actual value of 200 creates an error of 82.
Predictions cannot exceed the maximum or fall below the minimum training y value.

Limitation ② — outliers pull the leaf average upward
Similar X with an extreme y is more problematic

A tree can isolate an outlier if its X values are sufficiently unusual. More often, however, X looks similar to other observations while only y is extreme.

Suppose most observations at 82°C and 3.1 bar have a defect rate of 10–15%, but one has 80%. Similar X conditions give the tree no basis for separating it. The outlier pulls the leaf average up, distorting predictions throughout that leaf.

Limitation ③ — a wide y range within a node increases prediction errors
One average becomes a poor representative

If a leaf contains training y values [5%, 8%, 12%, 60%], it predicts their mean, 21%. The 60% case has a 39-percentage-point error, and the 5% case has a 16-percentage-point error.
Deeper splits make leaves smaller, but introduce a trade-off with more severe overfitting.

Categorical variables — sklearn trees cannot accept them directly
Splits use conditions of the form “variable value > threshold”

Label Encoding: assigns an order to unordered categories, so a comparison such as “operator 2 > operator 1” enters the split. Ten operators create 9 threshold candidates.
One-Hot Encoding: 10 operators become 10 binary variables, each with only one possible threshold, 0.5. Compared with continuous variables with hundreds of thresholds, this worsens the structural bias toward lower MDI.
XGBoost 1.7+: native support is available with enable_categorical=True, but is not the default.

Why SHAP is especially common with trees
TreeSHAP — fast, exact computation for tree models

General SHAP computation grows exponentially with feature combinations and becomes impractical (20 features → 2²⁰ combinations). Other models use approximations.
TreeSHAP exploits the tree’s split structure to calculate exact values in polynomial time. This explains why SHAP is widely used for trees.

03 Tree overfitting — more severe than linear regression 8 min
Key idea: Trees can form as many leaves as observations, making overfitting more severe than in linear regression. Training R² alone is uninformative; examine test R².
Why is it more severe?

Linear regression: one coefficient summarizes a relationship across observations, limiting expressiveness.
Trees: can keep splitting until each observation has its own leaf → training R² = 1.0, while test performance drops sharply.

Memorizing “defective at 82.3°C and 3.11 bar” can produce a completely different prediction at 82.4°C.

train R² vs test R²
High training R² in a tree need not mean “a good model”

Training R² uses training observations. Deeper splits reduce within-node y variance, automatically raising it. One leaf per observation yields 1.0.
Test R² uses observations excluded from training, measuring performance on unseen data.

Training R² = 0.95 and test R² = 0.62 indicate overfitting. A high training R² is unhelpful if test R² is low.
For trees, always examine the train/test R² gap together.

04 Ensembles — RandomForest / AdaBoost / XGBoost 20 min
Key idea: An ensemble combines models to improve on a single model. It need not combine only trees: stacking linear, tree, and neural models is also an ensemble. This section covers tree ensembles: RF (variance reduction) and XGBoost (bias reduction).
① Bagging — RandomForest
Aggregate 100 samples from the same population — noise averages out through the law of large numbers

Ordinary bagging: independently train trees on different bootstrap samples drawn with replacement, then average their outputs to reduce noise.

RandomForest = bagging + random feature selection: At each split, select only some variables (√p). With bagging alone, dominant variables can control every tree, making trees similar and weakening the benefit of averaging. Randomly restricting features makes trees more diverse.

sklearn caution: Classifiers default to max_features="sqrt", but regressors default to max_features=1.0, using all variables and thus behaving like ordinary bagging in feature selection.

OOB (out-of-bag) — evaluate without a separate test set

Bootstrap sampling leaves roughly 37% of observations out of a particular tree on average. These OOB observations provide a natural evaluation set and can also be used for OOB permutation importance.

② Boosting — from AdaBoost to XGBoost
AdaBoost — the original weighting approach

Increase weights for incorrectly predicted observations so their errors contribute more to the next tree’s loss. This raises the cost of getting them wrong.
Limitation: excessive focus on outliers makes it vulnerable to overfitting.

XGBoost — sequential residual correction through cumulative sums

Start with an initial prediction (mean y). In each round, train a tree using the current residuals as its target. X remains unchanged; residuals replace y.

Each leaf stores: Leaf score = sum of residuals / (sample count + λ)
— a regularized residual mean. Larger λ shrinks it toward 0, reducing corrections and helping prevent overfitting.

Final prediction = initial value + Σ(learning_rate × each tree’s leaf score)
As residuals decrease, predictions approach actual values. Early stopping halts training when further improvement stops.

Boosting overfits for a different reason from bagging

Bagging averages independent trees, so more trees generally stabilize it.
Boosting reduces residuals, potentially treating random noise as residual structure and memorizing it in detail.

06 Feature importance — three methods and their differences 15 min
Key idea: MDI has no direction and uses training data. SHAP provides direction, but as a post-hoc explanation, it can confidently explain the wrong direction when the model is wrong. See the separate example file for code, outputs, and comparisons.
MethodData usedOutputDirectionMain use
MDI Training data (traverse tree structure) One number per feature None Quick initial check
OOB Permutation OOB observations (within training dataset) One number per feature None RF feature selection
SHAP fitted model + test X A contribution per feature for each prediction Yes (positive / negative) Explain individual predictions
MDI — traverse the fitted tree structure

Sum each node’s splitting feature, impurity reduction, and sample count. Continuous features have more possible thresholds than categorical features, creating structural bias toward higher MDI.

OOB permutation — how much worse without the feature’s information?

Baseline: model.oob_score_ (not the training score). Shuffle feature j, recalculate OOB R², and use the decrease as importance. This is closer than MDI to the feature’s predictive contribution.

SHAP — decompose one prediction by feature

Pass test X to the fitted model. The baseline (mean prediction over X_train) plus all feature SHAP values equals the prediction. Contributions have a sign, and TreeSHAP computes them quickly and exactly for trees.

SHAP limitations

It explains a fitted model, so an incorrect model can produce confident explanations in the wrong direction. Compare predictions with y_test and examine SHAP for high-error cases before deciding whether to trust it.

Use MDI or OOB to establish “temperature is important,” then SHAP to inspect the direction, such as “higher temperature predicts more defects.” None of these methods establishes causality.

06+ Why manufacturers like trees — and why this can be risky 10 min
Key idea: Tree rules match the language of operations and feel intuitive. The greatest risk is letting that intuition lead to application without validation.
Why they are popular — rules resemble operational control criteria

Tree result: “Temperature > 85°C AND pressure > 3.2 bar → 62% defect rate”
Operational reading: “Above 85 degrees, keep pressure at or below 3.2 bar” — readily becomes an SOP.

Control charts, SPC, and process specifications all use conditional rules: “under this condition, do this.” Trees fit that language.

Why risky? — mistaking correlation for causation

A tree identifies “more defects occurred under these conditions,” not “these conditions caused defects.”

“62% defective above 85°C” → the actual cause could be insufficient coolant. Forcing the temperature down would not solve that underlying issue.

The more intuitive a rule, the more convincing it feels, sometimes leading to process changes without validation.

The interaction trap

“High temperature AND high pressure” looks like a physical causal mechanism, but it only shows a pattern in the data. Validate it through domain knowledge before changing the process.

Risk beyond the training range

Changed conditions, materials, or equipment can invalidate a rule. Applying last year’s rules unchanged to this year’s new line is a common failure pattern.

Model selection — why R² alone is insufficient
Examine residuals for extreme values separately

R² summarizes overall performance and can hide errors in extreme cases. Even with RF R² = 0.88 and XGBoost R² = 0.91, it does not show which model predicts defect rates above 70% more accurately.

Practical criteria:
· How frequent are extreme cases? A small share has little influence on R².
· Does the domain prioritize extreme cases or average performance?
· If a defect rate above 80% requires stopping a line, compare residuals in that range separately.

Method: divide observations into ranges by predicted or actual values, then examine each range’s residual distribution.

The message throughout this session

“XGBoost is a better model” is not a valid claim without context.
Does interpretation matter? Is there substantial noise? Are extreme values important? Which error ranges are costly? Understand these conditions first, then explain the model choice.

Final discussion (key)
“RandomForest has R² = 0.88 and XGBoost has R² = 0.91. Should you choose XGBoost? What additional information do you need?”
