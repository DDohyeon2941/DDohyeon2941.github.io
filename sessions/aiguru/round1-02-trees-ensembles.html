01 Decision Tree 15 min
핵심: 매 분기마다 변수 하나의 임계값으로 두 그룹으로 나눕니다. 이 직각 분할이 반복되면 2D 공간에서 축에 평행한 선들로 영역이 나뉘고, 각 영역에 다른 예측값이 배정됩니다 — 계단 형태라 비선형입니다.
불순도(Impurity) — 어떻게 나눌지 결정하는 기준
불순도 = "한 바구니 안에 얼마나 섞여 있는가" — 가장 많이 줄어드는 조건을 선택

불량 50개·정상 50개 섞인 바구니 → 불순도 최대. 어느 쪽도 확신 못 함
불량 98개·정상 2개 → 불순도 거의 0. "거의 확실히 불량"이라고 말할 수 있음

트리는 모든 변수·모든 분기점을 시도해보면서 나눴을 때 불순도가 가장 많이 줄어드는 조건을 선택합니다.
분류 → Gini: 완전히 분리되면 0, 절반씩 섞이면 0.5 / 회귀 → MSE: 노드 안 y값들의 퍼짐 정도

왜 비선형인가 — 2D 공간 분할로 보기 (온도 × 압력)
선형 회귀는 이 공간을 대각선 하나로 나눕니다. 트리는 축에 평행한 선들로 직각 분할합니다. 각 영역에 다른 예측값이 배정되고, 경계에서 예측값이 계단식으로 바뀝니다. 이것이 비선형인 이유입니다.
변수가 많으면 과적합이 심해지는 이유
노이즈 변수도 우연히 불순도를 줄이는 분기를 찾을 수 있습니다

변수가 많을수록 "이번 학습 데이터에서만 우연히 맞아떨어지는" 분기 조건을 찾을 가능성이 높아집니다. 이런 조건들이 쌓이면 train 성능은 올라가지만 test에서는 일반화되지 않습니다.

MDI는 중요도 합이 1로 정규화되기 때문에 변수가 늘어나도 상대적 순위 자체는 크게 달라지지 않습니다. 문제는 순위가 아니라 과적합입니다.

RandomForest에서 max_features=1.0(전체 변수)으로 두면 랜덤 변수 선택이 없어서 단순 Bagging과 같아집니다. 이 경우 노이즈 변수의 영향이 매 트리에 동일하게 반영됩니다. sklearn Regressor 기본값이 1.0인 것은 실무에서 주의해야 할 부분입니다.

분기 예시 ① — 분류 (불량/정상 예측)
분류 리프: 해당 노드 학습 데이터에서 각 클래스 비율을 계산 → 다수 클래스로 예측하거나, 비율 자체를 확률로 출력합니다.
분기 예시 ② — 회귀 (수율 예측)
회귀 리프: 해당 노드 학습 데이터의 y값 평균이 예측값으로 저장됩니다. 새 데이터가 "저온 + 고속" 노드에 떨어지면 조건이 조금 달라도 모두 95.7%로 예측합니다.

02 트리 계열 공통 특성 — 노드 평균값 12 min
핵심: 트리 계열은 리프 노드 안 값들의 평균을 예측값으로 씁니다. 무엇의 평균인지는 모델마다 다릅니다 — Decision Tree·RandomForest는 y값 평균, XGBoost는 잔차의 평균(정규화 포함). 이 구조가 Extreme Value를 못 맞추고, 노드 안 스케일이 크면 오차도 커지는 근본 원인입니다.
학습 때 평균을 저장하고, 예측 때는 그 값을 그대로 출력합니다

학습 시점: 리프 노드로 분류된 학습 데이터의 값들을 평균 내어 노드에 저장.
예측 시점: 새 데이터가 어느 노드에 떨어지는지만 결정. 저장된 평균을 그대로 출력.

Decision Tree·RandomForest: y값 평균을 저장
XGBoost: 그 라운드의 잔차 평균(정규화 항 λ 포함)을 저장 → 누적 합산으로 최종 예측

한계 ① — Extreme Value를 원천적으로 못 맞춘다
학습 데이터 y 범위를 벗어나는 예측은 불가능

노드 안 학습 y값이 [90, 95, 100, 105, 200]이면 예측값은 평균 118. 실제값 200인 데이터를 118로 예측 → 오차 82.
학습 데이터 y 최댓값보다 크거나 최솟값보다 작은 값은 절대 예측되지 않습니다.

한계 ② — 이상치가 있으면 노드 평균이 끌려올라간다
X가 비슷한데 y만 극단값인 경우가 더 위험합니다

이상치의 X 값이 충분히 특이하면 트리가 별도 노드로 격리할 수 있습니다. 하지만 실제 데이터에서 더 흔한 경우는 X는 비슷한데 y만 극단값인 경우입니다.

온도 82°C, 압력 3.1 bar인 데이터가 대부분 불량률 10~15%인데 그 중 1건이 80%라면, X 조건이 비슷해서 트리가 분리할 근거가 없습니다. 그 노드 평균이 이상치에 끌려올라가고 같은 노드 전체의 예측값이 왜곡됩니다.

한계 ③ — 노드 안 y 스케일이 크면 예측 오차도 커진다
평균 하나로 대표하는 것 자체가 부정확해짐

노드 안 학습 y값이 [5%, 8%, 12%, 60%]이면 예측값은 평균 21%. 60% 데이터는 39%p 오차, 5% 데이터는 16%p 오차.
분기를 더 깊이 하면 노드가 작아지지만, 과적합이 심해지는 트레이드오프가 생깁니다.

범주형 변수 — sklearn 트리 계열은 직접 받지 못합니다
분기 조건이 "변수값 > 임계값"만 사용하기 때문

Label Encoding: 순서 없는 범주에 순서를 부여 → "작업자 2 > 작업자 1"이라는 대소 관계가 분기에 반영됨. 작업자 10명이면 임계값 후보 9개
One-Hot Encoding: 작업자 10명 → 변수 10개, 각각 0 또는 1. 분기점 후보가 0.5 하나뿐. 연속형(수백 개 후보) 대비 MDI가 구조적으로 낮게 나오는 편향 심화
XGBoost 1.7+: enable_categorical=True로 native 지원 추가됐지만 기본값은 아님

SHAP을 트리에서 특히 많이 쓰는 이유
TreeSHAP — 트리에서만 빠르고 정확하게 계산됩니다

일반 SHAP은 변수 조합이 지수적으로 늘어나 현실적으로 불가능합니다(변수 20개 → 2²⁰ 조합). 다른 모델에서는 근사값을 씁니다.
TreeSHAP은 트리 분기 구조를 직접 활용해서 다항 시간에 정확한 값을 계산합니다. 트리에서 SHAP이 표준처럼 쓰이는 이유입니다.

03 트리의 과적합 — 선형 회귀보다 심하다 8 min
핵심: 트리는 분기를 데이터 건수만큼 만들 수 있어 선형 회귀보다 과적합이 심합니다. train R²는 트리에서 아무 의미가 없고, test R²만 봐야 합니다.
왜 더 심한가

선형 회귀: 계수 하나로 전체를 요약 → 표현력 자체에 한계가 있어 어느 정도에서 멈춤
트리: 데이터 건수만큼 분기를 만들 수 있음 → 극단적으로는 데이터 1건 = 리프 1개 → train R² = 1.0, test ↓↓

"온도 82.3°C, 압력 3.11 bar일 때 불량"이라는 조건을 그대로 기억해버리면, 82.4°C에서는 전혀 다른 예측이 나옵니다.

train R² vs test R²
트리에서 train R²가 높은 건 "모델이 좋아서"가 아닐 수 있습니다

train R²: 학습 데이터로 계산. 분기를 깊이 할수록 각 노드의 y 분산이 줄어들어 자동으로 올라갑니다. 노드를 데이터 수만큼 쪼개면 1.0이 됩니다.
test R²: 학습에 안 쓴 데이터로 계산. 실제로 새 데이터에서 얼마나 잘 맞추는지입니다.

train R² 0.95, test R² 0.62 → 과적합. train R²가 높아도 test R²가 낮으면 의미가 없습니다.
트리에서는 train/test R² 차이를 반드시 함께 봐야 합니다.

파라미터의미크면?작으면?
max_depth최대 분기 깊이과적합 ↑단순화
min_samples_leaf리프 최소 데이터 건수안정적 예측값1건짜리 리프 가능
min_samples_split분기 생성 최소 건수과적합 방지노이즈 조건까지 분기
04 앙상블 — RandomForest / AdaBoost / XGBoost 20 min
핵심: 앙상블은 여러 모델을 합쳐 단일 모델보다 나은 예측을 만드는 방법론입니다. 트리만 합치는 게 아닙니다(선형+트리+신경망을 합치는 Stacking도 앙상블). 이 섹션은 트리 앙상블만 다룹니다 — RF(분산 감소), XGBoost(편향 감소).
① Bagging — RandomForest
같은 모집단에서 표본을 100번 뽑아 집계 — 대수의 법칙으로 노이즈 상쇄

단순 Bagging: 트리마다 복원 추출(bootstrap)로 다른 샘플을 뽑아 독립 학습 → 평균 내면 노이즈 상쇄

RandomForest = Bagging + 변수 무작위 선택: 각 분기마다 전체 변수 중 일부(√p개)만 선택합니다. 단순 Bagging만 하면 지배적인 변수가 모든 트리를 점령해서 트리들이 비슷해지고 평균 효과가 줄어듭니다. 변수도 랜덤하게 제한해야 트리들이 다양해집니다.

sklearn 주의: Classifier는 max_features="sqrt" 기본값이지만, Regressor는 max_features=1.0 — 전체 변수 사용, 즉 단순 Bagging과 동일합니다.

OOB (Out-Of-Bag) — 별도 test set 없이 검증 가능

복원 추출하면 평균적으로 약 37%는 특정 트리에 포함되지 않습니다. 이 OOB 샘플이 자연스러운 검증 데이터가 됩니다. 변수 중요도(OOB Permutation) 계산에도 활용됩니다.

② Boosting — AdaBoost에서 XGBoost로
AdaBoost — Boosting의 원조, 가중치 방식

틀린 샘플에 가중치를 높여서 다음 트리의 손실함수에서 그 샘플의 오차 비중을 키웁니다. 틀리는 비용 자체를 높이는 방식입니다.
한계: 이상치에 과도하게 집중해서 과적합 취약.

XGBoost — 잔차를 순차적으로 줄여나가는 누적 합산

초기값(y 평균)에서 시작. 매 라운드마다 "현재 잔차"를 y로 놓고 트리를 학습합니다. X는 그대로, y 자리만 잔차로 바뀝니다.

각 리프에 저장되는 값: leaf score = 잔차 합 / (샘플 수 + λ)
— 정규화된 잔차 평균. λ가 클수록 0에 수축 → 보정 폭 줄어들어 과적합 방지

최종 예측 = 초기값 + Σ(learning_rate × 각 트리 leaf score)
잔차가 점점 줄어들면서 예측값이 실제값에 수렴. early_stopping은 잔차가 더 이상 줄지 않을 때 멈추는 장치.

Boosting 과적합 — Bagging과 이유가 다릅니다

Bagging은 독립 트리 평균이라 트리 수를 늘려도 안정화됩니다.
Boosting은 잔차를 줄이는 구조라 노이즈(우연한 오차)까지 잔차로 보고 정교하게 외워버립니다.

편향(Bias) — 체계적 오류

복잡한 패턴을 체계적으로 놓치는 상태. 너무 단순한 모델(max_depth=2)의 특징. Boosting이 줄임.

토론 질문 3
"train 성능은 비슷한데 XGBoost test 성능이 더 낮게 나왔습니다. 무슨 문제이고 어떻게 접근하시겠어요?"
06 변수 중요도 — 세 가지 방식과 그 차이 15 min
핵심: MDI는 방향 없고 학습 데이터 기반. SHAP은 방향까지 나오지만 사후 분석이라 모델이 틀리면 SHAP도 틀린 방향을 자신 있게 설명합니다. 코드·출력·비교는 별도 예시 파일 참고.
방식사용 데이터출력방향성주 용도
MDI 학습 데이터 (트리 구조 순회) 변수별 수치 하나 없음 빠른 1차 확인
OOB Permutation OOB 샘플 (학습 데이터셋 내) 변수별 수치 하나 없음 RF 변수 선택
SHAP fitted model + test X 예측 1건마다 변수별 기여량 있음 (양/음) 개별 예측 설명
MDI — 학습 완료 후 트리 구조 순회

각 노드에 저장된 "어떤 변수로 분기했는지, 불순도 변화, 샘플 수"를 합산. 연속형 변수가 범주형보다 임계값 후보가 많아서 구조적으로 MDI가 높게 나오는 편향이 있음.

OOB Permutation — 실제로 없애면 얼마나 나빠지는가

기준: model.oob_score_ (train set 아님). 변수 j를 섞은 후 OOB R² 재측정 → 하락폭이 중요도. MDI보다 실제 예측 기여에 가까움.

SHAP — 예측값 하나를 변수별로 분해

fitted model에 test X만 입력. 기준값(X_train 예측 평균) + 각 변수 SHAP 합산 = 예측값이 항상 성립. 방향(양/음)이 나오고 TreeSHAP으로 트리에서 빠르고 정확하게 계산.

SHAP의 한계

사후 분석이라 모델이 틀렸으면 SHAP도 틀린 방향을 자신 있게 설명합니다. y_test와 대조해서 오차가 큰 케이스의 SHAP을 봐야 신뢰 여부를 판단할 수 있습니다.

MDI·OOB로 "온도가 중요하다"를 확인하고, SHAP으로 "높을수록 불량이 많다"는 방향까지 확인합니다. 단, 인과관계는 어느 방식도 말해주지 않습니다.
토론 질문 4
"MDI 기준으로 온도가 1위입니다. '온도를 낮추면 불량이 줄겠네요'라고 말해도 될까요? 어떤 추가 정보가 필요한가요?"
06+ 제조 현장이 트리를 좋아하는 이유 — 그리고 왜 위험한가 10 min
핵심: 트리 규칙은 현장 언어와 딱 맞아서 직관적으로 납득됩니다. 그 납득감이 검증 없는 적용으로 이어지는 게 가장 큰 위험입니다.
왜 좋아하는가 — 현장 관리 기준과 같은 형태

트리 결과: "온도 > 85°C AND 압력 > 3.2 bar이면 불량률 62%"
현장 해석: "온도 85도 넘으면 압력 3.2 이하로 유지해라" — 바로 SOP가 됨

관리도, SPC, 공정 스펙 모두 "어떤 조건이면 어떻게 한다"는 규칙입니다. 트리가 그 언어와 딱 맞아떨어집니다.

왜 위험한가 — 상관관계를 인과관계로 오해합니다

트리가 찾은 건 "이 조건에서 불량이 많았다"는 패턴입니다. "이 조건이 불량을 만든다"는 원인이 아닙니다.

"온도 > 85°C에서 불량 62%" → 실제 원인은 냉각수 부족일 수 있습니다. 온도를 억지로 낮춰도 냉각수 문제는 그대로입니다.

규칙이 직관적일수록 "맞는 것 같다"는 느낌이 강합니다. 그 느낌 때문에 검증 없이 공정에 바로 반영하는 경우가 생깁니다.

교호작용 함정

"온도 높고 AND 압력 높으면"이라는 조건 조합이 물리적 인과처럼 보이지만, 데이터에 그 패턴이 있었다는 것입니다. 공정을 바꾸기 전에 도메인으로 반드시 검증해야 합니다.

학습 데이터 범위 밖 적용 위험

공정 조건, 원자재, 설비가 바뀌면 그 규칙이 더 이상 유효하지 않을 수 있습니다. "작년 데이터로 만든 규칙을 올해 새 라인에 그대로 적용"이 가장 흔한 실패 패턴입니다.

모델 선택 기준 — R² 하나로 결정하면 안 되는 이유
Extreme Value 구간의 잔차를 따로 봐야 합니다

R²는 전체 평균적인 성능이라 extreme 케이스에서의 오차가 숨어있습니다. RF R² 0.88, XGBoost R² 0.91이라도 불량률 70% 이상 극단 구간에서 어느 모델이 더 잘 맞추는지는 R²로 보이지 않습니다.

실제 판단 기준:
· extreme 케이스가 얼마나 있는가 — 데이터 비중이 작으면 R²에 거의 반영 안 됨
· 도메인상 extreme을 잘 맞추는 게 중요한가, 평균적인 걸 맞추는 게 중요한가
· 불량률 80% 이상인 케이스가 라인을 멈춰야 하는 상황이라면, 그 구간 잔차를 별도로 꺼내서 비교해야 합니다

방법: 예측값 또는 실제값 기준으로 구간을 나눠서 구간별 잔차 분포를 따로 확인합니다.

세션 전체를 관통하는 메시지

"XGBoost가 더 좋은 모델이다"는 맥락 없이 틀린 말입니다.
설명이 필요한가, 노이즈가 많은가, Extreme Value가 중요한가, 어떤 구간의 오차가 비즈니스적으로 치명적인가 — 이 조건들을 먼저 파악하고 선택 근거를 설명할 수 있어야 합니다.
