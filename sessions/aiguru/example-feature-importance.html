00 공통 시나리오
불량률 예측 모델 (RandomForest). 변수 5개 — 온도(연속), 압력(연속), 회전수(연속), 습도(연속), 작업자 ID(범주형 → Label Encoding). 학습 데이터 800건, test 데이터 200건.

02 OOB Permutation Importance
코드
# OOB 샘플에서 변수를 섞었을 때 성능 하락을 측정
# oob_score=True 필요
model = RandomForestRegressor(n_estimators=100, oob_score=True, random_state=42)
model.fit(X_train, y_train)

# 기준 성능: 변수 섞기 전 OOB 샘플에서의 R²
# train set 성능이 아닙니다
baseline = model.oob_score_  # 예: R² = 0.84

from sklearn.inspection import permutation_importance

# 변수 j를 섞은 후 OOB 성능 측정 → baseline과 차이가 중요도
# importance_j = baseline_score - permuted_score
result = permutation_importance(
  model, X_train, y_train,
  n_repeats=10,    # 섞기를 10번 반복해서 평균
  random_state=42
)

# result.importances_mean: 변수별 R² 하락량 평균
# result.importances_std: 변수별 R² 하락량 표준편차

값 = 해당 변수를 섞었을 때 R² 하락량. 클수록 중요. ± = 10번 반복 표준편차
MDI와 순위가 달라졌습니다

MDI에서 작업자ID는 0.07로 꼴찌였지만, OOB Permutation에서는 0.26으로 2위입니다.

이유: MDI는 작업자ID(범주형)의 임계값 후보가 적어서 구조적으로 낮게 나왔습니다. OOB Permutation은 "실제로 이 변수를 없애면 성능이 얼마나 떨어지는가"를 측정하기 때문에 그 편향이 없습니다.

MDI만 봤다면 작업자ID를 노이즈 변수로 잘못 판단하고 제거했을 수 있습니다.

03 SHAP
코드
# 학습 완료된 모델 + X_test (y_test 불필요)
explainer = shap.TreeExplainer(model)
shap_values = explainer.shap_values(X_test)  # X만 입력

# shap_values.shape = (200, 5) ← 200건 × 5개 변수

# 기준값: 학습 완료 모델로 X_train을 예측한 값들의 평균
# = model.predict(X_train).mean()
explainer.expected_value # → 0.182

# expected_value + sum(shap_values[i]) == model.predict(X_test)[i]

이 예측의 실제값은 0.71인데 모델은 0.492로 예측했습니다. 오차가 0.218입니다. SHAP은 그 틀린 예측 0.492를 자신 있게 설명하고 있습니다.

y_test와 대조해야 이 설명이 신뢰할 만한 케이스인지 파악할 수 있습니다.

Summary Plot에서 읽을 수 있는 것

온도: 빨강(높은 값)이 오른쪽에 몰림 → 온도가 높을수록 불량률을 높이는 방향으로 기여
작업자ID: 특정 ID(빨강)가 오른쪽에 몰림 → 특정 작업자에서 불량이 집중. MDI에서는 이 패턴이 가려졌음
습도: 0 근처에 몰림 → 불량률에 거의 영향 없음

MDI/OOB는 "얼마나 중요한가"만 알려줍니다. Summary Plot은 "어떤 방향으로, 어떤 값일 때 기여하는가"까지 보여줍니다.

OOB Permutation으로 실제 성능 기준 중요도를 확인하고, SHAP으로 "특정 작업자에서 불량이 높다"는 방향까지 파악해야 현업에 설득력 있는 설명이 됩니다.
